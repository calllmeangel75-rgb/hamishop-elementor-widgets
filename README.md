# HamiShop Elementor Widgets — ویجت‌های فروشگاهی المنتور (HamiSys)

ویجت‌های لوپ محصولات ووکامرس برای المنتور — تبدیل دقیق طرح HTML شما به ویجت، با **شخصی‌سازی کامل فونت، رنگ و استایل** و طراحی سبک برای رسیدن به **Lighthouse 100**.

ساخته‌شده توسط **HamiSys (حامی)** — [hamisys.ir](https://hamisys.ir/)

---

## ویجت‌ها (نسخه ۱.۱۱.۶)

هر سه بخشِ طرح ارسالی شما — **دسکتاپ و موبایل به‌صورت یکپارچه** — به ویجت تبدیل شده‌اند:

| ویجت | معادل در طرح | توضیح |
|---|---|---|
| **پیشنهاد شگفت‌انگیز (Wonder Deals)** | Section 1 | گرادیان قرمز، تایمر شمارش معکوس (کپسول دسکتاپ + جعبه‌های موبایل)، کارت بنر شروع، نوار پیشرفت موجودی |
| **پرفروش‌ترین‌ها (Best Sellers)** | Section 2 | نشان‌های رتبه ۱/۲/۳ با رنگ‌بندی طرح، دکمه «خرید»، لینک «مشاهده فهرست کامل» |
| **محبوب‌ترین‌ها / منتخب (Popular)** | Section 3 | تب‌های «محبوب‌ترین‌ها / جدیدترین‌ها / بیشترین تخفیف» (تعویض بدون رفرش)، نشان ویژه/ارسال رایگان/تخفیف، حالت «اتمام موجودی» با دکمه «خبرم کن» |

به‌علاوه دو **ویجت هدر** در دستهٔ «حامی — هدر و ناوبری»: **هدر فروشگاهی** و **هدر مینیمال شیشه‌ای** — جزئیات در بخش [ویجت‌های هدر](#ویجتهای-هدر-نسخه-۱۱۱۲).

## شخصی‌سازی (پنل المنتور)

برای هر ویجت در تب **Content**:
- منبع محصولات: پیشنهاد ویژه / پرفروش‌ترین / محبوب‌ترین (امتیاز) / جدیدترین / بیشترین تخفیف / منتخب / دسته‌بندی خاص / **انتخاب دستی محصولات**
- تعداد، حذف ناموجودها، برند (کلاس ویژگی مثل `pa_brand`)، امتیاز، متون همه نشان‌ها و دکمه‌ها
- شمارش معکوس: خودکار از پایان حراج محصولات یا زمان دستی
- تب‌ها: عنوان و منبع هر تب قابل ویرایش (Repeater)

در تب **Style** (همه با کنترل‌های ریسپانسیو دسکتاپ/موبایل):
- بخش: رنگ‌ها/گرادیان (لبه و وسط)، پدینگ، گردی، سایه، حاشیه
- سربرگ: تایپوگرافی و رنگ عنوان/توضیح/لینک، آیکون (نوع، اندازه، رنگ قاب)، رنگ نوار موبایل، برچسب کنار عنوان
- تایمر و فلش‌ها: رنگ کپسول/جعبه‌ها/اعداد، رنگ و گردی فلش‌ها، رنگ اسکرول‌بار
- کارت: عرض (موبایل ۱۴۴px / دسکتاپ ۲۸۸px طبق طرح)، فاصله، پس‌زمینه، حاشیه، گردی، پدینگ، زوم تصویر، تعداد خطوط عنوان، تایپوگرافی عنوان و برند
- نشان‌ها: رنگ پس‌زمینه/متن تخفیف، ویژه، ارسال رایگان + رتبه‌های ۱ و ۲و۳ و بقیه + رنگ‌های نوار موجودی
- قیمت: تایپوگرافی، رنگ قیمت جدید/قبلی
- دکمه‌ها: پس‌زمینه/رنگ (حالت عادی و هاور)، گردی
- بنر شروع و تب‌ها: رنگ‌ها، عرض بنر، تایپوگرافی تب

## بهینه‌سازی برای Lighthouse 100

- **بدون هیچ فریم‌ورکی**: CSS خالص ~۱۵KB و JS خالص ~۴KB — بدون Tailwind CDN، بدون jQuery
- **آیکون‌ها به‌صورت فونت زیرمجموعه لوکال**: فقط ۲۱ آیکون طرح در یک فایل `woff2` **۲۵KB** باندل شده؛ هیچ درخواست خارجی به Google Fonts زده نمی‌شود
- **بارگذاری شرطی**: CSS/JS فقط وقتی لود می‌شوند که ویجت در صفحه باشد
- تصاویر `loading="lazy"` + `decoding="async"`، کارت‌ها با `scroll-snap` بومی مرورگر (بدون کتابخانه اسلایدر)
- **حالت پیش‌فرض «ارث‌بری فونت»** است: فونت از قالب شما ارث می‌رسد و افزونه چیزی لود نمی‌کند. اگر خواستید وزیرمتن را از خود افزونه بگیرید، حالت «فونت اختصاصی» را روشن کنید (بخش «فونت وزیرمتن لوکال» پایین‌تر) — در آن حالت فایل ۱۱۱KB داخل افزونه یک‌بار لود می‌شود.

## نصب

1. از GitHub کلون/دانلود کنید: `https://github.com/calllmeangel75-rgb/hamishop-elementor-widgets`
2. پوشه را به ZIP تبدیل کنید (یا از گزینه Code → Download ZIP استفاده کنید)
3. پیشخوان وردپرس → افزونه‌ها → افزودن → بارگذاری افزونه → فایل ZIP
4. پیش‌نیازها: **WooCommerce** + **Elementor**
5. در المنتور، دستهٔ **HamiShop — حامی** را در پنل ویجت‌ها پیدا کنید

## یادداشت‌ها

- اعداد قیمت و رتبه‌ها خودکار فارسی می‌شوند.
- **Hami Call for Price:** اگر افزونهٔ CFP فعال باشد، محصولات علامت‌خورده در همهٔ سطوح HamiShop (لوپ، آرشیو، جعبه خرید، نوار چسبان و انتخاب تنوع) به‌جای قیمت/تخفیف/تعداد/خرید آنلاین، متن و اکشن تماسِ همان افزونه را نشان می‌دهند. تشخیص از API عمومی CFP انجام می‌شود و هندلرهای ووکامرس تغییر نمی‌کنند.
- دکمه افزودن به سبد با AJAX کار می‌کند و فرگمنت‌های ووکامرس را رفرش می‌کند؛ محصولات متغیر به صفحه محصول هدایت می‌شوند.
- تعویض تب‌ها از REST Route اختصاصی (`/wp-json/hsw/v1/loop`) با امضای امن استفاده می‌کند.
- اگر برند در ویژگی `pa_brand` نبود، به اولین دسته‌بندی محصول برمی‌گردد.

# ویجت‌های صفحه محصول (نسخه ۱.۱.۰)

تبدیل دقیق HTML صفحه محصول ارسالی شما — **هم دسکتاپ هم موبایل** — به ۱۰ ویجت المنتور:

| ویجت | نقش | دسکتاپ / موبایل |
|---|---|---|
| **همی‌راه محصول** | مسیر راهنما (Breadcrumb) | هر دو (جداکننده `/` دسکتاپ، شِوران موبایل، اسکرول افقی) |
| **گالری محصول** | تصویر اصلی + بندانگشت/دات + بج تخفیف و اصالت + بزرگنمایی | هر دو |
| **نوار اعتماد و ضمانت‌ها** | اصالت / ارسال فوری / ۷ روز بازگشت | دسکتاپ |
| **عنوان، امتیاز و متا** | عنوان فارسی/انگلیسی، کد کالا، امتیاز، تعداد دیدگاه، درصد پیشنهاد، وضعیت موجودی | هر دو |
| **انتخاب رنگ و حافظه** | سواچ‌های رنگی + چیپ‌های حافظه — **موتور انتخاب تنوع واقعی ووکامرس** | هر دو |
| **ویژگی‌های شاخص** | لیست تیک‌دار (دسکتاپ) / بنتو گرید ۲×۲ (موبایل) | هر دو |
| **جعبه خرید و قیمت** | قیمت + تخفیف، شمارنده تعداد، افزودن به سبد (AJAX)، گارانتی‌ها | دسکتاپ |
| **تب‌های محصول** | مشخصات فنی (از ویژگی‌های محصول)، بررسی تخصصی (توضیحات)، دیدگاه‌ها | دسکتاپ |
| **آکاردئون‌های محصول** | مشخصات کامل / دیدگاه‌ها / گارانتی و ارسال | موبایل |
| **نوار خرید چسبان** | قیمت + تعداد + افزودن به سبد + توست موفقیت (ثابت پایین صفحه) | موبایل |

## موتور تنوع (Variable Products)

- انتخاب رنگ/حافظه، تنوع واقعی ووکامرس را پیدا می‌کند و **قیمت، قیمت قبلی، درصد تخفیف و تصویر** را همزمان در جعبه خرید دسکتاپ **و** نوار چسبان موبایل به‌روز می‌کند.
- افزودن به سبد با `variation_id` صحیح از طریق `wc-ajax=add_to_cart` انجام و فرگمنت‌های مینی‌سبد رفرش می‌شوند.
- نام ویژگی‌ها در کنترل‌های ویجت تنظیم می‌شود (پیش‌فرض `pa_color` و `pa_memory`) و رنگ سواچ‌ها با نگاشت نام ترم → کد رنگ تعیین می‌شود.

## فونت وزیرمتن لوکال 🆕

- فونت **وزیرمتن متغیر** (Vazirmatn Variable، وزن‌های ۱۰۰ تا ۹۰۰ در یک فایل ~۱۱۱KB) **داخل افزونه پک شده** و با `font-display: swap` لود می‌شود؛ هیچ درخواستی به Google Fonts زده نمی‌شود.
- در فهرست فونت‌های المنتور با نام **«Vazirmatn HSW»** (گروه HamiShop لوکال) ثبت شده و در همه کنترل‌های تایپوگرافی قابل انتخاب است.
- زیرمجموعه آیکون‌های Material Symbols هم به **۶۷ آیکون** (پوشش کامل صفحه محصول و لوپ) ارتقا یافت — همچنان یک فایل لوکال.

## چیدمان پیشنهادی صفحه محصول (المنتور)

1. یک کانتینر دو ستونه (در موبایل تک‌ستونه): ستون راست = گالری + نوار اعتماد؛ ستون چپ = عنوان → رنگ/حافظه → ویژگی‌ها → جعبه خرید
2. زیر آن، تمام‌عرض: تب‌های محصول (دسکتاپ) یا آکاردئون‌ها (موبایل)
3. همی‌راه محصول بالای کانتینر؛ نوار خرید چسبان هر جای صفحه (fixed پایین viewport)

## بهینه‌سازی (Lighthouse 100)

- CSS صفحه محصول ~۱۶KB + JS ~۷KB، فقط وقتی ویجت‌ها در صفحه باشند لود می‌شوند (Elementor dependency).
- صفر درخواست خارجی: فونت‌ها، آیکون‌ها و استایل‌ها همگی لوکال.
- بدون jQuery؛ فقط Event Delegation؛ تصاویر lazy (اصلی eager با `fetchpriority="high"`).

# ویجت‌های جامع + مجله (نسخه ۱.۷.۰)

## ویجت‌های جامع (Composite) — کل صفحه با یک ویجت

شش ویجت جامع اضافه شد که همهٔ بخش‌های یک صفحهٔ فروشگاهی را با **یک درگ** می‌چینند.
داخل هر ویجت جامع، همان ویجت‌های تکی به‌صورت «بخش/پارت» رندر می‌شوند و برای هر بخش
یک سوییچ «نمایش این بخش» + مهم‌ترین کنترل‌ها (با پیشوند، مثلاً `pga_zoom`) در دسترس است.
ویجت‌های تکی هم مثل قبل مستقل کار می‌کنند و رفتارشان تغییری نکرده.

| ویجت جامع | شامل بخش‌ها |
|---|---|
| **صفحه کامل محصول** | بردکرامب → گالری → عنوان/امتیاز → رنگ و حافظه → ویژگی‌ها → جعبه خرید → اعتمادها → تب‌ها/آکاردئون‌ها → نوار چسبان |
| **صفحه کامل آرشیو** | بردکرامب → سربرگ → فیلترها (سایدبار/موبایل) → نوار ابزار → شبکه محصولات → صفحه‌بندی → راهنمای خرید |
| **صفحه کامل سبد خرید** | هدر/مراحل → بنر ارسال رایگان → اقلام → کد تخفیف → خلاصه و پرداخت |
| **صفحه کامل تسویه حساب** | هدر/مراحل → آدرس → روش ارسال → زمان تحویل → یادداشت/فاکتور → اقلام → خلاصه و ثبت سفارش |
| **صفحه کامل پرداخت** | هدر/مراحل → یادآوری سفارش → درگاه‌ها/کیف پول → کد تخفیف → خلاصه نهایی و پرداخت امن |
| **صفحه کامل مجله** | سربرگ مجله → تب دسته‌ها/مرتب‌سازی → مقاله ویژه → شبکه + صفحه‌بندی → سایدبار (پربازدید/خبرنامه/برچسب) |
| **صفحه کامل تکمیل خرید** | سربرگ موفقیت → جزئیات سفارش → اطلاعات تحویل → مراحل بعدی سفارش → دکمه‌های پایانی و پشتیبانی |

- چیدمان ستون‌ها از پنل قابل تنظیم است (عرض سایدبار/نسبت ستون گالری + فاصله) و در موبایل تک‌ستونه می‌شود.
- موتور: `includes/class-hsw-composite.php` + هلپرهای `part_section()` / `part_controls()` / `print_part()` در کلاس پایه. خطای یک پارت هرگز کل صفحه را نمی‌خواباند (Throwable-safe).
- ویجت‌های تکی موجود هیچ شناسهٔ کنترلی تغییر نکرده — تنظیمات قبلی صفحات شما دست‌نخورده باقی می‌ماند.

## خانوادهٔ مجله و وبلاگ (دستهٔ «حامی — ویجت‌های مجله و وبلاگ»)

هفت ویجت تازه، کاملاً داینامیک از مطالب/دسته‌ها/برچسب‌های خود سایت:

| ویجت | نقش |
|---|---|
| **سربرگ مجله** | بج + عنوان + توضیح + آمار زنده (تعداد مقاله/دسته/دیدگاه) + جستجو + برچسب‌های داغ |
| **تب دسته‌ها و مرتب‌سازی** | پیل‌های دسته (با شمارش) + انتخاب جدیدترین/پربحث‌ترین/قدیمی‌ترین — سرورساید و سئوپسند (بدون JS) |
| **مقاله ویژه** | کارت بزرگ مقالهٔ اول صفحه با دسته، خلاصه، نویسنده، تاریخ و زمان مطالعه |
| **شبکه مقالات** | کارت‌های مقالات + خلاصه + متا + صفحه‌بندی (تعداد ستون ریسپانسیو) |
| **پربازدیدترین‌ها** | لیست رتبه‌دار (منبع: دیدگاه‌ها؛ وردپرس شمارنده بازدید ندارد — برچسب قابل تغییر است) |
| **خبرنامه** | فرم عضویت با مقصد دلخواه (URL سرویس ایمیل) یا جایگزینی با شورت‌کد هر فرم‌ساز |
| **برچسب‌های داغ** | ابر برچسب‌ها بر اساس پرکاربردترین‌ها + هایلایت برچسب اول |

- زمان مطالعه خودکار تخمین زده می‌شود (۲۰۰ کلمه/دقیقه) و اعداد فارسی می‌شوند.
- استایل: `assets/css/hsw-blog.css` (توکن‌های طرح: سرمه‌ای تیره + نارنجی) — موبایل‌فرست.

# مجموعهٔ تکمیل خرید (نسخه ۱.۸.۰)

صفحهٔ «سفارش ثبت شد» که مشتری بعد از برگشت از درگاه پرداخت می‌بیند — کاملاً قابل تنظیم و پر‌شده از دادهٔ واقعی سفارش:

| ویجت | نقش |
|---|---|
| **صفحه کامل تکمیل خرید** (جامع) | سربرگ موفقیت + جزئیات سفارش + اطلاعات تحویل (ستون اصلی) + مراحل بعدی + دکمه‌های پایانی (ستون کناری) |
| **سربرگ موفقیت** | آیکن، عنوان/زیرعنوان، چیپ‌های شمارهٔ سفارش (ارقام فارسی)/تاریخ/وضعیت + کارت «سفارش یافت نشد» برای لینک ناقص/منقضی |
| **جزئیات سفارش** | اقلام و تصاویر واقعی، جمع سبد، تخفیف، ارسال (یا «رایگان»)، مالیات، مبلغ کل، روش پرداخت + نشان «پرداخت شده / در انتظار پرداخت»، یادداشت مشتری و خروجی اختصاصی درگاه (مثل صفحهٔ تشکر خود ووکامرس) |
| **اطلاعات تحویل** | تحویل‌گیرنده، تلفن، نشانی، کد پستی، روش ارسال (shipping → billing) |
| **مراحل بعدی سفارش** | ریپیتر آیکن/عنوان/توضیح با خط اتصال — متن سایت، نه دادهٔ سفارش |
| **دکمه‌های پایانی و پشتیبانی** | دکمهٔ هوشمند (پرداخت سفارش / مشاهدهٔ سفارش در حساب من / ورود به حساب) + ادامه خرید + ایمیل تأییدیهٔ ناشناس‌شده + جعبهٔ پشتیبانی |

## مسیردهی و تنظیم

- تنظیم: **ووکامرس → تنظیمات → تسویه حساب** — بخش «مسیر خرید (حامی)»: «صفحهٔ پرداخت (مرحلهٔ ۳)» و «صفحهٔ تکمیل خرید (مرحلهٔ ۴)». صفحه‌ها را بسازید و ویجت جامع هر مرحله را داخلشان بگذارید و اینجا انتخاب کنید. خالی بماند = رفتار پیش‌فرض (دکمهٔ تسویه به صفحهٔ تسویه، کارت تأیید داخل صفحهٔ پرداخت).
- ریدایرکت با فیلتر رسمی `woocommerce_get_checkout_order_received_url` انجام می‌شود؛ پس همهٔ درگاه‌ها، پرداخت‌های بدون درگاه (کارت‌به‌کارت/پرداخت در محل)، لینک‌های پرداخت ایمیل‌ها و Store API خودکار به صفحهٔ شما می‌آیند — همراه شمارهٔ سفارش و کلید امن. آدرس‌های قدیمی `/checkout/order-received/` هم خودکار ریدایرکت می‌شوند.
- نمایش سفارش فقط با کلید معتبر یا برای مالک واردشده؛ برای همه‌ی بقیه حالت «سفارش یافت نشد» با دکمه‌های حساب کاربری/ادامه خرید.
- بدون JS در این مجموعه؛ استایل `assets/css/hsw-complete.css` (وابسته به توکن‌های `hsw-checkout.css`) فقط وقتی لود می‌شود که ویجت‌های تکمیل خرید در صفحه باشند.

# ویجت‌های هدر (نسخه ۱.۱۱.۶)

دو ویجت هدر کامل در دستهٔ **«حامی — هدر و ناوبری»** (`hamishop-header`). هر دو روی یک کلاس پایهٔ مشترک (`HSW_Header_Base`) ساخته شده‌اند و دارایی‌هایشان مشترک است: `assets/css/hsw-header.css` و `assets/js/hsw-header.js` — فقط وقتی لود می‌شوند که یکی از این دو ویجت در صفحه باشد.

| ویجت | ظاهر | مناسب برای |
|---|---|---|
| **هدر فروشگاهی** (`hsw-header-store`) | نوار اعلان بالا + ردیف اصلی با لوگو، دکمهٔ «دسته‌بندی محصولات» با مگامنو، جستجوی محصول، حساب و سبد خرید | فروشگاه‌های کامل با دسته‌بندی زیاد |
| **هدر مینیمال شیشه‌ای** (`hsw-header-minimal`) | پیل شیشه‌ای شناور (blur + شفافیت) با منوی واقعی، جستجو و دکمهٔ اقدام | لندینگ‌ها و فروشگاه‌های سبک |

## قابلیت‌های مشترک

- **منوی واقعی وردپرس** با `wp_nav_menu` — همان منویی که در «نمایش → فهرست‌ها» ساخته‌اید؛ زیرمنوها خودکار به آکاردئون موبایل تبدیل می‌شوند.
- **جستجوی محصول ووکامرس**: فرم با فیلد `s` و `post_type=product` و دکمهٔ بومی؛ انتخاب دسته‌بندی کنار جستجو اختیاری است.
- **سبد خرید و حساب کاربری** با آدرس‌های بومی ووکامرس (`wc_get_cart_url()` و `wc_get_page_permalink( 'myaccount' )`) — هیچ لینک دستی یا هندلر جایگزینی وجود ندارد.
- **شمارنده و جمع سبد** از فرگمنت‌های بومی ووکامرس (`woocommerce_add_to_cart_fragments`) رفرش می‌شود؛ بدون رفرش صفحه و بدون jQuery.
- **هدر چسبان (Sticky)** اختیاری با سایهٔ ملایم در حالت اسکرول.
- **مخفی‌شدن هوشمند** (نسخه ۱.۱۱.۲۱): با اسکرول به پایین هدر کنار می‌رود و با کوچک‌ترین اسکرول به بالا برمی‌گردد — موبایل و دسکتاپ یکسان. تا ارتفاع «آستانهٔ شروع» هدر همیشه می‌ماند و هرگز وقتی مگامنو، جستجو یا دراور باز است مخفی نمی‌شود. جزئیات فنی در [WIDGET-GUIDE](WIDGET-GUIDE.md#هدر-چسبان-و-مخفی‌شدن-هوشمند-v11121).
- **دراور موبایل** با بستن روی کلیک بیرون، کلید `Esc` و قفل اسکرول بدنه.
- **مگامنو دسته‌بندی** (هدر فروشگاهی) از درخت واقعی `product_cat`: دسته‌ها به‌صورت **عمودی و تو در تو** باز می‌شوند (فقط یک دسته هم‌زمان) و محصولات همان دسته با تصویر کوچک، نام و قیمت در ستون کنار نمایش داده می‌شوند. تصاویر فقط بار اول باز شدن هر دسته لود می‌شوند (تنبل و کش‌شده) و محصولات «تماس برای قیمت» به‌جای قیمت، متن تماس نشان می‌دهند.
- **پنل جستجوی شیشه‌ای** (هدر مینیمال) به‌صورت اورلی سبک.
- **نمایش در** (دسکتاپ/تبلت/موبایل) برای هر ویجت به‌صورت مستقل.

## تنظیمات (تب Content)

- **برند و لوگو**: تصویر لوگو، نام برند، شعار، عرض لوگو
- **منو و ناوبری**: انتخاب منوی وردپرس، نمایش/مخفی منو، نمایش دسته‌بندی محصولات در منوی موبایل، هدر چسبان، مخفی‌شدن هوشمند هنگام اسکرول + آستانهٔ شروع (پیکسل)
- **جستجو**: نمایش جستجو، متن راهنما، انتخاب دسته‌بندی کنار جستجو، متن دکمه
- **حساب، سبد و پشتیبانی**: نمایش/برچسب حساب، نمایش/برچسب سبد، شمارهٔ پشتیبانی و برچسب آن

اختصاصی **هدر فروشگاهی**: نوار اعلان (برچسب، متن، برچسب زبان/واحد پول، دو لینک دلخواه) و مگامنو (عنوان دکمه، تعداد محصول پیش‌نمایش ۳/۴/۶، متن اعتماد).

اختصاصی **هدر مینیمال شیشه‌ای**: دکمهٔ اقدام (متن و لینک) و پیل شیشه‌ای (سایه، میزان بلور).

## تنظیمات (تب Style)

رنگ اصلی، پس‌زمینهٔ هدر، رنگ متن و متن کم‌رنگ، رنگ حاشیه‌ها، پس‌زمینهٔ جستجو، گردی گوشه‌ها، عرض محتوا، تایپوگرافی نام برند و منو — همه با کنترل‌های ریسپانسیو. رنگ‌های اختصاصی هر ویجت در بخش «نوار اعلان و ناوبری» همان ویجت است.

## نکته‌های پیاده‌سازی

- بدون فونت یا تصویر خارجی؛ آیکون‌ها از فونت لوکال Material Symbols همان افزونه می‌آیند (`hsw-fonts`).
- هیچ تغییری در فرم‌ها، نانس‌ها، اندپوینت‌ها یا هندلرهای ووکامرس داده نشده؛ هدر فقط لینک و فرم بومی می‌سازد.
- برای استفاده به‌عنوان هدر سراسری، ویجت را در یک قالب هدر المنتور (Theme Builder → Header) بگذارید.
- سایت‌هایی که از قبل گزینهٔ `hsw_enabled_widgets` را ذخیره کرده‌اند، هر دو ویجت هدر را به‌صورت یک‌باره و خودکار دریافت می‌کنند (گزینهٔ `hsw_header_widgets_migrated`).

# کنترل ویجت‌ها (نسخه ۱.۱۱.۶)

صفحهٔ مستقل **HamiShop → کنترل ویجت‌ها** مشخص می‌کند کدام ویجت‌ها در پنل المنتور دیده شوند:

- **۱۳ ویجت اصلی** پیش‌فرض فعال‌اند: دو ویجت هدر، سه ویجت لوپ، صفحه‌های کامل محصول/آرشیو/سبد خرید/تسویه حساب/پرداخت/تکمیل خرید، مجله و پنل حساب کاربری.
- **۴۶ بخش مستقل** (بردکرامب، گالری، جعبه خرید، خلاصه فاکتور، فیلترها و…) پیش‌فرض خاموش‌اند و فقط پس از فعال‌سازی در پنل المنتور ظاهر می‌شوند.
- هفت گروه: هدر و ناوبری، لوپ محصولات، صفحه محصول، سبد خرید و پرداخت، آرشیو محصولات، مجله و وبلاگ، حساب کاربری (در مجموع ۵۹ ویجت).
- جستجوی زنده، انتخاب گروهی، «فقط ویجت‌های اصلی»، «فعال‌سازی همه» و بازگردانی پیش‌فرض.
- تنظیم فقط روی **ثبت ویجت در المنتور** اثر دارد؛ ویجت‌های جامع بخش‌های داخلی خود را مستقل از این تنظیم رندر می‌کنند.
- ذخیره در گزینهٔ `hsw_enabled_widgets` با Settings API و نانس بومی وردپرس؛ بدون کتابخانهٔ خارجی و با CSS/JS داخلی سبک.
- اگر از یک بخش مستقل در صفحه‌ای ساخته‌شده استفاده کرده‌اید، پیش از خاموش‌کردن آن به هشدار همین صفحه توجه کنید.

# پالت رنگی (نسخه ۱.۱۱.۶)

صفحهٔ **HamiShop → پالت رنگی** یک منبع واحد رنگ برای همهٔ ویجت‌هاست:

- ۱۱ رنگ: اصلی، اصلی تیره، تاکید، متن، متن کم‌رنگ، حاشیه، پس‌زمینه کارت، پس‌زمینه ملایم، موفق، هشدار، خطا — با انتخابگر رنگ بومی وردپرس و پیش‌نمایش زنده.
- رنگ‌ها به‌صورت متغیرهای CSS روی `html:root` چاپ می‌شوند (`--hsw-primary`, `--hsw-accent`, `--hsw-pal-border`, …) و همهٔ خانواده‌ها (هدر، لوپ، صفحه محصول، آرشیو، مجله، سبد، تسویه، حساب) توکن‌های محلی خود را از همین‌ها می‌گیرند.
- اگر برای یک ویجت خاص در تنظیمات المنتور رنگ دستی انتخاب کرده باشید، همان اولویت دارد و پالت آن را بازنویسی نمی‌کند.
- ذخیره در گزینهٔ `hsw_palette` با نانس و بررسی دسترسی؛ دکمهٔ «بازنشانی به پیش‌فرض» هم دارد.
- مقدار پیش‌فرض همان آبی فعلی سایت (`#2563eb`) است، بنابراین فعال‌کردن این نسخه ظاهر سایت را عوض نمی‌کند تا خودتان رنگی را تغییر دهید.

# صفحه کامل نوشته (نسخه ۱.۱۱.۷)

ویجت **`hsw-post-page`** در گروه «مجله و وبلاگ» یک قالب تکی مقالهٔ کامل است و برای قالب Single Post المنتور ساخته شده.

- **دادهٔ واقعی:** عنوان، دسته، برچسب‌ها، نویسنده (نام، بیو، آواتار)، تاریخ، زمان مطالعه، تعداد دیدگاه و بازدید (`hsw_post_views`).
- **فهرست مطالب خودکار** از هدینگ‌های `h2`/`h3` متن نوشته ساخته می‌شود. نوع لنگر در تنظیمات «لنگر سرفصل‌ها» انتخاب می‌شود:
  - **از متن تیتر (پیش‌فرض):** آدرس خوانا و باثبات مثل `#فناوری-حذف-نویز-فعال`؛ مناسب اشتراک‌گذاری لینک هر بخش و سئو. تیتر تکراری `-2` می‌گیرد.
  - **شماره‌ای:** `hsw-h-1`، `hsw-h-2` …
  - **بدون لینک لنگر:** فهرست با دکمه اسکرول می‌کند و هیچ آدرس `…/#heading` ساخته نمی‌شود، پس چیزی برای ایندکس‌شدن در گوگل باقی نمی‌ماند.
- **کارت محصول داخل مقاله:** شناسهٔ محصول را در تنظیمات بدهید؛ اگر خالی بماند اولین محصولِ دستهٔ نوشته و در نهایت جدیدترین محصول پیشنهاد می‌شود. محصولات «تماس برای قیمت» به‌جای قیمت، متن تماس نشان می‌دهند.
- **دیدگاه‌ها واقعی‌اند:** `wp_list_comments` با کالبک اختصاصی + `comment_form` بومی؛ پاسخ‌های تودرتو و نشان «نویسنده» پشتیبانی می‌شود.
- **مقالات مرتبط** از دستهٔ همان نوشته، **نوشتهٔ قبلی/بعدی** از ترتیب وردپرس.
- **موبایل‌اول:** نوار بالای چسبان، نوار پیشرفت مطالعه، فهرست مطالب آکاردئونی و نوار چسبان پایین (پسند، پرش به دیدگاه‌ها، خرید کالا). از ۱۰۲۴px به دو ستون با سایدبار چسبان (فهرست، نویسنده، پربازدیدها) تبدیل می‌شود.
- همهٔ رنگ‌ها از «پالت رنگی» می‌آید؛ هر بخش را می‌توان در تنظیمات ویجت خاموش کرد.

# شخصی‌سازی متن (نسخه ۱.۱۱.۸)

هر متن توضیحی طولانی، در تب **استایل** ویجت، این کنترل‌ها را دارد:

| کنترل | گزینه‌ها |
|---|---|
| تراز متن | شروع سطر (راست در RTL) · وسط‌چین · پایان سطر · **هم‌تراز دو طرف (justify)** |
| جهت متن | مطابق قالب سایت · **RTL** · **LTR** |
| ارتفاع خط | اسلایدر `em` / `px` |
| اندازهٔ فونت | اسلایدر `px` |

همه پاسخ‌گو هستند (دسکتاپ / تبلت / موبایل جدا). اعمال‌شده روی:

- **آرشیو فروشگاه و آرشیو دسته‌بندی** — «متن توضیحات آرشیو» در ویجت جامع آرشیو (و ویجت سربرگ آرشیو)،
  هم نسخهٔ دسکتاپ و هم تیزر موبایل، به‌همراه جعبهٔ توضیحات پایین محصولات.
- **نوشتهٔ تکی** — «تراز و جهت متن مقاله» در تب استایل.
- **سربرگ مجله** — «متن توضیح سربرگ مجله» در ویجت جامع مجله.
- **توضیحات محصول** — «تراز، جهت و ارتفاع خط توضیحات محصول» در تب‌های صفحه محصول.

> تراز با `text-align: start/end` پیاده شده، پس «شروع سطر» در سایت فارسی راست و در سایت انگلیسی چپ می‌شود؛ لازم نیست برای هر زبان مقدار را عوض کنید.

## دکمه‌ها

هر دکمهٔ اصلی، در تب **استایل**، این کنترل‌ها را دارد (تب عادی + تب هاور):

پس‌زمینه · رنگ متن · پس‌زمینه هاور · رنگ متن هاور · تایپوگرافی دکمه (اندازه/وزن/ارتفاع خط) · حاشیه · گردی گوشه‌ها · فاصله داخلی · سایه

| دکمه | کجا |
|---|---|
| خرید کارت محصول (`hsw-pp__prodbtn`) | صفحهٔ نوشته |
| خرید نوار پایین موبایل (`hsw-pp__dockcta`) | صفحهٔ نوشته |
| ارسال دیدگاه (`hsw-pp__submit`) | صفحهٔ نوشته |
| افزودن به سبد (`.hsw-add`) | ویجت‌های لوپ: پیشنهاد شگفت‌انگیز، پرفروش‌ترین‌ها، محبوب |
| دسته‌بندی محصولات و جستجو | هدر فروشگاهی و مینیمال |
| اعمال فیلتر | آرشیو (ویجت فیلترها و ویجت جامع) |
| خرید محصول و نوار چسبان | صفحهٔ کامل محصول |

## آیکون‌ها

فونت آیکون یک ساب‌ست لوکال از Material Symbols است (۱۲۲ آیکون، ۹۱KB، محورهای FILL/GRAD/opsz/wght).
نام‌های غیراستاندارد در `HSW_Helpers::icon()` معادل‌سازی شده‌اند (`bell`→`notifications`،
`trash`→`delete`، `user`→`person`، `phone`→`call`، `location`→`place`، `plus`→`add` و …).

اگر آیکون تازه‌ای لازم شد، نامش را به `tools/_icons.txt` اضافه کنید و
`python tools/build-icons.py <full-woff2>` را اجرا کنید؛ وگرنه نام آیکون به‌صورت متن انگلیسی
روی صفحه دیده می‌شود.

## صفحهٔ کامل محصول — استایل یکپارچه

ویجت `hsw-product-page` در تب **استایل** بخش «رنگ‌ها و فونت (یکپارچه)» دارد:

- **رنگ:** عنوان، قیمت اصلی، قیمت قبل از تخفیف، متن توضیحات/ویژگی‌ها/اعتماد، تب فعال و غیرفعال، برچسب رنگ و حافظه، مسیر راهنما.
- **تایپوگرافی:** عنوان، قیمت، متن تب‌ها، ویژگی‌های کلیدی، برچسب واریانت، تب‌ها.
- **دکمه‌ها:** خرید (جعبه خرید) و نوار چسبان — با هاور، حاشیه، گردی، فاصله و سایه.

تنظیمات ریز هر بخش (۱ تا ۱۰) در تب «محتوا» دست‌نخورده باقی مانده‌اند.

## بهینه‌سازی (نسخه ۱.۱۱.۱۳)

- هر فایل CSS/JS یک نسخهٔ `.min` دارد و وردپرس تا وقتی `SCRIPT_DEBUG` خاموش است همان را لود می‌کند:
  **CSS ۴۲۷KB → ۳۱۴KB (۲۶٪)** و **JS ۱۲۳KB → ۷۶KB (۳۸٪)**.
- بازسازی بعد از هر تغییر: `python tools/build-assets.py` (پوشهٔ `tools` در بستهٔ نصبی نیست).
- هر ویجت فقط استایل و اسکریپت خودش را لود می‌کند (`get_style_depends` / `get_script_depends`).
- فونت‌ها لوکال‌اند (هیچ درخواست خارجی)، تصاویر `loading="lazy"`، اسکریپت‌ها در فوتر.
- **سمت هاست:** gzip/Brotli را روشن کنید — همان ۳۱۴KB به ~۵۵KB می‌رسد. این تنها بزرگ‌ترین
  اهرم باقی‌مانده است و در پلاگین قابل انجام نیست.
- **تصویر LCP:** تصویر کارت اول در آرشیو و شبکهٔ مقالات `loading="eager"` + `fetchpriority="high"` است
  (بقیه lazy). تصویر اصلی گالری محصول و تصویر شاخص مقاله هم eager هستند.
- **preconnect** به `secure.gravatar.com` برای آواتارها.

### تنظیم پیشنهادی سرور (برای Lighthouse)

```apache
# gzip
AddOutputFilterByType DEFLATE text/html text/css application/javascript image/svg+xml application/json

# cache
<FilesMatch "\.(css|js|woff2|png|jpg|jpeg|webp|svg|gif|ico)$">
  Header set Cache-Control "public, max-age=31536000, immutable"
</FilesMatch>
<FilesMatch "\.(html)$">
  Header set Cache-Control "public, max-age=0, must-revalidate"
</FilesMatch>
```

در nginx معادل: `gzip on;` و `location ~* \.(css|js|woff2|png|jpg|webp|svg)$ { expires 1y; }`.
با این دو، همان دو هشدار «No compression applied» و «Cache TTL = None» برطرف می‌شود.

## اندازهٔ فونت

هر متن در صفحهٔ نوشته تایپوگرافی کامل دارد: عنوان مقاله، تاریخ و آمار، نام نویسنده، فهرست مطالب (و تیتر آن)، فهرست سایدبار، برچسب‌ها، عنوان مقالات مرتبط، پربازدیدترین‌ها، متن باکس نویسنده، متن و نام دیدگاه‌ها، و بدنهٔ مقاله (اندازه/تراز/جهت/ارتفاع خط/رنگ).

# برند و لوگو (نسخه ۱.۱۱.۲۲)

منوی **HamiShop → برند و لوگو**. نام، شعار کوتاه و لوگوی فروشگاه را یک‌بار تنظیم کنید؛ همهٔ
جاهایی که قبلاً «HamiShop» ثابت نوشته شده بود از همین مقادیر می‌خوانند:

| محل | قبلاً | حالا |
|---|---|---|
| لوگوی پنل ورود / ثبت‌نام | متن ثابت HamiShop | لوگو + نام برند |
| اعلان خوش‌آمد حساب جدید | «به HamiShop خوش آمدید» | «به {نام برند} خوش آمدید» |
| امضای پیام‌های پشتیبانی | «پشتیبانی HamiShop» | «پشتیبانی {نام برند}» |

پیش‌فرض‌ها از خود سایت خوانده می‌شوند (نام سایت و لوگوی سفارشی قالب)، پس بدون هیچ تنظیمی هم
درست نمایش داده می‌شود. اگر لوگویی انتخاب نکنید، آیکون پیش‌فرض پنل استفاده می‌شود.

# امنیت (نسخه ۱.۱۱.۲۲)

منوی **HamiShop → امنیت**. سه گزینه، همه سبک — بررسی مسیر یک مقایسهٔ رشته‌ای است و فیلتر REST
فقط در درخواست‌های REST اجرا می‌شود.

## آدرس دلخواه پیشخوان

`wp-admin` برای **کاربر مهمان** ۴۰۴ می‌شود و پیشخوان از آدرس دلخواه (مثلاً `/manage/`) سرو
می‌شود. قاعده در `.htaccess` ریشه نوشته می‌شود و **قبل از فعال‌شدن با یک درخواست واقعی به همان
آدرس تست می‌شود**؛ اگر وب‌سرور آن را اجرا نکند (Nginx، `AllowOverride None`)، تنظیم فعال نمی‌شود
تا هیچ مدیری قفل نشود.

نکات مهم پیاده‌سازی:

- **کاربر واردشده هرگز بلاک نمی‌شود.** `/wp-admin/` برای او به آدرس دلخواه ریدایرکت می‌شود و
  مسیرهای عمیق (`/wp-admin/post.php?...`) مستقیم کار می‌کنند. یعنی بدترین حالت ممکن، برگشتن به
  رفتار عادی است — نه قفل‌شدن.
- **کوکی `auth` وردپرس به `wp-admin/` محدود است.** برای اینکه آدرس دلخواه احراز هویت شود، کوکی
  معادل `auth` فقط برای همان درخواست از روی کوکی `logged_in` ساخته می‌شود
  (`resolve_user_from_logged_in_cookie`). کوکی گسترده‌تری به مرورگر داده نمی‌شود.
- `admin-ajax.php` و `admin-post.php` باز می‌مانند (فرم‌ها و فیلترهای فروشگاه از آن‌ها استفاده
  می‌کنند).
- با غیرفعال‌کردن افزونه، بلوک `.htaccess` پاک می‌شود (`register_deactivation_hook`).
- برای Nginx، کانفیگ آماده در همان صفحه نمایش داده می‌شود.

## مخفی‌کردن فهرست کاربران

`/wp-json/wp/v2/users` و `/wp-json/wp/v2/users/<id>` برای هر کسی که `list_users` ندارد حذف
می‌شوند. `/wp/v2/users/me` دست‌نخورده می‌ماند چون ویرایشگر بلوک و پنل حساب به آن نیاز دارند.

## XML-RPC

اختیاری؛ `xmlrpc_enabled` را خاموش می‌کند و هدر `X-Pingback` را برمی‌دارد.

# فرم‌های حساب کاربری (نسخه ۱.۱۱.۲۲)

فرم «اطلاعات حساب» ووکامرس **جایگزین نشده** — همان مارک‌آپ بومی با همان nonce و همان اکشن
رندر می‌شود، فقط بازطراحی شده. دلیلش ساده است: افزونه‌های دیگر به `woocommerce_edit_account_form`
وصل می‌شوند و اگر فرم را از نو می‌نوشتیم، فیلدهایشان حذف می‌شد.

زبان بصری مشترک با فرم ورود/ثبت‌نام پنل: ارتفاع ۵۲px، گوشهٔ ۱۳px، پس‌زمینهٔ `#f7f9fc`، فوکوس
سفید + حلقهٔ برند. نام/نام‌خانوادگی در دو ستون با `@container` کنار هم می‌نشینند — یعنی به عرض
**کارت** واکنش می‌دهند نه عرض صفحه، چون این فرم در ستونی به عرض ~۴۶۰px کنار سایدبار حساب قرار
می‌گیرد.

# تأیید ایمیل حساب (نسخه ۱.۱۱.۲۳)

فروشگاه‌هایی که ورود را با کد پیامکی انجام می‌دهند، هنگام ثبت‌نام ایمیل هم می‌گیرند — ولی هیچ‌وقت
ثابت نمی‌شود که آن ایمیل مال همان کاربر است. نتیجه: فاکتورها و بازیابی رمز به آدرسی می‌رود که
کسی تأییدش نکرده.

این نسخه آن حلقهٔ گم‌شده را اضافه می‌کند:

1. کاربر پیامکی در **پیشخوان / سفارش‌ها / اطلاعات حساب** یک نوار ملایم می‌بیند.
2. با زدن «تأیید ایمیل» یک کد ۶ رقمی به همان صندوق می‌رود.
3. با وارد کردن کد، ایمیل تأیید و روی حساب ثبت می‌شود (`user_email` + `billing_email`) و نوار
   برای همیشه محو می‌شود.

| نکته | رفتار |
|---|---|
| چه کسی این نوار را می‌بیند | فقط حسابی که با OTP پیامکی ساخته شده (`_hsw_auth_phone`) و ایمیلش تأیید نشده |
| کسی که با رمز ثبت‌نام کرده | نوار نمی‌بیند؛ تأییدیهٔ خود ووکامرس را دارد |
| اعتبار کد | ۱۵ دقیقه |
| تلاش مجاز | ۵ بار، بعد از آن کد می‌سوزد |
| فاصلهٔ ارسال | ۶۰ ثانیه |
| ایمیل متعلق به حساب دیگر | رد می‌شود (۴۰۹) |
| سوئیچ | HamiShop ← پنل حساب کاربری ← فعال‌سازی و چیدمان |

**چرا سبک است:** دو متای کاربر (`_hsw_email_verified` و کد موقت)، دو اکشن `admin-ajax`، بدون جدول
جدید، بدون cron، بدون کوئری اضافه در بارگذاری صفحه. بعد از تأیید، هیچ کدی اجرا نمی‌شود.

## آدرس و نام ایمیل فرستنده

جایگزین اسنیپت `wp_mail_from` / `wp_mail_from_name` در فانکشن قالب:
**HamiShop ← برند و لوگو ← ایمیل فرستنده**.

- **آدرس فرستنده** — خالی = همان `wordpress@دامنه` وردپرس. برای تحویل بهتر باید روی دامنهٔ همان
  سایت باشد.
- **نام فرستنده** — خالی = نام برند.

این تنظیم روی همهٔ ایمیل‌های سایت اثر دارد (سفارش، بازیابی رمز، کد تأیید ایمیل)، دقیقاً مثل همان
فیلترهایی که قبلاً در قالب می‌گذاشتید.

# پشتیبانی به سبک گفتگو (نسخه ۱.۱۱.۲۴)

بخش پشتیبانی از سه صفحهٔ جدا به **یک صفحهٔ دوستونه** تبدیل شد:

```
┌─────────────────────────┬──────────────────────────────┐
│  گفتگوها            [+] │  موضوع گفتگو      [بستن]     │
│  🔍 جستجوی گفتگو…       │  وضعیت · #T-123 · سفارش #۶۶۵۹ │
│  ─────────────────────  │  ──────────────────────────  │
│  مشکل در ارسال سفارش    │  [آواتار] نام · زمان          │
│  سفارش #۶۶۵۹ — سلام…   │  ┌──────────────────────┐    │
│  در انتظار پاسخ  ۱۴۰۵/… │  │ متن پیام              │    │
│                         │  └──────────────────────┘    │
│                         │  ──────────────────────────  │
│                         │  [ پیامت رو بنویس…      ][→] │
└─────────────────────────┴──────────────────────────────┘
```

## پاپ‌آپ «یه تیکت جدید بزن»

دکمهٔ «+» بالای فهرست (و دکمهٔ حالت خالی) این فرم را باز می‌کند:

| فیلد | توضیح |
|---|---|
| موضوع تیکت * | ۳ تا ۱۲۰ کاراکتر |
| سفارش / سرویس مرتبط (اختیاری) | جستجوی سفارش‌های **خودِ مشتری**؛ نتیجه به شکل `#۶۶۵۹ - ۳۷۵,۸۸۸ تومان` |
| متن پیام * | تا سقف تنظیم `max_message` |
| عکس (اختیاری) | فشرده‌سازی سمت مرورگر با canvas قبل از آپلود |
| یه سوال کوچیک * | جمع دو عدد، اعتبارسنجی سمت سرور |

## ایمیل‌ها

| رویداد | گیرنده | محتوا |
|---|---|---|
| ثبت تیکت جدید | مدیر (`support_email` یا `admin_email`) | موضوع، کاربر، دپارتمان، اولویت، **سفارش مرتبط**، لینک عکس، متن پیام |
| پاسخ پشتیبانی | مشتری | متن پاسخ + لینک گفتگو |

هر دو با `support.email_notifications` کنترل می‌شوند. آدرس فرستنده از
**برند و لوگو ← ایمیل فرستنده** می‌آید.

## نکات پیاده‌سازی

- **بدون رفرش**: تغییر گفتگو، ارسال پاسخ، بستن و ساخت تیکت همه با `admin-ajax` و HTML
  سمت سرور (`chat_thread_html()`)، پس مارک‌آپ یک منبع دارد و بین حالت اولیه و AJAX تفاوتی نیست.
- **بدون جاوااسکریپت هم کار می‌کند**: هر آیتم فهرست یک `<a href="?ticket=ID">` واقعی است و
  پاپ‌آپ یک `<form>` واقعی.
- **عکس**: `handle_image_upload()` با `media_handle_upload()` ذخیره می‌کند. نکتهٔ مهم:
  `wp_check_filetype_and_ext()` نقشهٔ `ext => mime` می‌خواهد (مثل `get_allowed_mime_types()`)،
  نه `mime => ext`؛ برعکس دادنش همهٔ آپلودها را رد می‌کند.
- **کپچا**: پاسخ در یک transient با کلید توکن نگه داشته می‌شود، نه در فرم. `HSW_Helpers::en_num()`
  ارقام فارسی/عربی را قبل از مقایسه به لاتین تبدیل می‌کند.
- **سبک**: بدون جدول جدید، بدون cron. متادیتای تیکت همان CPT موجود است و فقط دو متای
  `_hsw_ticket_order` و `_hsw_ticket_image` اضافه شده.
