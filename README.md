# HamiShop Elementor Widgets — ویجت‌های فروشگاهی المنتور (HamiSys)

[![CI](https://github.com/calllmeangel75-rgb/hamishop-elementor-widgets/actions/workflows/ci.yml/badge.svg)](https://github.com/calllmeangel75-rgb/hamishop-elementor-widgets/actions/workflows/ci.yml)

ویجت‌های لوپ محصولات ووکامرس برای المنتور — تبدیل دقیق طرح HTML شما به ویجت، با **شخصی‌سازی کامل فونت، رنگ و استایل** و طراحی سبک و بدون وابستگی سنگین. امتیاز نهایی Lighthouse به قالب، محتوا و محیط میزبانی بستگی دارد.

ساخته‌شده توسط **HamiSys (حامی)** — [hamisys.ir](https://hamisys.ir/)

---

## ویجت‌ها

هر سه بخشِ طرح ارسالی شما — **دسکتاپ و موبایل به‌صورت یکپارچه** — به ویجت تبدیل شده‌اند:

| ویجت | معادل در طرح | توضیح |
|---|---|---|
| **پیشنهاد شگفت‌انگیز (Wonder Deals)** | Section 1 | گرادیان قرمز، تایمر شمارش معکوس (کپسول دسکتاپ + جعبه‌های موبایل)، کارت بنر شروع، نوار پیشرفت موجودی |
| **پرفروش‌ترین‌ها (Best Sellers)** | Section 2 | نشان‌های رتبه ۱/۲/۳ با رنگ‌بندی طرح، دکمه «خرید»، لینک «مشاهده فهرست کامل» |
| **محبوب‌ترین‌ها / منتخب (Popular)** | Section 3 | تب‌های «محبوب‌ترین‌ها / جدیدترین‌ها / بیشترین تخفیف» (تعویض بدون رفرش)، نشان ویژه/ارسال رایگان/تخفیف، حالت «اتمام موجودی» با دکمه «خبرم کن» |

به‌علاوه دو **ویجت هدر** در دستهٔ «حامی — هدر و ناوبری»: **هدر فروشگاهی** و **هدر مینیمال شیشه‌ای** — جزئیات در بخش [ویجت‌های هدر](#ویجتهای-هدر-نسخه-۱۱۱۲).

## شخصی‌سازی (پنل المنتور)

برای هر ویجت در تب **Content**:
- منبع محصولات: پیشنهاد ویژه / پرفروش‌ترین / محبوب‌ترین (امتیاز) / جدیدترین / بیشترین تخفیف / منتخب / دسته‌بندی خاص / **انتخاب دستی محصولات**
- تعداد، حذف ناموجودها، برند (کلاس ویژگی مثل `pa_brand`)، امتیاز، متون همه نشان‌ها و دکمه‌ها
- شمارش معکوس: خودکار از پایان حراج محصولات یا زمان دستی
- تب‌ها: عنوان و منبع هر تب قابل ویرایش (Repeater)

در تب **Style** (همه با کنترل‌های ریسپانسیو دسکتاپ/موبایل):
- بخش: رنگ‌ها/گرادیان (لبه و وسط)، پدینگ، گردی، سایه، حاشیه
- سربرگ: تایپوگرافی و رنگ عنوان/توضیح/لینک، آیکون (نوع، اندازه، رنگ قاب)، رنگ نوار موبایل، برچسب کنار عنوان
- تایمر و فلش‌ها: رنگ کپسول/جعبه‌ها/اعداد، رنگ و گردی فلش‌ها، رنگ اسکرول‌بار
- کارت: عرض (موبایل ۱۴۴px / دسکتاپ ۲۸۸px طبق طرح)، فاصله، پس‌زمینه، حاشیه، گردی، پدینگ، زوم تصویر، تعداد خطوط عنوان، تایپوگرافی عنوان و برند
- نشان‌ها: رنگ پس‌زمینه/متن تخفیف، ویژه، ارسال رایگان + رتبه‌های ۱ و ۲و۳ و بقیه + رنگ‌های نوار موجودی
- قیمت: تایپوگرافی، رنگ قیمت جدید/قبلی
- دکمه‌ها: پس‌زمینه/رنگ (حالت عادی و هاور)، گردی
- بنر شروع و تب‌ها: رنگ‌ها، عرض بنر، تایپوگرافی تب

## بهینه‌سازی عملکرد

- **بدون هیچ فریم‌ورکی**: CSS و JS خالص — بدون Tailwind CDN، بدون jQuery
- **آیکون‌ها به‌صورت فونت زیرمجموعه لوکال**: فقط ۲۱ آیکون طرح در یک فایل `woff2` **۲۵KB** باندل شده؛ هیچ درخواست خارجی به Google Fonts زده نمی‌شود
- **بارگذاری شرطی**: CSS/JS فقط وقتی لود می‌شوند که ویجت در صفحه باشد
- تصاویر `loading="lazy"` + `decoding="async"`، کارت‌ها با `scroll-snap` بومی مرورگر (بدون کتابخانه اسلایدر)
- **فونت:** استایل پایهٔ فونت (`hsw-fonts`) همراه هر ویجت یک‌بار لود می‌شود (۱۵ KB کمینه) تا چیدمان فارسی و ارقام یکدست بماند؛ اگر «فونت اختصاصی» (وزیرمتن لوکال) روشن باشد، فایل فونت هم اضافه می‌شود.
- **امتیاز ثابت تضمین نمی‌شود:** نتیجهٔ Lighthouse به قالب، محتوا، سرعت سرور و افزونه‌های دیگر وابسته است. این افزونه دارایی‌های خودش را سبک و شرطی نگه می‌دارد؛ بهینه‌سازی کامل صفحات نیازمند بررسی همان محیط است.

## تست خودکار (CI)

هر push و هر PR روی GitHub یک workflow چهارمرحله‌ای را اجرا می‌کند (`.github/workflows/ci.yml`):

| مرحله | چه می‌سنجد |
|---|---|
| lint | `php -l` روی همهٔ فایل‌ها، روی PHP 7.4 تا 8.3 |
| harness | لود شدن همهٔ فایل‌ها به‌ترتیب وردپرس (گرفتن fatal‌های سطح declaration) |
| checks | هم‌خوانی نسخه‌ها، دامنهٔ ترجمه، نبود دیباگ، وجود `.min`، ثبت ویجت‌ها در کاتالوگ |
| generated | تازه بودن فایل‌های `.min` و `.pot` نسبت به سورس |

همین بررسی‌ها محلی هم اجرا می‌شوند:

```bash
php tools/ci-checks.php
php tests/harness.php
```

پروب‌های مرورگری (`tests/*.js`) به سایت زنده نیاز دارند و در CI اجرا نمی‌شوند.

## نصب

1. از GitHub کلون/دانلود کنید: `https://github.com/calllmeangel75-rgb/hamishop-elementor-widgets`
2. پوشه را به ZIP تبدیل کنید (یا از گزینه Code → Download ZIP استفاده کنید)
3. پیشخوان وردپرس → افزونه‌ها → افزودن → بارگذاری افزونه → فایل ZIP
4. پیش‌نیازها: **WooCommerce** + **Elementor**
5. در المنتور، دستهٔ **HamiShop — حامی** را در پنل ویجت‌ها پیدا کنید

## یادداشت‌ها

- اعداد قیمت و رتبه‌ها خودکار فارسی می‌شوند.
- **Hami Call for Price:** اگر افزونهٔ CFP فعال باشد، محصولات علامت‌خورده در همهٔ سطوح HamiShop (لوپ، آرشیو، جعبه خرید، نوار چسبان و انتخاب تنوع) به‌جای قیمت/تخفیف/تعداد/خرید آنلاین، متن و اکشن تماسِ همان افزونه را نشان می‌دهند. تشخیص از API عمومی CFP انجام می‌شود و هندلرهای ووکامرس تغییر نمی‌کنند.
- دکمه افزودن به سبد با AJAX کار می‌کند و فرگمنت‌های ووکامرس را رفرش می‌کند؛ محصولات متغیر به صفحه محصول هدایت می‌شوند.
- تعویض تب‌ها از REST Route اختصاصی (`/wp-json/hsw/v1/loop`) با امضای امن استفاده می‌کند.
- اگر برند در ویژگی `pa_brand` نبود، به اولین دسته‌بندی محصول برمی‌گردد.

# ویجت‌های صفحه محصول (نسخه ۱.۱.۰)

تبدیل دقیق HTML صفحه محصول ارسالی شما — **هم دسکتاپ هم موبایل** — به ۱۰ ویجت المنتور:

| ویجت | نقش | دسکتاپ / موبایل |
|---|---|---|
| **همی‌راه محصول** | مسیر راهنما (Breadcrumb) | هر دو (جداکننده `/` دسکتاپ، شِوران موبایل، اسکرول افقی) |
| **گالری محصول** | تصویر اصلی + بندانگشت/دات + بج تخفیف و اصالت + بزرگنمایی | هر دو |
| **نوار اعتماد و ضمانت‌ها** | اصالت / ارسال فوری / ۷ روز بازگشت | دسکتاپ |
| **عنوان، امتیاز و متا** | عنوان فارسی/انگلیسی، کد کالا، امتیاز، تعداد دیدگاه، درصد پیشنهاد، وضعیت موجودی | هر دو |
| **انتخاب رنگ و حافظه** | سواچ‌های رنگی + چیپ‌های حافظه — **موتور انتخاب تنوع واقعی ووکامرس** | هر دو |
| **ویژگی‌های شاخص** | لیست تیک‌دار (دسکتاپ) / بنتو گرید ۲×۲ (موبایل) | هر دو |
| **جعبه خرید و قیمت** | قیمت + تخفیف، شمارنده تعداد، افزودن به سبد (AJAX)، گارانتی‌ها | دسکتاپ |
| **تب‌های محصول** | بررسی تخصصی (توضیحات)، گارانتی و خدمات، مشخصات فنی (از ویژگی‌های محصول)، دیدگاه‌ها | هر دو |
| **آکاردئون‌های محصول** | مشخصات کامل / دیدگاه‌ها / گارانتی و ارسال | موبایل |
| **نوار خرید چسبان** | قیمت + تعداد + افزودن به سبد + توست موفقیت (ثابت پایین صفحه) | موبایل |

## موتور تنوع (Variable Products)

- انتخاب رنگ/حافظه، تنوع واقعی ووکامرس را پیدا می‌کند و **قیمت، قیمت قبلی، درصد تخفیف و تصویر** را همزمان در جعبه خرید دسکتاپ **و** نوار چسبان موبایل به‌روز می‌کند.
- افزودن به سبد با `variation_id` صحیح از طریق `wc-ajax=add_to_cart` انجام و فرگمنت‌های مینی‌سبد رفرش می‌شوند.
- نام ویژگی‌ها در کنترل‌های ویجت تنظیم می‌شود (پیش‌فرض `pa_color` و `pa_memory`) و رنگ سواچ‌ها با نگاشت نام ترم → کد رنگ تعیین می‌شود.

## فونت وزیرمتن لوکال 🆕

- فونت **وزیرمتن متغیر** (Vazirmatn Variable، وزن‌های ۱۰۰ تا ۹۰۰ در یک فایل) **داخل افزونه پک شده** و با `font-display: swap` لود می‌شود؛ هیچ درخواستی به Google Fonts زده نمی‌شود. فایل به همان بازه‌های یونیکدی که سایت واقعاً رندر می‌کند محدود شده است (۱۰۸KB → ۶۴KB).
- در فهرست فونت‌های المنتور با نام **«Vazirmatn HSW»** (گروه HamiShop لوکال) ثبت شده و در همه کنترل‌های تایپوگرافی قابل انتخاب است.
- آیکون‌ها دیگر فونت نیستند: **SVG sprite** درون همان صفحه، فقط شامل آیکون‌هایی که آن صفحه رندر کرده است (۹۹ نام در دسترس، ۱۷–۲۲KB در هر صفحه، بدون درخواست جدا).

## چیدمان پیشنهادی صفحه محصول (المنتور)

1. یک کانتینر دو ستونه (در موبایل تک‌ستونه): ستون راست = گالری + نوار اعتماد؛ ستون چپ = عنوان → رنگ/حافظه → ویژگی‌ها → جعبه خرید
2. زیر آن، تمام‌عرض: تب‌های محصول (دسکتاپ) یا آکاردئون‌ها (موبایل)
3. همی‌راه محصول بالای کانتینر؛ نوار خرید چسبان هر جای صفحه (fixed پایین viewport)

## بهینه‌سازی عملکرد

- CSS و JS صفحه محصول فقط وقتی ویجت‌ها در صفحه باشند لود می‌شوند (Elementor dependency).
- صفر درخواست خارجی: فونت‌ها، آیکون‌ها و استایل‌ها همگی لوکال.
- بدون jQuery؛ فقط Event Delegation؛ تصاویر lazy (اصلی eager با `fetchpriority="high"`).

# ویجت‌های جامع + مجله (نسخه ۱.۷.۰)

## ویجت‌های جامع (Composite) — کل صفحه با یک ویجت

شش ویجت جامع اضافه شد که همهٔ بخش‌های یک صفحهٔ فروشگاهی را با **یک درگ** می‌چینند.
داخل هر ویجت جامع، همان ویجت‌های تکی به‌صورت «بخش/پارت» رندر می‌شوند و برای هر بخش
یک سوییچ «نمایش این بخش» + مهم‌ترین کنترل‌ها (با پیشوند، مثلاً `pga_zoom`) در دسترس است.
ویجت‌های تکی هم مثل قبل مستقل کار می‌کنند و رفتارشان تغییری نکرده.

| ویجت جامع | شامل بخش‌ها |
|---|---|
| **صفحه کامل محصول** | بردکرامب → گالری → عنوان/امتیاز → رنگ و حافظه → ویژگی‌ها → جعبه خرید → اعتمادها → تب‌ها/آکاردئون‌ها → نوار چسبان |
| **صفحه کامل آرشیو** | بردکرامب → سربرگ → فیلترها (سایدبار/موبایل) → نوار ابزار → شبکه محصولات → صفحه‌بندی → راهنمای خرید |
| **صفحه کامل سبد خرید** | هدر/مراحل → بنر ارسال رایگان → اقلام → کد تخفیف → خلاصه و پرداخت |
| **صفحه کامل تسویه حساب** | هدر/مراحل → آدرس → روش ارسال → زمان تحویل → یادداشت/فاکتور → اقلام → خلاصه و ثبت سفارش |
| **صفحه کامل پرداخت** | هدر/مراحل → یادآوری سفارش → درگاه‌ها/کیف پول → کد تخفیف → خلاصه نهایی و پرداخت امن |
| **صفحه کامل مجله** | سربرگ مجله → تب دسته‌ها/مرتب‌سازی → مقاله ویژه → شبکه + صفحه‌بندی → سایدبار (پربازدید/خبرنامه/برچسب) |
| **صفحه کامل تکمیل خرید** | سربرگ موفقیت → جزئیات سفارش → اطلاعات تحویل → مراحل بعدی سفارش → دکمه‌های پایانی و پشتیبانی |

- چیدمان ستون‌ها از پنل قابل تنظیم است (عرض سایدبار/نسبت ستون گالری + فاصله) و در موبایل تک‌ستونه می‌شود.
- از نسخهٔ ۱.۱۱.۱۴۹ تب **استایل** صفحهٔ کامل محصول بخش‌های تفصیلی گالری، عنوان/امتیاز، قیمت، موجودی/برچسب‌ها، توضیحات، ویژگی‌ها، متغیرها، تعداد/خرید، پیام‌ها، تب‌ها، محصولات مرتبط و اعتماد دارد؛ هر بخش فقط وقتی دیده می‌شود که پارت محتوایی‌اش فعال باشد. رنگ‌های عمومی از پالت (`hsw_palette`) می‌آیند؛ از ۱.۱۱.۱۵۱ پالت اختصاصی ویجت حذف شده و کنترل‌های رنگی عنصربه‌عنصر باقی مانده‌اند.
- موتور: `includes/class-hsw-composite.php` + هلپرهای `part_section()` / `part_controls()` / `print_part()` در کلاس پایه. خطای یک پارت هرگز کل صفحه را نمی‌خواباند (Throwable-safe).
- ویجت‌های تکی موجود هیچ شناسهٔ کنترلی تغییر نکرده — تنظیمات قبلی صفحات شما دست‌نخورده باقی می‌ماند.

## خانوادهٔ مجله و وبلاگ (دستهٔ «حامی — ویجت‌های مجله و وبلاگ»)

هفت ویجت تازه، کاملاً داینامیک از مطالب/دسته‌ها/برچسب‌های خود سایت:

| ویجت | نقش |
|---|---|
| **سربرگ مجله** | بج + عنوان + توضیح + آمار زنده (تعداد مقاله/دسته/دیدگاه) + جستجو + برچسب‌های داغ |
| **تب دسته‌ها و مرتب‌سازی** | پیل‌های دسته (با شمارش) + انتخاب جدیدترین/پربحث‌ترین/قدیمی‌ترین — سرورساید و سئوپسند (بدون JS) |
| **مقاله ویژه** | کارت بزرگ مقالهٔ اول صفحه با دسته، خلاصه، نویسنده، تاریخ و زمان مطالعه |
| **شبکه مقالات** | کارت‌های مقالات + خلاصه + متا + صفحه‌بندی (تعداد ستون ریسپانسیو) |
| **پربازدیدترین‌ها** | لیست رتبه‌دار (منبع: دیدگاه‌ها؛ وردپرس شمارنده بازدید ندارد — برچسب قابل تغییر است) |
| **خبرنامه** | فرم عضویت با مقصد دلخواه (URL سرویس ایمیل) یا جایگزینی با شورت‌کد هر فرم‌ساز |
| **برچسب‌های داغ** | ابر برچسب‌ها بر اساس پرکاربردترین‌ها + هایلایت برچسب اول |

- زمان مطالعه خودکار تخمین زده می‌شود (۲۰۰ کلمه/دقیقه) و اعداد فارسی می‌شوند.
- استایل: `assets/css/hsw-blog.css` (توکن‌های طرح: سرمه‌ای تیره + نارنجی) — موبایل‌فرست.

# مجموعهٔ تکمیل خرید (نسخه ۱.۸.۰)

صفحهٔ «سفارش ثبت شد» که مشتری بعد از برگشت از درگاه پرداخت می‌بیند — کاملاً قابل تنظیم و پر‌شده از دادهٔ واقعی سفارش:

| ویجت | نقش |
|---|---|
| **صفحه کامل تکمیل خرید** (جامع) | سربرگ موفقیت + جزئیات سفارش + اطلاعات تحویل (ستون اصلی) + مراحل بعدی + دکمه‌های پایانی (ستون کناری) |
| **سربرگ موفقیت** | آیکن، عنوان/زیرعنوان، چیپ‌های شمارهٔ سفارش (ارقام فارسی)/تاریخ/وضعیت + کارت «سفارش یافت نشد» برای لینک ناقص/منقضی |
| **جزئیات سفارش** | اقلام و تصاویر واقعی، جمع سبد، تخفیف، ارسال (یا «رایگان»)، مالیات، مبلغ کل، روش پرداخت + نشان «پرداخت شده / در انتظار پرداخت»، یادداشت مشتری و خروجی اختصاصی درگاه (مثل صفحهٔ تشکر خود ووکامرس) |
| **اطلاعات تحویل** | تحویل‌گیرنده، تلفن، نشانی، کد پستی، روش ارسال (shipping → billing) |
| **مراحل بعدی سفارش** | ریپیتر آیکن/عنوان/توضیح با خط اتصال — متن سایت، نه دادهٔ سفارش |
| **دکمه‌های پایانی و پشتیبانی** | دکمهٔ هوشمند (پرداخت سفارش / مشاهدهٔ سفارش در حساب من / ورود به حساب) + ادامه خرید + ایمیل تأییدیهٔ ناشناس‌شده + جعبهٔ پشتیبانی |

## مسیردهی و تنظیم

- تنظیم: **ووکامرس → تنظیمات → تسویه حساب** — بخش «مسیر خرید (حامی)»: «صفحهٔ پرداخت (مرحلهٔ ۳)» و «صفحهٔ تکمیل خرید (مرحلهٔ ۴)». صفحه‌ها را بسازید و ویجت جامع هر مرحله را داخلشان بگذارید و اینجا انتخاب کنید. خالی بماند = رفتار پیش‌فرض (دکمهٔ تسویه به صفحهٔ تسویه، کارت تأیید داخل صفحهٔ پرداخت).
- ریدایرکت با فیلتر رسمی `woocommerce_get_checkout_order_received_url` انجام می‌شود؛ پس همهٔ درگاه‌ها، پرداخت‌های بدون درگاه (کارت‌به‌کارت/پرداخت در محل)، لینک‌های پرداخت ایمیل‌ها و Store API خودکار به صفحهٔ شما می‌آیند — همراه شمارهٔ سفارش و کلید امن. آدرس‌های قدیمی `/checkout/order-received/` هم خودکار ریدایرکت می‌شوند.
- نمایش سفارش فقط با کلید معتبر یا برای مالک واردشده؛ برای همه‌ی بقیه حالت «سفارش یافت نشد» با دکمه‌های حساب کاربری/ادامه خرید.
- بدون JS در این مجموعه؛ استایل `assets/css/hsw-complete.css` (وابسته به توکن‌های `hsw-checkout.css`) فقط وقتی لود می‌شود که ویجت‌های تکمیل خرید در صفحه باشند.

# ویجت‌های هدر (نسخه ۱.۱۱.۶۹)

دو ویجت هدر کامل در دستهٔ **«حامی — هدر و ناوبری»** (`hamishop-header`). هر دو روی یک کلاس پایهٔ مشترک (`HSW_Header_Base`) ساخته شده‌اند و دارایی‌هایشان مشترک است: `assets/css/hsw-header.css` و `assets/js/hsw-header.js` — فقط وقتی لود می‌شوند که یکی از این دو ویجت در صفحه باشد.

| ویجت | ظاهر | مناسب برای |
|---|---|---|
| **هدر فروشگاهی** (`hsw-header-store`) | نوار اعلان بالا + ردیف اصلی با لوگو، دکمهٔ «دسته‌بندی محصولات» با مگامنو، جستجوی محصول، حساب و سبد خرید | فروشگاه‌های کامل با دسته‌بندی زیاد |
| **هدر مینیمال شیشه‌ای** (`hsw-header-minimal`) | پیل شیشه‌ای شناور (blur + شفافیت) با منوی واقعی، جستجو و دکمهٔ اقدام | لندینگ‌ها و فروشگاه‌های سبک |

## قابلیت‌های مشترک

- **منوی واقعی وردپرس** با `wp_nav_menu` — همان منویی که در «نمایش → فهرست‌ها» ساخته‌اید؛ زیرمنوها خودکار به آکاردئون موبایل تبدیل می‌شوند.
- **جستجوی محصول ووکامرس**: فرم با فیلد `s` و `post_type=product` و دکمهٔ بومی؛ انتخاب دسته‌بندی کنار جستجو اختیاری است.
- **سبد خرید و حساب کاربری** با آدرس‌های بومی ووکامرس (`wc_get_cart_url()` و `wc_get_page_permalink( 'myaccount' )`) — هیچ لینک دستی یا هندلر جایگزینی وجود ندارد.
- **شمارنده و جمع سبد** از فرگمنت‌های بومی ووکامرس (`woocommerce_add_to_cart_fragments`) رفرش می‌شود؛ بدون رفرش صفحه و بدون jQuery.
- **هدر چسبان (Sticky)** اختیاری با سایهٔ ملایم در حالت اسکرول.
- **مخفی‌شدن هوشمند** (نسخه ۱.۱۱.۲۱): با اسکرول به پایین هدر کنار می‌رود و با کوچک‌ترین اسکرول به بالا برمی‌گردد — موبایل و دسکتاپ یکسان. تا ارتفاع «آستانهٔ شروع» هدر همیشه می‌ماند و هرگز وقتی مگامنو، جستجو یا دراور باز است مخفی نمی‌شود. جزئیات فنی در [WIDGET-GUIDE](WIDGET-GUIDE.md#هدر-چسبان-و-مخفی‌شدن-هوشمند-v11121).
- **دراور موبایل** با بستن روی کلیک بیرون، کلید `Esc` و قفل اسکرول بدنه.
- **دراور سبد خرید** (نسخه ۱.۱۱.۱۴۸): کلیک روی آیکون سبد، پنل کناری اقلام سبد را با تصویر، تعداد، حذف، جمع سبد، «مشاهده سبد خرید» و «صورت‌حساب» باز می‌کند. محتوای آن با فرگمنت‌های ووکامرس رفرش می‌شود، روی کلیک بیرون/`Esc` بسته می‌شود و به‌صورت دیالوگ دسترس‌پذیر با تله فوکوس و قفل اسکرول کار می‌کند.
- **مگامنو دسته‌بندی** (هدر فروشگاهی) از درخت واقعی `product_cat`: دسته‌ها در دسکتاپ به‌صورت **آبشاری به سمت چپ** باز می‌شوند، تا ۳ لایه پشتیبانی می‌کنند و محصولات فقط در انتهای مسیر با تصویر کوچک، نام و قیمت نمایش داده می‌شوند. دسته‌بندی‌های سربرگ از المنتور قابل انتخاب‌اند و در حالت خالی، ۵ دستهٔ اول فروشگاه نمایش داده می‌شود؛ همین فهرست در دراور موبایل هم استفاده می‌شود.
- **پنل جستجوی شیشه‌ای** (هدر مینیمال) به‌صورت اورلی سبک.
- **نمایش در** (دسکتاپ/تبلت/موبایل) برای هر ویجت به‌صورت مستقل.

## تنظیمات (تب Content)

- **برند و لوگو**: تصویر لوگو، نام برند، شعار، عرض لوگو
- **منو و ناوبری**: انتخاب منوی وردپرس، نمایش/مخفی منو، نمایش دسته‌بندی محصولات در منوی موبایل، هدر چسبان، مخفی‌شدن هوشمند هنگام اسکرول + آستانهٔ شروع (پیکسل)
- **جستجو**: نمایش جستجو، متن راهنما، انتخاب دسته‌بندی کنار جستجو، متن دکمه
- **حساب، سبد و پشتیبانی**: نمایش/برچسب حساب، نمایش/برچسب سبد، شمارهٔ پشتیبانی و برچسب آن

اختصاصی **هدر فروشگاهی**: نوار اعلان (برچسب، متن، برچسب زبان/واحد پول، دو لینک دلخواه) و مگامنو (عنوان دکمه، انتخاب دسته‌بندی‌های سربرگ، تعداد پیش‌فرض ۵، عمق ۱–۳، تعداد محصول انتهایی ۳/۴/۶، متن اعتماد).

اختصاصی **هدر مینیمال شیشه‌ای**: دکمهٔ اقدام (متن و لینک) و پیل شیشه‌ای (سایه، میزان بلور).

## تنظیمات (تب Style)

رنگ اصلی، پس‌زمینهٔ هدر، رنگ متن و متن کم‌رنگ، رنگ حاشیه‌ها، پس‌زمینهٔ جستجو، گردی گوشه‌ها، عرض محتوا، تایپوگرافی نام برند و منو — همه با کنترل‌های ریسپانسیو. رنگ‌های اختصاصی هر ویجت در بخش «نوار اعلان و ناوبری» همان ویجت است.

## نکته‌های پیاده‌سازی

- بدون فونت یا تصویر خارجی؛ آیکون‌ها از **SVG sprite درون صفحه** می‌آیند (`HSW_Helpers::icon()` + `wp_footer`).
- هیچ تغییری در فرم‌ها، نانس‌ها، اندپوینت‌ها یا هندلرهای ووکامرس داده نشده؛ هدر فقط لینک و فرم بومی می‌سازد.
- برای استفاده به‌عنوان هدر سراسری، ویجت را در یک قالب هدر المنتور (Theme Builder → Header) بگذارید.
- سایت‌هایی که از قبل گزینهٔ `hsw_enabled_widgets` را ذخیره کرده‌اند، هر دو ویجت هدر را به‌صورت یک‌باره و خودکار دریافت می‌کنند (گزینهٔ `hsw_header_widgets_migrated`).

# کنترل ویجت‌ها (نسخه ۱.۱۱.۶۹)

صفحهٔ مستقل **HamiShop → کنترل ویجت‌ها** مشخص می‌کند کدام ویجت‌ها در پنل المنتور دیده شوند:

- **۱۳ ویجت اصلی** پیش‌فرض فعال‌اند: دو ویجت هدر، سه ویجت لوپ، صفحه‌های کامل محصول/آرشیو/سبد خرید/تسویه حساب/پرداخت/تکمیل خرید، مجله و پنل حساب کاربری.

- هفت گروه: هدر و ناوبری، لوپ محصولات، صفحه محصول، سبد خرید و پرداخت، آرشیو محصولات، مجله و وبلاگ، حساب کاربری (در مجموع ۵۹ ویجت).

- تنظیم فقط روی **ثبت ویجت در المنتور** اثر دارد؛ ویجت‌های جامع بخش‌های داخلی خود را مستقل از این تنظیم رندر می‌کنند.
- ذخیره در گزینهٔ `hsw_enabled_widgets` با Settings API و نانس بومی وردپرس؛ بدون کتابخانهٔ خارجی و با CSS/JS داخلی سبک.
- اگر از یک بخش مستقل در صفحه‌ای ساخته‌شده استفاده کرده‌اید، پیش از خاموش‌کردن آن به هشدار همین صفحه توجه کنید.

# پالت رنگی (نسخه ۱.۱۱.۶)

صفحهٔ **HamiShop → پالت رنگی** یک منبع واحد رنگ برای همهٔ ویجت‌هاست:

- ذخیره در گزینهٔ `hsw_palette` با نانس و بررسی دسترسی؛ دکمهٔ «بازنشانی به پیش‌فرض» هم دارد.
- مقدار پیش‌فرض همان آبی فعلی سایت (`#2563eb`) است، بنابراین فعال‌کردن این نسخه ظاهر سایت را عوض نمی‌کند تا خودتان رنگی را تغییر دهید.

# صفحه کامل نوشته (نسخه ۱.۱۱.۷)

ویجت **`hsw-post-page`** در گروه «مجله و وبلاگ» یک قالب تکی مقالهٔ کامل است و برای قالب Single Post المنتور ساخته شده.

- **دادهٔ واقعی:** عنوان، دسته، برچسب‌ها، نویسنده (نام، بیو، آواتار)، تاریخ، زمان مطالعه، تعداد دیدگاه و بازدید (`hsw_post_views`).
- **فهرست مطالب خودکار** از هدینگ‌های `h2`/`h3` متن نوشته ساخته می‌شود. نوع لنگر در تنظیمات «لنگر سرفصل‌ها» انتخاب می‌شود:
  - **از متن تیتر (پیش‌فرض):** آدرس خوانا و باثبات مثل `#فناوری-حذف-نویز-فعال`؛ مناسب اشتراک‌گذاری لینک هر بخش و سئو. تیتر تکراری `-2` می‌گیرد.
  - **شماره‌ای:** `hsw-h-1`، `hsw-h-2` …
  - **بدون لینک لنگر:** فهرست با دکمه اسکرول می‌کند و هیچ آدرس `…/#heading` ساخته نمی‌شود، پس چیزی برای ایندکس‌شدن در گوگل باقی نمی‌ماند.
- **کارت محصول داخل مقاله:** شناسهٔ محصول را در تنظیمات بدهید؛ اگر خالی بماند اولین محصولِ دستهٔ نوشته و در نهایت جدیدترین محصول پیشنهاد می‌شود. محصولات «تماس برای قیمت» به‌جای قیمت، متن تماس نشان می‌دهند.
- **دیدگاه‌ها واقعی‌اند:** `wp_list_comments` با کالبک اختصاصی + `comment_form` بومی؛ پاسخ‌های تودرتو و نشان «نویسنده» پشتیبانی می‌شود.
- **مقالات مرتبط** از دستهٔ همان نوشته، **نوشتهٔ قبلی/بعدی** از ترتیب وردپرس.
- **موبایل‌اول:** نوار بالای چسبان، نوار پیشرفت مطالعه، فهرست مطالب آکاردئونی و نوار چسبان پایین (پسند، پرش به دیدگاه‌ها، خرید کالا). از ۱۰۲۴px به دو ستون با سایدبار چسبان (فهرست، نویسنده، پربازدیدها) تبدیل می‌شود.
- همهٔ رنگ‌ها از «پالت رنگی» می‌آید؛ هر بخش را می‌توان در تنظیمات ویجت خاموش کرد.

# شخصی‌سازی متن (نسخه ۱.۱۱.۸)

هر متن توضیحی طولانی، در تب **استایل** ویجت، این کنترل‌ها را دارد:

| کنترل | گزینه‌ها |
|---|---|
| تراز متن | شروع سطر (راست در RTL) · وسط‌چین · پایان سطر · **هم‌تراز دو طرف (justify)** |
| جهت متن | مطابق قالب سایت · **RTL** · **LTR** |
| ارتفاع خط | اسلایدر `em` / `px` |
| اندازهٔ فونت | اسلایدر `px` |

همه پاسخ‌گو هستند (دسکتاپ / تبلت / موبایل جدا). اعمال‌شده روی:

- **آرشیو فروشگاه و آرشیو دسته‌بندی** — «متن توضیحات آرشیو» در ویجت جامع آرشیو (و ویجت سربرگ آرشیو)،
  هم نسخهٔ دسکتاپ و هم تیزر موبایل، به‌همراه جعبهٔ توضیحات پایین محصولات.
- **نوشتهٔ تکی** — «تراز و جهت متن مقاله» در تب استایل.
- **سربرگ مجله** — «متن توضیح سربرگ مجله» در ویجت جامع مجله.
- **توضیحات محصول** — «تراز، جهت و ارتفاع خط توضیحات محصول» در تب‌های صفحه محصول.

> تراز با `text-align: start/end` پیاده شده، پس «شروع سطر» در سایت فارسی راست و در سایت انگلیسی چپ می‌شود؛ لازم نیست برای هر زبان مقدار را عوض کنید.

## دکمه‌ها

هر دکمهٔ اصلی، در تب **استایل**، این کنترل‌ها را دارد (تب عادی + تب هاور):

پس‌زمینه · رنگ متن · پس‌زمینه هاور · رنگ متن هاور · تایپوگرافی دکمه (اندازه/وزن/ارتفاع خط) · حاشیه · گردی گوشه‌ها · فاصله داخلی · سایه

| دکمه | کجا |
|---|---|
| خرید کارت محصول (`hsw-pp__prodbtn`) | صفحهٔ نوشته |
| خرید نوار پایین موبایل (`hsw-pp__dockcta`) | صفحهٔ نوشته |
| ارسال دیدگاه (`hsw-pp__submit`) | صفحهٔ نوشته |
| افزودن به سبد (`.hsw-add`) | ویجت‌های لوپ: پیشنهاد شگفت‌انگیز، پرفروش‌ترین‌ها، محبوب |
| دسته‌بندی محصولات و جستجو | هدر فروشگاهی و مینیمال |
| اعمال فیلتر | آرشیو (ویجت فیلترها و ویجت جامع) |
| خرید محصول و نوار چسبان | صفحهٔ کامل محصول |

## آیکون‌ها

آیکون‌ها **SVG sprite** هستند، نه فونت. `HSW_Helpers::icon( 'add' )` این را چاپ می‌کند:

```html
<svg class="hsw-ic" aria-hidden="true"><use href="#hsw-i-add"></use></svg>
```

و `HSW_Helpers::print_sprite()` در `wp_footer` فقط نمادهای همان صفحه را چاپ می‌کند.

| | قبل (فونت) | بعد (sprite) |
|---|---|---|
| حجم | ۹۴KB woff2، همیشه | ۱۷–۲۲KB درون HTML، فقط آیکون‌های همان صفحه |
| درخواست | یک فونت جدا + FOUT | صفر |
| رنگ | با محور FILL و `font-variation-settings` | `fill: currentColor` |
| سایز | `font-size` روی `.hsw-ic` | همان `font-size` (چون `1em` است) |

نام‌های غیراستاندارد در `icon_name()` معادل‌سازی شده‌اند (`bell`→`notifications`،
`trash`→`delete`، `user`→`person`، `phone`→`call`، `location`→`place`، `plus`→`add`،
`favorite_border`→`favorite` و …).

برای آیکون تازه: نام را به `tools/_icons.txt` اضافه کنید و
`python tools/build-sprite.py tools/_full.woff2` را اجرا کنید (خروجی:
`includes/class-hsw-icon-paths.php`). نام ناشناخته به یک نقطهٔ بی‌طرف تبدیل می‌شود، نه متن انگلیسی.

## صفحهٔ کامل محصول — استایل یکپارچه

ویجت `hsw-product-page` در تب **استایل** بخش «رنگ‌ها و فونت (یکپارچه)» دارد:

- **رنگ:** عنوان، قیمت اصلی، قیمت قبل از تخفیف، متن توضیحات/ویژگی‌ها/اعتماد، تب فعال و غیرفعال، برچسب رنگ و حافظه، مسیر راهنما.
- **تایپوگرافی:** عنوان، قیمت، متن تب‌ها، ویژگی‌های کلیدی، برچسب واریانت، تب‌ها.
- **دکمه‌ها:** خرید (جعبه خرید) و نوار چسبان — با هاور، حاشیه، گردی، فاصله و سایه.

تنظیمات ریز هر بخش (۱ تا ۱۰) در تب «محتوا» دست‌نخورده باقی مانده‌اند.

## بهینه‌سازی (نسخه ۱.۱۱.۱۳)

- هر فایل CSS/JS یک نسخهٔ `.min` دارد و وردپرس تا وقتی `SCRIPT_DEBUG` خاموش است همان را لود می‌کند:
  **CSS ۴۲۷KB → ۳۱۴KB (۲۶٪)** و **JS ۱۲۳KB → ۷۶KB (۳۸٪)**.
- بازسازی بعد از هر تغییر: `python tools/build-assets.py` (پوشهٔ `tools` در بستهٔ نصبی نیست).
- هر ویجت فقط استایل و اسکریپت خودش را لود می‌کند (`get_style_depends` / `get_script_depends`).
- فونت‌ها لوکال‌اند (هیچ درخواست خارجی)، تصاویر `loading="lazy"`، اسکریپت‌ها در فوتر.
- **سمت هاست:** gzip/Brotli را روشن کنید — همان ۳۱۴KB به ~۵۵KB می‌رسد. این تنها بزرگ‌ترین
  اهرم باقی‌مانده است و در پلاگین قابل انجام نیست.
- **تصویر LCP:** تصویر کارت اول در آرشیو و شبکهٔ مقالات `loading="eager"` + `fetchpriority="high"` است
  (بقیه lazy). تصویر اصلی گالری محصول و تصویر شاخص مقاله هم eager هستند.
- **preconnect** به `secure.gravatar.com` برای آواتارها.

### تنظیم پیشنهادی سرور (برای Lighthouse)

```apache
# gzip
AddOutputFilterByType DEFLATE text/html text/css application/javascript image/svg+xml application/json

# cache
<FilesMatch "\.(css|js|woff2|png|jpg|jpeg|webp|svg|gif|ico)$">
  Header set Cache-Control "public, max-age=31536000, immutable"
</FilesMatch>
<FilesMatch "\.(html)$">
  Header set Cache-Control "public, max-age=0, must-revalidate"
</FilesMatch>
```

در nginx معادل: `gzip on;` و `location ~* \.(css|js|woff2|png|jpg|webp|svg)$ { expires 1y; }`.
با این دو، همان دو هشدار «No compression applied» و «Cache TTL = None» برطرف می‌شود.

جاهایی که قبلاً «HamiShop» ثابت نوشته شده بود از همین مقادیر می‌خوانند:

## آدرس دلخواه پیشخوان

`wp-admin` برای **کاربر مهمان** ۴۰۴ می‌شود و پیشخوان از آدرس دلخواه (مثلاً `/manage/`) سرو
می‌شود. قاعده در `.htaccess` ریشه نوشته می‌شود و **قبل از فعال‌شدن با یک درخواست واقعی به همان
آدرس تست می‌شود**؛ اگر وب‌سرور آن را اجرا نکند (Nginx، `AllowOverride None`)، تنظیم فعال نمی‌شود
تا هیچ مدیری قفل نشود.

نکات مهم پیاده‌سازی:

- **کاربر واردشده هرگز بلاک نمی‌شود.** `/wp-admin/` برای او به آدرس دلخواه ریدایرکت می‌شود و
  مسیرهای عمیق (`/wp-admin/post.php?...`) مستقیم کار می‌کنند. یعنی بدترین حالت ممکن، برگشتن به
  رفتار عادی است — نه قفل‌شدن.
- **کوکی `auth` وردپرس به `wp-admin/` محدود است.** برای اینکه آدرس دلخواه احراز هویت شود، کوکی
  معادل `auth` فقط برای همان درخواست از روی کوکی `logged_in` ساخته می‌شود
  (`resolve_user_from_logged_in_cookie`). کوکی گسترده‌تری به مرورگر داده نمی‌شود.
- `admin-ajax.php` و `admin-post.php` باز می‌مانند (فرم‌ها و فیلترهای فروشگاه از آن‌ها استفاده
  می‌کنند).
- با غیرفعال‌کردن افزونه، بلوک `.htaccess` پاک می‌شود (`register_deactivation_hook`).
- برای Nginx، کانفیگ آماده در همان صفحه نمایش داده می‌شود.

## مخفی‌کردن فهرست کاربران

`/wp-json/wp/v2/users` و `/wp-json/wp/v2/users/<id>` برای هر کسی که `list_users` ندارد حذف
می‌شوند. `/wp/v2/users/me` دست‌نخورده می‌ماند چون ویرایشگر بلوک و پنل حساب به آن نیاز دارند.

## XML-RPC

اختیاری؛ `xmlrpc_enabled` را خاموش می‌کند و هدر `X-Pingback` را برمی‌دارد.

# فرم‌های حساب کاربری (نسخه ۱.۱۱.۲۲)

فرم «اطلاعات حساب» ووکامرس **جایگزین نشده** — همان مارک‌آپ بومی با همان nonce و همان اکشن
رندر می‌شود، فقط بازطراحی شده. دلیلش ساده است: افزونه‌های دیگر به `woocommerce_edit_account_form`
وصل می‌شوند و اگر فرم را از نو می‌نوشتیم، فیلدهایشان حذف می‌شد.

زبان بصری مشترک با فرم ورود/ثبت‌نام پنل: ارتفاع ۵۲px، گوشهٔ ۱۳px، پس‌زمینهٔ `#f7f9fc`، فوکوس
سفید + حلقهٔ برند. نام/نام‌خانوادگی در دو ستون با `@container` کنار هم می‌نشینند — یعنی به عرض
**کارت** واکنش می‌دهند نه عرض صفحه، چون این فرم در ستونی به عرض ~۴۶۰px کنار سایدبار حساب قرار
می‌گیرد.

# تأیید ایمیل حساب (نسخه ۱.۱۱.۲۳)

فروشگاه‌هایی که ورود را با کد پیامکی انجام می‌دهند، هنگام ثبت‌نام ایمیل هم می‌گیرند — ولی هیچ‌وقت
ثابت نمی‌شود که آن ایمیل مال همان کاربر است. نتیجه: فاکتورها و بازیابی رمز به آدرسی می‌رود که
کسی تأییدش نکرده.

این نسخه آن حلقهٔ گم‌شده را اضافه می‌کند:

1. کاربر پیامکی در **پیشخوان / سفارش‌ها / اطلاعات حساب** یک نوار ملایم می‌بیند.
2. با زدن «تأیید ایمیل» یک کد ۶ رقمی به همان صندوق می‌رود.
3. با وارد کردن کد، ایمیل تأیید و روی حساب ثبت می‌شود (`user_email` + `billing_email`) و نوار
   برای همیشه محو می‌شود.

| نکته | رفتار |
|---|---|
| چه کسی این نوار را می‌بیند | فقط حسابی که با OTP پیامکی ساخته شده (`_hsw_auth_phone`) و ایمیلش تأیید نشده |
| کسی که با رمز ثبت‌نام کرده | نوار نمی‌بیند؛ تأییدیهٔ خود ووکامرس را دارد |
| اعتبار کد | ۱۵ دقیقه |
| تلاش مجاز | ۵ بار، بعد از آن کد می‌سوزد |
| فاصلهٔ ارسال | ۶۰ ثانیه |
| ایمیل متعلق به حساب دیگر | رد می‌شود (۴۰۹) |
| سوئیچ | HamiShop ← پنل حساب کاربری ← فعال‌سازی و چیدمان |

**چرا سبک است:** دو متای کاربر (`_hsw_email_verified` و کد موقت)، دو اکشن `admin-ajax`، بدون جدول
جدید، بدون cron، بدون کوئری اضافه در بارگذاری صفحه. بعد از تأیید، هیچ کدی اجرا نمی‌شود.

## آدرس و نام ایمیل فرستنده

جایگزین اسنیپت `wp_mail_from` / `wp_mail_from_name` در فانکشن قالب:
**HamiShop ← برند و لوگو ← ایمیل فرستنده**.

- **آدرس فرستنده** — خالی = همان `wordpress@دامنه` وردپرس. برای تحویل بهتر باید روی دامنهٔ همان
  سایت باشد.
- **نام فرستنده** — خالی = نام برند.

این تنظیم روی همهٔ ایمیل‌های سایت اثر دارد (سفارش، بازیابی رمز، کد تأیید ایمیل)، دقیقاً مثل همان
فیلترهایی که قبلاً در قالب می‌گذاشتید.

# پشتیبانی به سبک گفتگو (نسخه ۱.۱۱.۲۴)

بخش پشتیبانی از سه صفحهٔ جدا به **یک صفحهٔ دوستونه** تبدیل شد:

```
┌─────────────────────────┬──────────────────────────────┐
│  گفتگوها            [+] │  موضوع گفتگو      [بستن]     │
│  🔍 جستجوی گفتگو…       │  وضعیت · #T-123 · سفارش #۶۶۵۹ │
│  ─────────────────────  │  ──────────────────────────  │
│  مشکل در ارسال سفارش    │  [آواتار] نام · زمان          │
│  سفارش #۶۶۵۹ — سلام…   │  ┌──────────────────────┐    │
│  در انتظار پاسخ  ۱۴۰۵/… │  │ متن پیام              │    │
│                         │  └──────────────────────┘    │
│                         │  ──────────────────────────  │
│                         │  [ پیامت رو بنویس…      ][→] │
└─────────────────────────┴──────────────────────────────┘
```

## پاپ‌آپ «یه تیکت جدید بزن»

دکمهٔ «+» بالای فهرست (و دکمهٔ حالت خالی) این فرم را باز می‌کند:

| فیلد | توضیح |
|---|---|
| موضوع تیکت * | ۳ تا ۱۲۰ کاراکتر |
| سفارش / سرویس مرتبط (اختیاری) | جستجوی سفارش‌های **خودِ مشتری**؛ نتیجه به شکل `#۶۶۵۹ - ۳۷۵,۸۸۸ تومان` |
| متن پیام * | تا سقف تنظیم `max_message` |
| عکس (اختیاری) | فشرده‌سازی سمت مرورگر با canvas قبل از آپلود |
| یه سوال کوچیک * | جمع دو عدد، اعتبارسنجی سمت سرور |

## ایمیل‌ها

| رویداد | گیرنده | محتوا |
|---|---|---|
| ثبت تیکت جدید | مدیر (`support_email` یا `admin_email`) | موضوع، کاربر، دپارتمان، اولویت، **سفارش مرتبط**، لینک عکس، متن پیام |
| ثبت تیکت جدید | **مشتری** | تأیید ثبت + شمارهٔ پیگیری `#T-…` + لینک گفتگو (از ۱.۱۱.۳۲) |
| پاسخ پشتیبانی | مشتری | متن پاسخ + لینک گفتگو |
| پاسخ کاربر | مدیر | متن پاسخ کاربر |

همه با `support.email_notifications` کنترل می‌شوند. آدرس فرستنده از
**برند و لوگو ← ایمیل فرستنده** می‌آید.

## پاسخ دادن از داخل ایمیل (نسخه ۱.۱۱.۳۲)

هر ایمیل تیکت با یک `Reply-To` **امضاشده** فرستاده می‌شود:

```
From    : فروشگاه <shop@example.com>
Reply-To: shop+t13469.d7957d5eb8@example.com
                     └┬─┘ └────┬────┘
                      │        └─ HMAC-SHA256 با wp_salt('auth')
                      └─ شناسهٔ تیکت
```

پشتیبان روی همان ایمیل «پاسخ» می‌زند، متنش به گفتگو اضافه می‌شود، وضعیت به «پاسخ داده شده»
می‌رود و مشتری هم ایمیل می‌گیرد. اگر خودِ مشتری به ایمیل جواب بدهد، پاسخش به‌عنوان پیام کاربر
در همان تیکت ثبت و مدیر مطلع می‌شود.

### وصل کردنش

| مسیر | کار لازم |
|---|---|
| فورواردر سی‌پنل / DirectAdmin | یک فورواردر روی آدرس کلید بسازید که به وب‌هوک `POST` بزند |
| Gmail / Outlook | با یک سرویس «Email → Webhook» (Zapier، Make، n8n) |
| اسکریپت خودتان | `curl -X POST …/wp-json/hsw/v1/ticket-inbound -d '{"secret":"…","to":"…","from":"…","text":"…"}'` |

آدرس وب‌هوک و کلیدش در **پشتیبانی** ← «پاسخ از داخل ایمیل» است و کلید در اولین بازدید
خودکار ساخته می‌شود.

**امنیت:** کلید با `hash_equals()` مقایسه می‌شود، امضای آدرس با `wp_salt('auth')` ساخته می‌شود
(بدون کلید وردپرس قابل جعل نیست)، فرستنده باید ایمیل پشتیبانی، مدیر فروشگاه یا خودِ مشتری باشد،
و سقف ۱۲۰ درخواست در ساعت به‌ازای هر IP دارد. عمداً به `ext-imap` وابسته نیست — روی بسیاری از
هاست‌ها نصب نیست و در PHP 8.4 منسوخ شده.

## رابط تیکت در پیشخوان

- **نشان وضعیت**: `.hsw-admin-badge` قبلاً هیچ CSS‌ای نداشت و متن خالی دیده می‌شد؛ حالا قرص رنگی
  با نقطهٔ وضعیت است (`is-success` / `is-warning` / `is-muted`).
- **گفتگو**: حباب‌های سفید برای مشتری و آبی روشن برای پشتیبان، با سرستون نویسنده و زمان.
- **نوار ابزار** بالای گفتگو: وضعیت، لینک سفارش مرتبط، و دکمهٔ بستن/بازگشایی.
- **فونت**: `admin_styles()` فونت لوکال را فقط روی صفحهٔ تنظیمات HamiShop و صفحات تیکت
  بارگذاری می‌کند. نکته: وردپرس برای فارسی `.locale-fa-ir body{font-family:Tahoma,…}` دارد که از
  یک قاعدهٔ سادهٔ `body` خاص‌تر است؛ بدون `!important` هیچ اتفاقی نمی‌افتد.

## نکات پیاده‌سازی

- **بدون رفرش**: تغییر گفتگو، ارسال پاسخ، بستن و ساخت تیکت همه با `admin-ajax` و HTML
  سمت سرور (`chat_thread_html()`)، پس مارک‌آپ یک منبع دارد و بین حالت اولیه و AJAX تفاوتی نیست.
- **بدون جاوااسکریپت هم کار می‌کند**: هر آیتم فهرست یک `<a href="?ticket=ID">` واقعی است و
  پاپ‌آپ یک `<form>` واقعی.
- **عکس**: `handle_image_upload()` با `media_handle_upload()` ذخیره می‌کند. نکتهٔ مهم:
  `wp_check_filetype_and_ext()` نقشهٔ `ext => mime` می‌خواهد (مثل `get_allowed_mime_types()`)،
  نه `mime => ext`؛ برعکس دادنش همهٔ آپلودها را رد می‌کند.
- **کپچا**: پاسخ در یک transient با کلید توکن نگه داشته می‌شود، نه در فرم. `HSW_Helpers::en_num()`
  ارقام فارسی/عربی را قبل از مقایسه به لاتین تبدیل می‌کند.
- **سبک**: بدون جدول جدید، بدون cron. متادیتای تیکت همان CPT موجود است و فقط دو متای
  `_hsw_ticket_order` و `_hsw_ticket_image` اضافه شده.

# مسیر خرید: سبد، تسویه، فاکتور (نسخه ۱.۱۱.۳۳)

## افزودن به سبد از آرشیو

دکمهٔ کارت‌های آرشیو `data-hsw-add` است و `hsw-archive.js` آن را مدیریت می‌کند. تا قبل از
۱.۱۱.۳۳ پاسخ AJAX خوانده نمی‌شد، پس محصول متغیر فقط یک تیک سبز نشان می‌داد و هیچ اتفاقی
نمی‌افتاد. حالا:

| پاسخ WooCommerce | رفتار |
|---|---|
| `{fragments, cart_hash}` | نوتیف + به‌روزرسانی نشان سبد از همان `fragments` |
| `{error:true, product_url}` | انتقال به صفحهٔ محصول (محصول متغیر / ناموجود) |
| خطای شبکه | نوتیف خطا و بازگشت دکمه به حالت عادی |

نشان سبد فقط با یکی از دو مسیر به‌روز می‌شود (`added_to_cart` با fragments، یا رویداد
`hsw_added_to_cart`) تا درخواست دوم لازم نشود.

## تعداد با کیبورد

فیلد تعداد دیگر `readonly` نیست. `hsw-cart.js` مقدار را با `toLatin()` از ارقام فارسی/عربی به
لاتین تبدیل، به `min`/`max` محدود و با Enter یا `change` فرم `update_cart` را submit می‌کند.
اگر مقدار عوض نشده باشد هیچ درخواستی فرستاده نمی‌شود.

## نوتیف‌های WooCommerce

`HSW_Helpers::wc_notices()` تنها جایی است که `wc_print_notices()` صدا زده می‌شود. این تابع
هم چاپ می‌کند و هم صف نشست را **پاک** می‌کند؛ نبودنش دو اثر داشت: کد تخفیف اشتباه هیچ
بازخوردی نمی‌داد، و هر «سبد خرید به‌روز شد» تا ابد در نشست می‌ماند و بعد یک‌جا در صفحهٔ
آدرس‌ها ظاهر می‌شد.

## آدرس در مرحلهٔ ارسال

اگر `customer_has_address()` منفی باشد، ویجت آدرس یک فرم درون‌خطی رندر می‌کند
(`address_form_html()`). ارسال با `POST /wp-json/hsw/v1/checkout/address` ذخیره می‌شود:

- هم `billing_*` و هم `shipping_*` نوشته می‌شود تا سفارش، دفترچه آدرس و مرحلهٔ پرداخت یکی باشند.
- `WC()->customer->save()` برای کاربر واردشده در user meta و برای مهمان در نشست ذخیره می‌کند.
- بعد از ذخیره `calculate_shipping()` و `calculate_totals()` صدا زده می‌شود چون استان/شهر
  نرخ ارسال را تعیین می‌کنند.
- صفحه دوباره بارگذاری می‌شود تا خلاصه و مرحلهٔ پرداخت آدرس تازه را ببینند.

## رنگ دکمه‌های CTA

دو توکن تازه در پالت: `cta` و `cta_hover` (پیش‌فرض `#0f2042` و `#1c3566`). سبد، تسویه و
پرداخت همه به `--hsw-cta` / `--hsw-cta-hover` اشاره می‌کنند و در `:hover` صریحاً
`color: var(--hsw-on-cta)` می‌گذارند — بدون آن، قاعدهٔ `a:hover` قالب رنگ متن را عوض می‌کرد
(روی یکی سیاه، روی دیگری سفید).

## فاکتور سفارش

`view_order_content()` جای قالب پیش‌فرض WooCommerce را می‌گیرد: لوگو و نام فروشگاه، شماره و
تاریخ، وضعیت، آدرس صورتحساب/تحویل، روش پرداخت و ارسال، جدول اقلام، جمع‌ها و دکمهٔ چاپ.

**چاپ فقط فاکتور:** در `@media print` از `:has()` استفاده شده:

```css
body *:not(:has(#hsw-invoice)):not(#hsw-invoice):not(#hsw-invoice *) { display: none !important; }
```

با `visibility: hidden` بقیهٔ جعبه‌ها فضایشان را نگه می‌دارند و فاکتور روی صفحهٔ دوم چاپ
می‌شود؛ `display: none` آن‌ها را جمع می‌کند و `:has()` فقط زنجیرهٔ والدهای فاکتور را زنده
نگه می‌دارد. مرورگرهای بدون `:has()` قاعده را نادیده می‌گیرند و صفحه را همان‌طور که هست چاپ
می‌کنند.

# کیف پول (نسخه ۱.۱۱.۳۴)

## چرا اینطور پیاده شده

| تصمیم | دلیل |
|---|---|
| موجودی در `_hsw_wallet_balance` | خواندن موجودی در هر صفحهٔ حساب و هر تسویه‌ای لازم است؛ `get_user_meta()` یک ردیف ایندکس‌شده و اغلب کش‌شده است، ولی `SUM(amount)` روی دفتر تراکنش‌ها با گذر زمان سنگین می‌شود. |
| افزایش با یک `UPDATE` | `UPDATE usermeta SET meta_value = meta_value + X` اتمیک است؛ خواندن-تغییر-نوشتن در PHP باعث می‌شود دو شارژ هم‌زمان یکی را گم کنند. |
| دفتر تراکنش جدا | فقط وقتی کسی صورت‌حساب را باز می‌کند خوانده می‌شود؛ ایندکس `(user_id, created_at)`. |
| شارژ با تایید ادمین | بدون درگاه، دکمهٔ «شارژ کن» یعنی پول مجانی. درخواست ثبت می‌شود و ادمین تایید می‌کند. |
| امتیاز قابل تبدیل = کسب‌شده − مصرف‌شده | امتیاز از مجموع خرید محاسبه می‌شود (مشتق است)، پس برای خرج‌کردن باید شمارندهٔ مصرف داشته باشیم. |

## جریان‌ها

```
مشتری: درخواست شارژ ──▶ ردیف pending ──▶ ادمین تایید ──▶ موجودی + ردیف done
مشتری: تبدیل امتیاز ──▶ _hsw_points_used += n ──▶ موجودی + ردیف points
ادمین: شارژ گروهی ──▶ به ازای هر کاربر: موجودی + ردیف admin ──▶ پیامک (اختیاری)
```

## پیامک

هیچ SDKای همراه نیست. قرارداد یکی است: `POST` به آدرس تنظیم‌شده با بدنهٔ
`{"phone","text","secret"}` و `blocking => false` (پاسخ انتظار نمی‌شود، پس صفحهٔ ادمین کند نمی‌شود).
هر پنل پیامکی یا پل بله (n8n/Make) که این قرارداد را بپذیرد کار می‌کند. برای پیاده‌سازی دلخواه:

```php
add_filter( 'hsw_wallet_sms', function ( $handled, $phone, $text ) {
    // ارسال با پنل خودتان؛ true برگردانید تا مسیر پیش‌فرض اجرا نشود.
    return my_sms_send( $phone, $text );
}, 10, 3 );
```

## مشتریان طلایی

یک کوئری روی `wc_order_stats` + `wc_customer_lookup` (نه `wc_get_customer_total_spent()` برای هر
کاربر که N کوئری می‌شود). اگر جدول آمار خالی باشد فهرست خالی برمی‌گردد و پیام راهنما نشان داده
می‌شود.

## نکتهٔ فیلد مبلغ در پیشخوان

`min="1" step="1000"` باعث می‌شد مرورگر هر مبلغ رُند (مثل ۵۰۰۰۰) را «مقدار نامعتبر» بداند و
فرم اصلاً ارسال نشود — `step` نسبت به `min` سنجیده می‌شود. حالا `min="1000" step="1000"` است.

# پاکسازی فرانت در پنل امنیت

سه گزینه، همه پیش‌فرض خاموش:

| گزینه | چه می‌کند | ریسک |
|---|---|---|

# سیستم استایل یکپارچه (نسخه ۱.۱۱.۳۵)

## مشکل قبلی

سه تابع `a_color` / `a_box` / `a_text` **دقیقاً یک‌بار در `HSW_Archive_Base` و یک‌بار در
`HSW_Cart_Base` کپی شده بودند** (۹۳ خط تکراری)، و کنترل «عرض ستون» در شش ویجت صفحه‌ای با
نسخه‌های کمی متفاوت تکرار شده بود. نتیجه: هر تغییر باید در چند جا اعمال می‌شد و بعضی ویجت‌ها
`%` نداشتند و بعضی `em/rem`.

## راه‌حل: `HSW_Style_Kit`

فایل `includes/trait-hsw-style-kit.php`، استفاده‌شده در `HSW_Widget_Base` — پس **همهٔ**
ویجت‌ها آن را دارند.

| متد | خروجی | واحدها |
|---|---|---|
| `style_typo_var( $id, $label, $var, $args )` | اندازهٔ فونت در یک CSS Variable | px / em / rem |
| `style_size_var( $id, $label, $var, $args )` | عرض/ارتفاع در یک CSS Variable | px / % |
| `style_color_var( $id, $label, $var )` | رنگ در یک CSS Variable | — |
| `style_columns( $prefix, $side, $args )` | عرض ستون کناری + فاصله | px / % |
| `style_typography_section( $prefix, $parts )` | یک بخش کامل «تایپوگرافی» | px / em / rem |

### قاعدهٔ طراحی

همه چیز روی `{{WRAPPER}}` به‌صورت custom property نوشته می‌شود، نه به‌صورت property واقعی:

```css
/* کنترل: {{WRAPPER}} → --hsw-cp-title-fs: 16px; */
.hsw-cp .hsw-csummary__title { font-size: var(--hsw-cp-title-fs, 1rem); }
```

سه فایده:
1. CSS تولیدشده کوتاه است (یک declaration به‌جای ده‌ها قاعده)،
2. سایت می‌تواند هر مقدار را از استایل‌شیت خودش override کند،
3. مقدار پیش‌فرض در fallback نوشته شده، پس **صفحه‌های موجود تغییر نمی‌کنند**.

### مهاجرت بدون شکستن

شناسهٔ کنترل‌ها عوض نشده (`cp_side`، `cp_gap`، `{id}_s`)، چون المنتور مقدارها را با نام کنترل
ذخیره می‌کند؛ تغییر نام یعنی ریست‌شدن همهٔ صفحه‌های ساخته‌شده.

| تغییر | سازگاری |
|---|---|
| `a_text` حالا px/em/rem می‌پذیرد | مقدار ذخیره‌شدهٔ px معتبر است |
| `cp_side` حالا `%` هم می‌پذیرد | مقدار px قبلی سر جایش است |
| `cp_cols` (صفحه محصول) حالا `px` هم می‌پذیرد | پیش‌فرض همان ۴۲٪ |
| ویجت حساب: `ac_side_unit` / `ac_max_unit` | خالی = px، مثل قبل |
| `a_color/a_box/a_text` به کلاس پایه منتقل شدند | امضای متد یکسان است |

## تایپوگرافی صفحه‌های خرید

`hsw-cart-page`، `hsw-checkout-page`، `hsw-pay-page` و `hsw-complete-page` یک بخش
**تایپوگرافی** دارند با چهار گروه: عنوان بخش‌ها، متن‌ها، قیمت‌ها، دکمه‌ها. متغیرها روی
wrapper می‌نشینند و به همهٔ ویجت‌های فرزند به ارث می‌رسند، پس یک‌جا تنظیم می‌شوند.

# سود شما از خرید (نسخه ۱.۱۱.۳۵)

`HSW_Helpers::savings()` دو منبع را جمع می‌زند:

```
سود = Σ (قیمت عادی − قیمت فروش) × تعداد  +  تخفیف کوپن
```

- **قیمت عادی** از `WC_Product::get_regular_price()` هر آیتم خوانده می‌شود؛ `get_subtotal()`
  نمی‌تواند «حراج» را از «محصول ارزان‌تر» تشخیص دهد.
- **کوپن** از `WC_Cart::get_discount_total()`.
- اگر حاصل صفر باشد، `savings_html()` رشتهٔ خالی برمی‌گرداند و ردیف **چاپ نمی‌شود**.

نمایش در سه جا: `hsw-cart-items` (دسکتاپ + موبایل)، `hsw-checkout-items`، `hsw-pay-summary`.
رنگ و اندازه با `--hsw-savings-color` / `--hsw-savings-fs` از تنظیمات همان ویجت.

# پیام‌های کوپن (نسخه ۱.۱۱.۳۵)

`HSW_Coupon_Messages` روی دو فیلتر رسمی ووکامرس می‌نشیند:
`woocommerce_coupon_error` و `woocommerce_coupon_message`.

- کد داخل پیام **همان چیزی است که کاربر تایپ کرده**، نه متن ثابت.
- نکتهٔ مهم: وقتی کد وجود ندارد، ووکامرس بسته به محتوای سبد کد خطای ۱۰۵ («برای کالاهای این سبد
  معتبر نیست») را می‌فرستد، نه ۱۰۰. برای همین وجود کد با `$coupon->get_id()` سنجیده می‌شود و
  پیام «وجود ندارد» اولویت می‌گیرد.
- برای پیاده‌سازی دلخواه: فیلترهای `hsw_coupon_error_message` و `hsw_coupon_success_message`.

# بازخورد افزودن به سبد: توست + مودال (نسخه ۱.۱۱.۳۵)

`assets/js/hsw-feedback.js` تنها منبع نمایش بازخورد است (`window.HSWFeedback`).

```
HSWFeedback.toast( متن, { tone: 'error' } )        پیام کوتاه، وسط صفحه، بستن خودکار
HSWFeedback.modal({ title, html, actions })        پنجرهٔ سبد
HSWFeedback.addedToCart({ fragments, labels })     یکی از دو مورد بالا، هرگز هر دو
```

| ویژگی | توست | مودال |
|---|---|---|
| وسط صفحه | ✓ | ✓ |
| بستن خودکار | ۴ ثانیه | — |
| دکمهٔ بستن | ✓ | ✓ |
| `Esc` | ✓ | ✓ |
| کلیک بیرون | ✓ | ✓ (backdrop) |
| قفل اسکرول | ✗ | ✓ |
| ARIA | `role=status` + `aria-live=polite` | `role=dialog` + `aria-modal=true` |

**بارگذاری شرطی:** `hsw-feedback` فقط وابستهٔ `hsw-archive` / `hsw-loop` / `hsw-product` است،
پس در صفحه‌ای که این سه خانواده نیستند دانلود نمی‌شود (بدون jQuery، ۵KB).

مودال محتوای **fragment مینی‌کارت ووکامرس** را نشان می‌دهد، پس تصویر، نام، تعداد و جمع سبد
بدون هیچ پارس‌کردن دستی و بدون درخواست اضافه درست است.

# تایپوگرافی مجله، مقاله و کارت آرشیو (نسخه ۱.۱۱.۳۶)

بخش ۱ درخواست («سیستم استایل مشترک برای همهٔ ویجت‌ها، اصلی و ریز») تا ۱.۱۱.۳۵ فقط
خانوادهٔ سبد/تسویه/پرداخت و آرشیو را پوشش می‌داد. مجله، صفحهٔ مقاله و کارت‌های آرشیو
اندازه‌هایشان را در CSS ثابت داشتند.

## الگوی مشترک

هر ویجت یک بخش «تایپوگرافی» با `style_typography_section()` می‌گیرد و CSS همان متغیر را
می‌خواند:

```php
$this->style_typography_section( 'bhero', array(
    'title' => array( __( 'عنوان اصلی' ), 26 ),
    'stat'  => array( __( 'اعداد آمار' ), 22 ),
    'hot'   => array( __( 'برچسب‌های داغ' ), 12 ),
) );
```

```css
.hsw-bhero__title { font-size: var(--hsw-bhero-title-fs, 26px); }
```

**مقدار پیش‌فرض کنترل = همان اندازهٔ فعلی طرح**، پس با فعال‌شدن کنترل‌ها هیچ صفحه‌ای
تغییر نمی‌کند (تست: ۲۴ سلکتور در دو عرض، اختلاف صفر).

## اندازه‌های کوچک‌تر نسبتی‌اند، نه ثابت

قبلاً موبایل با یک عدد ثابت override می‌شد (`font-size: 21px`). اگر کاربر عنوان دسکتاپ را
۴۰px کند، آن قاعده موبایل را روی ۲۱ قفل می‌کرد. حالا نسبت است:

```css
@media (max-width: 767.98px) {
    .hsw-bhero__title { font-size: calc(var(--hsw-bhero-title-fs, 26px) * .81); }
}
```

عنوان مقاله هم همین‌طور: کنترل **سقف** اندازه را می‌دهد و کف سیال می‌ماند —

```css
font-size: clamp(calc(var(--hsw-pp-title-fs, 32px) * .66), 5.6vw, var(--hsw-pp-title-fs, 32px));
```

## ۱) فونت آیکون حذف شد

# کیف پول: پرداخت و شارژ (نسخه ۱.۱۱.۳۸)

## پرداخت با کیف پول

`HSW_Wallet_Gateway` یک درگاه ووکامرس معمولی است (`id = hsw_wallet`)، پس در همان جایی
ظاهر می‌شود که بقیهٔ درگاه‌ها: مرحلهٔ پرداخت، سفارش‌های «پرداخت مجدد»، و هر جایی که
`get_available_payment_gateways()` صدا زده شود.

```
is_available():  کاربر وارد شده + موجودی > ۰ + (سفارش بی‌مبلغ یا موجودی ≥ مبلغ)
process_payment(): HSW_Wallet::debit() → order note → payment_complete() → empty_cart()
```

دو نکته که در عمل به آن‌ها خوردیم:

1. **کلاس باید بعد از `WC_Payment_Gateway` تعریف شود.** قلاب `woocommerce_loaded` تنها کافی
   نبود، چون ووکامرس آن را قبل از رسیدن افزونه‌های `plugins_loaded` اجرا می‌کند. حالا اگر
   `did_action('woocommerce_loaded')` درست باشد، همان لحظه ثبت می‌شود.
2. **`WC()->cart` در REST خالی است**، پس `get_total()` صفر برمی‌گرداند و درگاه «نامعتبر»
   تلقی می‌شد. `is_available()` حالا بدون مبلغ هم اجازه می‌دهد و `process_payment()` مبلغ
   واقعی سفارش را دوباره بررسی می‌کند.
3. **`credit()` مبلغ منفی را عمداً نادیده می‌گیرد** (تا یک اشتباه حساب را خالی نکند)، برای
   همین برداشت از `debit()` استفاده می‌کند که در صورت کمبود موجودی `WP_Error` می‌دهد.

## شارژ کیف پول

| روش | جریان |
|---|---|
| **درگاه** | مبلغ → `POST /hsw/v1/account/wallet/pay` → سفارش با یک ردیف هزینه → `order-pay` → درگاه → `woocommerce_payment_complete` → شارژ خودکار |
| **کارت به کارت** | شمارهٔ کارت روی صفحه → ثبت شمارهٔ پیگیری (درخواست `pending`) → تایید در **HamiShop ← کیف پول** |

سفارش شارژ یک **ردیف هزینه** است، نه محصول مخفی: نه موجودی دارد، نه در کاتالوگ دیده می‌شود،
و مبلغش دقیقاً همان چیزی است که مشتری وارد کرده. شارژ در `woocommerce_payment_complete`
انجام می‌شود و با متای `_hsw_wallet_topup_credited` از شارژ دوباره محافظت می‌شود (این قلاب
می‌تواند چند بار اجرا شود).

**انتخاب درگاه** از خود ووکامرس خوانده می‌شود (`HSW_Wallet_Topup::gateways()`)، پس هر
افزونه‌ای که فعال باشد — آقای پرداخت، زیبال، زرین‌پال — بدون کد اضافه در فهرست می‌آید.
تنظیمات در **HamiShop ← حساب کاربری ← کیف پول**: روش شارژ، درگاه، و اطلاعات کارت.

# فاکتور، آدرس، ارسال رایگان و بازخورد سبد (نسخه ۱.۱۱.۳۹)

## فاکتور

ساختار از نمونهٔ ارسالی گرفته شده و روی یک صفحهٔ A4 جا می‌شود (تست: ۸ قلم، یک صفحه):

```
عنوان + شماره/تاریخ/شماره سفارش        لوگو + نام فروشگاه
──────────────────────────────────────────────────────────
کادر خریدار            │ کادر فروشنده
─────────────────────────────────────────────────────────
جدول اقلام (ردیف، شرح، تعداد، بهای واحد، مبلغ کل)
─────────────────────────────────────────────────────────
جمع‌ها            │ کادر خط‌چین: مبلغ + مبلغ به حروف
روش پرداخت / وضعیت
امضای خریدار                       مهر
پانویس + آدرس فاکتور + ۱/۱
```

- رنگ‌ها از پالت می‌آیند (`--hsw-primary` / `--hsw-accent`)، پس فاکتور با هویت فروشگاه چاپ
  می‌شود، نه با یک سرمه‌ای ثابت.
- مبلغ به حروف با `HSW_Helpers::number_words()` (تا هزار میلیارد).
- فاصله‌ها عمداً جمع‌اند: هر ردیف ۵px، کادرها ۱۰px — همان چیزی که باعث می‌شود ۸ قلم در یک
  صفحه بماند.

## آدرس در حساب کاربری

`WC_Checkout::create_order()` آدرس را فقط روی سفارش می‌نویسد. `persist_customer_address()`
بعد از ثبت سفارش، فیلدهای غیرخالی را روی `WC_Customer` می‌گذارد و ذخیره می‌کند؛ اگر آدرس
تحویل خالی باشد، آدرس صورتحساب کپی می‌شود (رفتار «ارسال به همان آدرس»). صفحهٔ آدرس‌ها هم اگر
آدرس تحویل نبود، صورتحساب را با برچسب «تحویل به همان آدرس صورتحساب» نشان می‌دهد.

## ارسال رایگان

`HSW_Free_Shipping` روی `woocommerce_package_rates` (اولویت ۲۰) می‌نشیند: اگر جمع اقلام از
سقف تنظیم‌شده بیشتر باشد، هزینهٔ همهٔ نرخ‌های آن بسته صفر و برچسب «ارسال رایگان» می‌شود.
مبلغ از `get_displayed_subtotal()` خوانده می‌شود تا با عددی که مشتری می‌بیند یکی باشد.
تنظیم: **HamiShop ← کنترل ویجت‌ها ← ارسال رایگان** (۰ = خاموش).

## بازخورد افزودن به سبد

دو حالت، یکی از آن‌ها فعال:

| حالت | ظاهر |
|---|---|
| **مودال** | پنجرهٔ شیشه‌ای ۳۵۲px با `backdrop-filter: blur(18px)`, پس‌زمینهٔ ۷۸٪ سفید، محتوای مینی‌کارت |
| **نوار تک‌خطی** | یک خط بالای صفحه: «نام محصول — به سبد خرید اضافه شد»، لینک «مشاهده سبد خرید»، نوار سبز ۵ ثانیه‌ای |

نوار سبز هم زمان‌سنج است هم نشانگر پیشرفت (`@keyframes` روی `scaleX`). بدون blur هم خوانا
می‌ماند (`@supports not`).

## علاقه‌مندی

- افزودن/حذف از آرشیو یک خط کوتاه نشان می‌دهد (`hsw-toast--thin`).
- دکمهٔ حذف در پیشخوان آیکون نداشت: `.hsw-ac :where(img, svg) { max-width:100% }` که برای
  عکس محصول نوشته شده بود، عرض SVG آیکون را صفر می‌کرد. حالا `.hsw-ac .hsw-ac-ic` صریحاً
  `width: 1em; max-width: none` دارد.

# شمارندهٔ خرید موبایل و font-display (نسخه ۱.۱۱.۴۰)

## نوار خرید پایین صفحهٔ محصول

روی موبایل، ویجت خرید معمولاً پنهان است و نوار چسبان پایین صفحه کار می‌کند. این نوار
به‌هم ریخته بود: قالب سایت `input[type="text"] { width: 100% }` دارد و همان قاعده فیلد
تعداد را تا ۳۱۰px کشیده بود، پس دکمهٔ «خرید آنلاین» به یک نوار ۱۶ پیکسلی تبدیل می‌شد.

```css
/* دو کلاس + basis صریح: تک‌کلاسی در برابر قاعدهٔ قالب می‌بازد */
.hsw-psticky .hsw-psticky__qval { width: 2rem; flex: 0 0 2rem; border: 0 !important; }
.hsw-psticky__stepper { flex: 0 0 auto; gap: 2px; }
```

### شمارنده: ۱ = سطل، ۲+ = منفی

```
تعداد ۱ :  [+]  ۱  [🗑]   خرید آنلاین
تعداد ۲ :  [+]  ۲  [−]   خرید آنلاین
```

- هر دو دکمه در مارک‌آپ هستند؛ کلاس `is-min` روی `.hsw-psticky__stepper` تعیین می‌کند کدام
  دیده شود (`display:none` روی منفی، `display:flex` روی سطل).
- `setQty()` این کلاس را با هر تغییر عدد به‌روز می‌کند و بار اول هم روی DOMContentLoaded
  ست می‌شود.
- سطل، آدرس حذف همان آیتم از سبد را دارد (`wc_get_cart_remove_url`)؛ اگر محصول در سبد نباشد
  `disabled` است.
- همین رفتار در `.hsw-ppurch__stepper` هم هست، اما فقط داخل `@media (max-width: 767.98px)` —
  روی دسکتاپ همان «منفی غیرفعال در ۱» می‌ماند.

## font-display: swap

در **پیشخوان امنیت ← بهینه‌سازی و پاکسازی فرانت** یک تیک اضافه شد. وقتی روشن باشد:

- داخل همهٔ بلوک‌های `<style>` صفحه، `font-display: auto|block|fallback` → `swap` می‌شود.
- آدرس‌های `fonts.googleapis.com` اگر `display=` داشته باشند به `swap` تغییر می‌کنند و اگر
  نداشته باشند `&display=swap` اضافه می‌شود.

روش: `ob_start()` روی `template_redirect` و بازنویسی در خروجی نهایی؛ فقط `<style>`ها لمس
می‌شوند و به فایل‌های CSS خارجی دست نمی‌زنیم (برای آن‌ها بدون fetch کردن فایل راهی نیست).
در پیشخوان، AJAX، فید و ویرایشگر المنتور اجرا نمی‌شود.

فونت خود افزونه از قبل `swap` است، پس این گزینه برای فونت‌های قالب و افزونه‌های دیگر است.

# کارت آرشیو و رنگ‌های هدر (نسخه ۱.۱۱.۴۱)

## خطای `is_in_stock()` روی null

`card()` دو شاخه دارد: دمو (پیش‌نمایش المنتور) و محصول واقعی. متغیر `$product` فقط در شاخهٔ
دوم ساخته می‌شد، ولی خط `$is_oos = ! $product->is_in_stock();` بیرون از آن بود — یعنی در
حالت دمو روی null صدا زده می‌شد. حالا:

```php
$product = null;                                   // بالای تابع
$is_oos  = ( $product instanceof WC_Product ) && ! $product->is_in_stock();
```

## تصویر دوم در هاور

اگر محصول عکس گالری داشته باشد، اولین عکس گالری به‌صورت لایهٔ دوم روی کارت می‌آید:

```css
.hsw-ag__media img.hsw-ag__img2 { opacity: 0; transform: scale(1.04); transition: opacity .35s, transform .45s; }
@media (hover: hover) and (pointer: fine) {
  .hsw-ag__card:hover .hsw-ag__media img.hsw-ag__img2 { opacity: 1; transform: scale(1.1); }
}
```

- فقط وقتی عکس دوم **وجود دارد** رندر می‌شود؛ کارت تک‌عکسی همان یک `<img>` را دارد.
- `@media (hover: hover)` جلوی گیر کردن حالت هاور بعد از لمس در موبایل را می‌گیرد.
- تصویر دوم `alt=""` و `aria-hidden` است تا خوانندهٔ صفحه آن را دوباره نخواند.

## نشان «ناموجود»

قبلاً `inset-inline-start: 50%` + `translateX(-50%)` بود. در RTL لبهٔ inline-start سمت
**راست** است، پس همان translate منفی، نشان را از مرکز بیرون می‌برد (روی موبایل کاملاً از کارت
بیرون می‌زد). حالا با `inset: 0; margin: auto; width: max-content` در هر دو جهت وسط است و
در گوشی به‌جای `nowrap` می‌شکند.

## ترتیب محصولات ناموجود

این رفتار از قبل وجود داشت ولی جای تنظیم نداشت: `HSW_Archive_Query` با یک `LEFT JOIN` روی
`_stock_status` و یک `CASE` در ابتدای `ORDER BY`، ناموجودها را به انتهای فهرست می‌برد
(بدون دست‌زدن به ترتیب قیمت/تاریخ/تخفیف). حالا در
**HamiShop ← کنترل ویجت‌ها ← ترتیب محصولات** یک تیک دارد (پیش‌فرض روشن) که روی گزینهٔ
`hsw_oos_last` می‌نشیند؛ فیلتر `hsw_archive_oos_last` هم برای توسعه‌دهنده باقی است.

## رنگ دکمه‌ها و آیکن‌های هدر

بله، از **HamiShop ← پالت رنگی** قابل تغییر است — و حالا واقعاً یکپارچه:

| حالت | توکن پالت |
|---|---|
| عادی | رنگ اصلی (`--hsw-primary`) |
| هاور | رنگ هاور (`--hsw-hover`) |
| اکتیو | رنگ اصلی تیره (`--hsw-primary-dark`) |

قبلاً هاور با `color-mix(primary, #000 10%)` ساخته می‌شد؛ یعنی اگر رنگ اصلی را عوض می‌کردید،
هاور یک آبی کمی متفاوت می‌ماند. حالا آیکن‌ها، دکمهٔ حساب، سبد، دسته‌بندی، منو و CTA هدر همه
از همان سه توکن می‌خوانند (با fallback به رفتار قبلی برای پالت‌های قدیمی).

## رنگ‌ها: یک منبع واحد

از نسخهٔ **۱.۱۱.۱۵۱** بخش «پالت رنگ ویجت» از تب Style همهٔ ویجت‌های HamiShop حذف شد.
رنگ‌های عمومی (برند، تاکید، پس‌زمینه، کارت، متن، حاشیه و وضعیت‌ها) فقط از
**HamiShop ← پالت رنگی** خوانده می‌شوند و روی `html:root` چاپ می‌شوند.

کنترل‌های رنگی عنصربه‌عنصر — مثل بج تخفیف/ویژه، دکمهٔ خرید، ردیف سبد یا کارت مقاله —
هنوز در تب Style همان ویجت هستند و روی wrapper ویجت اعمال می‌شوند؛ بنابراین برای
سفارشی‌سازی نقطه‌ای باقی مانده‌اند، ولی پالت اختصاصی ویجت دیگر وجود ندارد.

مقادیر `pal_*` که در قالب‌های قدیمی ذخیره شده‌اند حذف نمی‌شوند؛ فقط دیگر CSS تولید
نمی‌کنند. هنگام به‌روزرسانی، کش CSS المنتور یک‌بار پاک می‌شود تا اوررایدهای قدیمی
از فایل‌های CSS قبلی هم حذف شوند و رنگ پالت پیشخوان اعمال شود.

## تازه‌های نسخه‌های ۱.۱۱.۵۱ تا ۱.۱۱.۶۹

- **صفحهٔ محصول:** تب‌های یکسان دسکتاپ/موبایل با تب «گارانتی و خدمات» و اسکرول افقی با نشانگر نازک؛ کاروسل و فیدهای RTL با `left/right` فیزیکی؛ لایت‌باکس با SVG و بستن با کلیک بیرون.
- **خرید موبایل:** دکمهٔ خرید به استپر `🗑 ۱ +` تبدیل می‌شود و شیت پایین‌کش «کالا اضافه شد» با لیست کالاهای مشابه باز می‌شود؛ نوار خرید بالای شیت می‌ماند.
- **صفحه‌بندی:** نوار قرصی با نشانگر لغزنده برای همهٔ حلقه‌های محصول (فروشگاه، دسته، آرشیو).
- **پیشخوان:** صفحهٔ «پالت رنگی» با پیش‌نمایش زنده، صفحهٔ «برند و لوگو» با کارت «تنظیمات نام حامی»، و صفحهٔ «امنیت» با حذف لوگوی وردپرس، قفل درخواست‌های خارجی و صفحهٔ ورود سفارشی.
- **آیکون‌ها:** مجموعهٔ Iconsax محلی (کاربر، قلب، کیف پول، فروشگاه، تنظیمات، سبد) داخل همان اسپرایت درون‌صفحه‌ای.
- **صفحهٔ ۴۰۴:** فونت وزیرمتن + متن‌های قابل ویرایش در «کنترل ویجت‌ها».

## ویجت فوتر چسبان (۱.۱۱.۷۳+)

نوار ثابت پایین صفحه برای موبایل با پنج لینک پیش‌فرض: خانه، فروشگاه، سبد خرید،
علاقه‌مندی‌ها، حساب کاربری — همه با آیکون‌های خود افزونه.
- `z-index: 9000` (زیر شیت خرید ۹۹۹۰ و نوار خرید محصول ۹۹۹۵) → بدون تداخل.
- در دسکتاپ (≥۱۰۲۴px) مخفی است و `body:has(.hsw-sf)` فاصلهٔ پایین را جبران می‌کند.
- کنترل‌ها: عنوان اختیاری، ریپیتر (متن/آدرس/آیکن/تب جدید/nofollow)، جای آیکن،
  تراز و فاصله‌های واکنش‌گرا، رنگ‌ها، حالت شیشه‌ای با رنگ انتخابی، پس‌زمینه/حاشیه/سایه.

## فونت پیش‌فرض همهٔ ویجت‌ها

در «پالت رنگی» یک انتخابگر فونت اضافه شده: فونت‌های بارگذاری‌شدهٔ قالب (font
library وردپرس) + وزیرمتن افزونه + فیلتر `hsw_font_choices`. مقدار انتخابی روی
`html:root` به‌صورت `--hsw-font` چاپ و در همهٔ ویجت‌ها اعمال می‌شود؛ کنترل فونت
هر ویجت اولویت دارد.

## هدر: چیدمان و فاصلهٔ آیکن‌ها

در تب Style هدر: «چیدمان افقی هدر» (راست/وسط/چپ) و زیرش **«فاصلهٔ آیکن‌ها /
اکشن‌ها»** — هر دو واکنش‌گرا (موبایل/تبلت/دسکتاپ).

## معماری افزونه (برای متخصص وردپرس/المنتور)

### چرخهٔ بارگذاری
1. `hamishop-elementor-widgets.php` → `HSW_Plugin::init()` فایلهای `includes/` را لود میکند.
2. `HSW_Assets` استایل/اسکریپتها را فقط **register** میکند (بدون enqueue سراسری):
   `hsw-fonts` → پایهٔ مشترک، سپس `hsw-header`, `hsw-product`, `hsw-cart`,
   `hsw-checkout`, `hsw-account`, `hsw-loop`, `hsw-archive`, `hsw-post`.
3. هر ویجت با `get_style_depends()` / `get_script_depends()` فقط وابستگی خودش را
   enqueue میکند؛ یعنی صفحهٔ محصول `hsw-cart.css` را نمیگیرد و برعکس.
4. `tools/build-assets.py` نسخهٔ `.min.*` را میسازد؛ اگر `SCRIPT_DEBUG` خاموش باشد
   همان فایل مینیفای سرو میشود (۲۶–۳۸٪ کوچکتر).

### سیستم رنگ (سه لایه)
```
پالت پیشخوان  →  html:root { --hsw-cta, --hsw-woo-btn-bg, --hsw-btn-bg, --hsw-font … }
   ↓
متغیر کامپوننت  →  .hsw-c { --hswc-cta: var(--hsw-cta); }
   ↓
ویجت/دکمه       →  .hsw-csummary__cta { background: var(--hsw-cs-cta-bg, var(--hswc-cta)); }
```
- لایهٔ ۱ همیشه مقدار دارد (پیشفرضها)، پس بدون تنظیم ویجت هم همهچیز رنگ دارد.
- لایهٔ ۳ با فالبک نوشته شده؛ اگر متغیر اختصاصی تنظیم شود همان برنده است.
- خانوادهٔ دکمهها: `--hsw-cta-*` (مسیر خرید)، `--hsw-woo-btn-*` (بقیهٔ دکمههای
  ووکامرس)، `--hsw-btn-*` (دکمههای ثانویه).

### آیکونها
- یک اسپرایت SVG **درونصفحهای** (`print_sprite`) که فقط آیکونهای همان درخواست
  را چاپ میکند؛ صفر درخواست شبکه.
- آیکونهای Iconsax (خطی، ۲۴×۲۴، `stroke="currentColor"`) در
  `includes/class-hsw-icon-raw.php`؛ بقیه از جدول مسیر Material.
- پنل حساب نقشهٔ آیکون مستقل دارد (`HSW_Account::icon()`).

### صفحههای پیشخوان
`پالت رنگی` (توکنها + فونت)، `برند و لوگو` (نام/لوگو/شعار)، `امنیت` (حذف لوگوی
وردپرس، قفل درخواست خارجی، صفحهٔ ورود سفارشی)، `کنترل ویجتها` (روشن/خاموش کردن
هر ویجت؛ فهرست از `HSW_Widget_Manager::$catalog_cache`).

### محدودیت شناختهشده
در ویجتهای «صفحهٔ کامل …» المنتور کنترلهایی که `selectors` دارند را در
`register_controls()` بیصدا حذف میکند (کنترل بدون selectors ثبت میشود).
به همین دلیل رنگ دکمهها فعلاً از **پالت** تنظیم میشود، نه از تب Style ویجت.
