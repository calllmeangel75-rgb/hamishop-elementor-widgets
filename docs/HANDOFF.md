## ۱. این پروژه چیست

`HamiShop Elementor Widgets` — یک بستهٔ ویجت المنتور برای فروشگاه‌های ووکامرس فارسی‌زبان. شامل آرشیو محصول، سه هدر/فوتر سفارشی، سبد و تسویه، پنل حساب، کیف پول، تیکت پشتیبانی، بلاگ و صفحهٔ نوشته.

```
مسیر مخزن   : D:\work-webs\0 Build\hamishop-repo
مخزن        : github.com/calllmeangel75-rgb/hamishop-elementor-widgets
نسخهٔ فعلی  : 1.11.247
فایل اصلی   : hamishop-elementor-widgets.php  (هدر نسخه + HSW_VERSION)
تست لوکال   : http://localhost/sks/   (XAMPP، افزونه در wp-content/plugins/hamishop-elementor-widgets)
سایت‌های زنده: gilaclick.ir · new.mrdastbaaf.com
```

**قبل از شروع بخوان:** `docs/DEVELOPMENT.md` (فرآیند ریلیز) · `docs/ARCHITECTURE.md` · `docs/PERFORMANCE.md`

## ۲. قواعد ثابت — این‌ها قابل مذاکره نیستند

### R1 — کارایی یک ویژگی است، نه یک عدد

- روی مسیر فرانت‌اند **هیچ کوئری تازه‌ای** اضافه نکن. هر چیزی که هر درخواست محاسبه می‌شود باید کش شود (object cache + transient) و **قلاب ابطال** داشته باشد.
- هر `update_option` که خودت می‌نویسی: پارامتر سوم `false` (autoload خاموش)، مگر اینکه در هر درخواست خوانده شود.
- ممنوع در مسیر داغ: `posts_per_page => -1` · `get_comments( count )` داخل حلقه · `meta_query` روی مقدار بدون ایندکس · `wc_get_orders( limit => -1 )` بدون کش.
- **Lighthouse 100 هدف است، نه قانون.** هرگز صحت را فدای نمره نکن. همیشه بگو چه چیزی سهم ما بود و چه چیزی سهم قالب/LiteSpeed.

### R2 — WP-Cron کارگر پس‌زمینه نیست

WP-Cron با **بازدید فرانت** اجرا می‌شود. کار سنگین روی آن، worker را می‌گیرد و سایت ۵۰۳ می‌دهد (این دقیقاً اتفاق ۱.۱۱.۲۳۲ بود). کار طولانی: تیک فقط از پیشخوان، با بودجهٔ زمانی، یا کلید `HSW_UPGRADER_OFF`.

### R3 — قرارداد استایل

ترتیب اولویت، همیشه:

```
کنترل صریح همان عنصر در المنتور  >  تنظیم ویجت  >  پالت سراسری (--hsw-*)  >  پیش‌فرض افزونه
```

- فونت یا رنگی که پالت مالکش است را hard-code نکن. الگو: `var(--hsw-font, 'Vazirmatn HSW')`.
- `!important` فقط جایی که باید یک قاعدهٔ بیرونی شکسته شود، و همیشه با کامنت که «کدام قاعده».
- گرید با محتوای متنی: `minmax(0, 1fr)`، هرگز `1fr` خالی.
- **هر گزینهٔ ظاهری جدید باید در حالت پیش‌فرض بی‌اثر باشد** — همان HTML/CSS قبلی.

### R4 — یکپارچگی با المنتور

- شناسهٔ هیچ کنترلی را عوض یا حذف نکن؛ صفحات ذخیره‌شده به آن وابسته‌اند.
- ویجت مستقل و همان بخش داخل ویجت جامع باید **یکسان** رندر شوند.
- تنظیمات را از `effective_settings()` بخوان، نه `get_settings()`.

### R5 — امنیت روی هر چیزی که شناسه می‌گیرد

- `post_status` + `current_user_can( 'edit_post', $id )` را چک کن. فیلد عددی آزاد یعنی کاربر می‌تواند پیش‌نویس را نام ببرد.
- `post_password_required()` را رعایت کن. اگر بدنه را از `$post->post_content` می‌خوانی، `get_the_content()` اجرا نمی‌شود و هسته فرصت نمی‌کند فرم رمز را جایگزین کند.
- خروجی: `esc_html` / `esc_attr` / `esc_url`. بدون استثنا.

### R6 — ریاضیات پول بدون تست استیجینگ دست نمی‌خورد

کیف پول، امتیاز، جمع سفارش. اگر SQL را بازنویسی می‌کنی، اول خروجی قدیم و جدید را روی یک سبد واقعی مقایسه کن.

### R7 — اول باگ را ثابت کن، بعد رفع

- کد قدیم و جدید را کنار هم اجرا کن و **عدد قبل/بعد** بده. رفع بدون «قبل» یعنی حدس.
- برای CSS: `getComputedStyle` و `scrollWidth` را بخوان، نه متن استایل‌شیت.
- برای پیدا کردن سرریز افقی: اجزا را یکی‌یکی حذف کن و هر بار اندازه بگیر.

### R8 — خروجی پیش‌فرض باید بایت‌به‌بایت یکسان بماند

بعد از هر تغییر ظاهری، HTML دو-سه صفحه را قبل و بعد بگیر و diff کن. nonce، `?ver=` و timestamp کش را نرمال کن. هر تفاوت دیگری = رگرسیون.

### R9 — نظم ریلیز

چک‌لیست `docs/DEVELOPMENT.md` اجباری است. مرحله‌ای که همه جا می‌افتد:

```
python tools/build-pot.py
```

هر تغییر PHP که شماره خط فایل‌های ترجمه‌دار را جابه‌جا کند، POT را کهنه می‌کند و CI با «generated files in sync» قرمز می‌شود.

`main` و tag باید یک کامیت باشند؛ sha256 فایل ZIP باید با digest دارایی Release یکی باشد.

### R10 — تاریخ را بازنویسی نکن

`--amend` و force-push ممنوع. پیام کامیت غلط، ارزان‌تر از تاریخ بازنویسی‌شده است.

### R11 — مسیرها روی ویندوز

PHP اینجا باینری ویندوزی است: `/tmp/...` **بی‌صدا** شکست می‌خورد. از `sys_get_temp_dir()` یا `C:/...` استفاده کن، و همیشه بعد از نوشتن مقدار را بازخوانی کن و طولش را چک کن. (یک بار همین باعث پاک‌شدن `_elementor_data` سه صفحهٔ لوکال شد.)

### R12 — چیزی که کاربر نخواسته را عوض نکن

تغییر قابل مشاهده (متن، چیدمان، فونت) نیاز به تأیید صریح دارد. مواردی که عمداً انجام نمی‌شوند، با دلیل در یادداشت انتشار می‌آیند.

## ۴. کارهای باز (عمداً انجام نشده)

| مورد | چرا |
|---|---|
| عدد کنار دکمهٔ قلب | عدد = تعداد دیدگاه + `localStorage`. جابه‌جایی ظاهر نوار موبایل را عوض می‌کند؛ نیاز به تصمیم کاربر |
| قبلی/بعدی با «شناسهٔ دستی» | `get_previous_post()` به `$post` سراسری وابسته است |
| بردکرامب سلسله‌مراتبی | افزودنی است، نه باگ |
| نوار پایین + فوتر چسبان | روی سایت کاربر هم‌زمان فعال نبود؛ نیاز به تست چشمی |
| جدول عریض / بردکرامب در عرض کم | نیاز به تست با محتوای واقعی |
| `wallet_topup_spent()` با SQL مستقیم | عدد مالی؛ نیاز به تست HPOS + legacy روی استیجینگ |
| مرتب‌سازی «پربازدیدترین» با معیار بازدید | کوئری سنگین‌تر می‌خواهد؛ فعلاً عنوان به «پربحث‌ترین» تغییر کرد |

## ۵. نحوهٔ کار با این کاربر

- خسته است و از تغییرات ناگهانی آسیب دیده. **قبل از ریلیز، اثبات بیاور.**
- اگر چیزی را نمی‌دانی، حدس نزن — اندازه بگیر. حدس اشتباه اینجا هزینهٔ واقعی دارد.
- وقتی چیزی را خودت خراب کردی، همان‌جا بگو و درست کن؛ توضیح اضافه لازم نیست.
- فارسی جواب بده. کد و کامیت انگلیسی.
