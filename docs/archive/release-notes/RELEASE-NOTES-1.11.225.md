# یادداشت‌های انتشار نگارش 1.11.225 (Release Notes v1.11.225)

> **موضوع:** منوی هدر سطح سوم را حذف نمی‌کند.

## ۱. مشکل

در منوی هدر، آیتم «لوازم و ابزار قالی‌بافی» باز می‌شد و «ابزار قالی‌بافی و پرداخت فرش» را نشان می‌داد — ولی زیرمجموعه‌های همان آیتم هیچ‌وقت ظاهر نمی‌شدند.

## ۲. علت

در `HSW_Header_Base::menu_html()` فراخوانی `wp_nav_menu()` با این آرگومان انجام می‌شد:

```php
'depth' => 2,
```

`depth = 2` یعنی «فقط دو سطح»: خود آیتم و یک سطح زیرمجموعه. هر آیتمی که خودش فرزند داشت، در سطح سوم **بی‌صدا حذف می‌شد**. هیچ خطا و هیچ پیامی هم نبود — برای همین در پنل المنتور هم چیزی دیده نمی‌شد که توضیح بدهد چرا.

## ۳. راه‌حل

- `depth` به `0` تغییر کرد: تمام سطوح رندر می‌شوند، هرچقدر عمیق باشند.
- CSS جدید برای زیرمنوی تودرتو: به‌جای اینکه زیر آیتم قبلی بیفتد (و روی لیست خودش قرار بگیرد)، **کنار** آیتم باز می‌شود — در RTL به سمت چپ، در LTR به سمت راست.
- فلش آیتم‌های دارای فرزند، به سمتی اشاره می‌کند که زیرمنو باز می‌شود (`:dir(rtl)` برای جهت).
- آیتم والد تا وقتی زیرمنویش باز است هایلایت می‌ماند.
- منوی کشوی موبایل هم بدون تغییر کار می‌کند (زیرمنوها در کشو به‌صورت لیست تودرتو با تورفتگی نمایش داده می‌شوند).

## ۴. تأیید

با Chrome headless و CSS واقعی ساخته‌شده (نه سورس) روی یک منوی سه‌سطحی:

```
third level visibility (closed) = hidden
third level visibility (open, after transition) = visible
parent rect = 986..1192 / y 117
child  rect = 764..982  / y 116
child opens to the LEFT of parent (RTL) = yes
child top within parent height          = yes
```

یعنی سطح سوم باز می‌شود و در سمت درست، هم‌تراز با آیتم والد قرار می‌گیرد.

## ۵. فایل‌های تغییر‌یافته

- `includes/class-hsw-header-base.php` — `depth` از ۲ به ۰
- `assets/css/hsw-header.css` + `.min.css` — فلای‌اوت سطح سوم، فلش جهت‌دار، هایلایت والد
- `hamishop-elementor-widgets.php` (نسخه) · `readme.txt` · `CHANGELOG.md`

## ۶. نکته برای منوهای خیلی عمیق

سطح چهارم و بیشتر هم رندر می‌شود (همان قاعدهٔ فلای‌اوت). اگر منویی داشتید که در موبایل از عرض صفحه بیرون زد، بگویید تا برای سطح ۴+ قاعدهٔ «برگشت به سمت مخالف» اضافه شود.
