# یادداشت‌های انتشار نگارش 1.11.244 (Release Notes v1.11.244)

> **موضوع:** ویجت تازهٔ «هدر GC» — همان طراحی نوار شناور با نشان مدار و پنل‌های کشویی، این بار به‌صورت یک ویجت بومی المنتور با کنترل‌های واقعی.

## ۱. از کجا آمد

فایل صادرشده از المنتور چهار ویجت HTML و یک اسکریپت پل ۳۰ کیلوبایتی بود: استایل‌ها در یک ویجت HTML، مارک‌آپ در ویجت دوم، منوی موبایل در سوم، و یک «پل» که مقادیر ویجت‌های کنترلی پنهان را با `MutationObserver` روی DOM اصلی کپی می‌کرد. زیبا بود، ولی هر تغییر کوچک یعنی ویرایش CSS داخل یک بلوک متنی.

این نسخه همان طراحی را به یک ویجت معمولی HamiShop منتقل می‌کند:

- نوار شناور با گوشهٔ گرد که با اسکرول به نوار تمام‌عرض مات می‌چسبد؛
- نشان برند به‌صورت «G» کشیده‌شده با خط مدار که هنگام ورود صفحه خودش را می‌کشد؛
- خط گرادیانتی زیر منو که با اشاره‌گر حرکت می‌کند و به صفحهٔ جاری برمی‌گردد؛
- پنل‌های کشویی که ردیف‌هایشان یکی‌یکی وارد می‌شوند.

## ۲. چه چیزی قابل ویرایش است

| بخش | کنترل |
|---|---|
| نشان | **لوگوی سایت (خودکار)** / مدار GC / آیکون مجموعه / بدون نشان |
| برند | نام فارسی، نام لاتین، لینک، اندازهٔ نشان |
| منو | پنج ردیف پیش‌فرض (عنوان + لینک + انتخاب پنل) |
| پنل‌ها | شش جایگاه؛ هر ردیف: آیکون، عنوان، توضیح، لینک |
| پایین پنل | ردیف نوع «لینک پایین پنل» به‌صورت لینک تأکیدشده |
| دکمه‌ها | سبد (با نشانگر تعداد)، حساب کاربری، منوی موبایل |
| رفتار | چسبان / پنهان با اسکرول پایین / درون جریان + آستانهٔ چسبیدن |
| رنگ | نُه کنترل رنگ، همه خالی‌به‌پیش‌فرض تا پالت حاکم بماند |

پنل‌ها با «جایگاه» آدرس می‌دهند، نه با شمارهٔ ردیف: ردیف منو «پنل ۲» را انتخاب می‌کند و ردیف‌های پنل هم «پنل ۲» را. بنابراین جابه‌جا کردن ردیف‌ها هیچ اتصالی را نمی‌شکند.

## ۲ب. رفتار با اسکرول — سه حالت، یک کنترل

سه حالت با هم جمع نمی‌شوند، پس یک `SELECT` دارند نه دو سوئیچ:

| حالت | رفتار |
|---|---|
| **چسبان** (پیش‌فرض) | نوار همیشه دیده می‌شود؛ با اسکرول به نوار تمام‌عرض مات تبدیل می‌شود |
| **پنهان با اسکرول پایین** | نوار با رفتن به پایین کنار می‌رود و با کوچک‌ترین اسکرول به بالا فوراً برمی‌گردد |
| **درون جریان** | نوار در جریان صفحه می‌ماند، برای وقتی خودِ سکشن المنتور چسبان است |

اندازه‌گیری روی مرورگر واقعی (۱۲۸۰px):

```
حالت autohide
  بالای صفحه (y=0)      → hidden=false   top=0
  اسکرول به y=500        → hidden=true    top=-92
  اسکرول به y=480        → hidden=false   top=0     ← با ۲۰px بالا آمدن

حالت dock
  اسکرول به y=400        → docked=true    bg top=0  bg width=1280
```

دو نکته که عمدی است:

- **پنل باز = نوار می‌ماند.** تا وقتی یک پنل کشویی یا کشوی موبایل باز است، اسکرول پایین نوار را پنهان نمی‌کند (`hidden=false` در تست، با `panelOpen=true`).
- **فوکوس کیبورد نوار را برمی‌گرداند.** هر `focusin` داخل نوار `is-hidden` را برمی‌دارد، تا کاربر با Tab داخل نوارِ نامرئی نیفتد.

> یک تلهٔ واقعی: انیمیشن ورود `hsw-gc-in` با `fill-mode: both` اجرا می‌شد. `both` آخرین کی‌فریم (`transform: none`) را برای همیشه نگه می‌دارد و انیمیشن از declaration معمولی قوی‌تر است — یعنی `transform` حالت پنهان هیچ اثری نمی‌داشت. به `backwards` تغییر کرد؛ آخرین کی‌فریم همان حالت عادی است، پس پرشی دیده نمی‌شود.

## ۲ج. لوگو، خودکار

`mark_style` پیش‌فرض `logo` است و زنجیرهٔ خواندن این است:

```
تصویر انتخاب‌شده روی همین ویجت
  → custom_logo قالب (سفارشی‌سازی ← هویت سایت ← لوگو)
    → آپشن site_logo (قالب‌های بلاکی)
      → نشان مدار GC (اگر سایت هیچ لوگویی ندارد)
```

تصویر با اندازهٔ `array(320,320)` درخواست می‌شود، نه `full`: لوگوی ۲۰۰۰ پیکسلی نباید داخل جعبهٔ ۳۸ پیکسلی دانلود شود. تست: فایل ۱۰۰۰px → کاندید `430x430` انتخاب شد، جعبه ۳۸×۳۸.

اگر لوگو SVG باشد و وردپرس نتواند نسخهٔ اندازه‌دار بسازد، به URL خام برمی‌گردد تا نشان حذف نشود.

**در پنل چه می‌بینی:** زیر همان کنترل، یک نوار وضعیت نشان می‌دهد کدام تصویر انتخاب شده — بندانگشتی + عنوان فایل — یا اگر سایت لوگو ندارد، صریح می‌گوید «این سایت لوگویی ندارد» و مسیر تنظیمش را می‌نویسد. این نوار فقط در ویرایشگر ساخته می‌شود؛ رندر فرانت‌اند هیچ هزینه‌ای بابتش نمی‌دهد.

> علامت «G» مدار، لوگوی خود گیلاکلیک است و به‌عنوان یک **گزینه** در کنترل «نشان برند» می‌ماند؛ پیش‌فرض نیست. روی هر سایتی که نصب شود، لوگوی همان سایت می‌آید.

## ۳. قرارداد رنگ — با اندازه‌گیری تأیید شد

ترتیب مستند پروژه: کنترل ویجت > پالت > پیش‌فرض.

```
بدون پالت        →  trace = rgb(25,197,139)   CTA = rgb(6,39,31)
پالت بنفش        →  trace = پالت              CTA = پالت
کنترل دستی آبی   →  trace = کنترل             CTA = کنترل
```

هیچ کنترل رنگی `default` ندارد؛ دلیلش همان است که در ۱.۱۱.۲۲۱ نوشته شد — المنتور مقدار پیش‌فرض را در CSS صفحه چاپ می‌کند و پالت دیگر نمی‌رسد.

علت: `.hsw-gc a { color: inherit }` specificity (0,1,1) دارد و از `.hsw-gc__drawer-btn--dark` (0,1,0) قوی‌تر بود. همهٔ قواعدی که رنگ یک `<a>` را تعیین می‌کنند حالا پیشوند `.hsw-gc` دارند → (0,2,0).

## ۵. سه باگ دیگر که هنگام بررسی پیدا شد

### الف) ویجت GC در پنل المنتور نبود

`register_widgets()` دو فهرست دارد: یکی فایل‌ها را `require` می‌کند، دیگری نام کلاس‌ها را ثبت می‌کند — و هر نامی که در فهرست دوم نباشد با یک `continue` بی‌صدا رد می‌شود. فایل اضافه شده بود، کلاس نه. نتیجه: ویجت بارگذاری می‌شد، ثبت نمی‌شد، و **هیچ خطایی هم نمی‌داد**.

بررسی جدید در `ci-checks.php` (چک بیست‌وسوم) هر کلاس ویجت را با همان فهرست تطبیق می‌دهد.

### ب) `HSW_Widget_Blog_Page::is_demo()`

همان پیامی که در پیشخوان دیدی. متد از زمان افزودن جعبهٔ توضیحات صدا زده می‌شد، ولی فقط روی پایه‌های archive/cart/product تعریف شده بود، نه روی `HSW_Blog_Base`. هر رندر ویجت صفحهٔ مجله استثنا می‌داد، `hsw_report_fatal()` آن را به یک نوار زرد تبدیل می‌کرد، و هر چیزی بعد از آن خط — یعنی کل جعبهٔ توضیحات — رندر نمی‌شد.

### ج) `HSW_Composite::is_active()`

همان خانواده، شکل دیگر: یک فراخوانی **استاتیک** به متدی که هرگز نوشته نشده بود (`widgets/class-hsw-widget-blog-grid.php:238`). حالا از هلپر موجود `is_composite_part()` استفاده می‌کند، دقیقاً مثل `class-hsw-widget-archive-header.php`.

### گارد جدید

`tests/harness.php` حالا هر `$this->name(` و هر `HSW_*::name(` را در فایلِ خودِ کلاس با `method_exists` تطبیق می‌دهد. هر سه باگ بالا را پیدا می‌کند و با حذف هر رفع، هارنس قرمز می‌شود (منفی‌آزمایی انجام شد).

```
php tests/harness.php
  UNDEFINED METHOD: HSW_Blog_Base::is_demo() — class-hsw-blog-base.php
  HARNESS RESULT: 1 FAILURE(S)
```

رندر همهٔ ۶۳ ویجت با تنظیمات پیش‌فرض در وردپرس واقعی: **۶۳ سالم، ۰ استثنا** (۲۰ مورد خروجی خالی دارند چون به زمینهٔ محصول/سبد نیاز دارند).

## ۶. بررسی‌های دیگر

- پنل‌ها در ۱۱۰۰ / ۱۱۵۰ / ۱۲۸۰px هیچ‌جا از لبهٔ دید خارج نمی‌شوند (چپ/راست هر شش پنل اندازه‌گیری شد).
- `php tools/ci-checks.php` → ۲۲ بررسی، همه پاس.
- `php tests/harness.php` → ۱۲۲ فایل، ۱۱۴ کلاس، ALL CLEAN.
- سبک‌سازی: CSS از ۲۷٫۸KB به ۱۹٫۲KB، JS از ۱۳٫۶KB به ۹٫۲KB.

## ۷. کارهایی که انجام نشد (عمدی)

- **منوی وردپرس به‌عنوان منبع:** پنل‌های این طراحی آیکون و توضیح جدا برای هر ردیف می‌خواهند و منوی وردپرس این‌ها را ندارد. منبع، ردیف‌های خود ویجت است. اگر بعداً منوی وردپرس لازم شد، افزودنی است.
- **آیکون‌های خطی اصلی:** پنل‌ها از مجموعهٔ مشترک Material استفاده می‌کنند، نه آیکون‌های خطی طرح اصلی. دلیل: یک فهرست آیکون مشترک برای همهٔ ویجت‌ها (قاعدهٔ موجود پروژه).
