# یادداشت‌های انتشار نگارش 1.11.232 (Release Notes v1.11.232)

> **موضوع:** کار پس‌زمینهٔ آپدیت دیگر روی کران فرانت اجرا نمی‌شود — علت ۵۰۳ متناوب gilaclick.ir.

## ۱. لاگ چه گفت و چه نگفت

لاگی که فرستادی، از ۰۷:۱۳ تا ۰۷:۱۷، **فقط** `PHP Notice` بود — همان پیام `wp_add_privacy_policy_content` که از افزونهٔ دیگری می‌آید و بی‌ضرر است. با ۱.۱۱.۲۳۱ نصب‌شده، اگر خطای PHP رخ می‌داد باید یک خط `[HSW/fatal]` هم می‌دیدی. **نبود.**

پس نتیجه: **درخواست‌ها با خطای PHP نمی‌میرند.** پروسه از بیرون کشته می‌شود.

و یک چیز دیگر: آن Noticeها هر ۱-۲ ثانیه تکرار می‌شوند — یعنی درخواست‌ها پشت سر هم می‌آیند و هر کدام `init` وردپرس را کامل اجرا می‌کنند.

## ۲. چه چیزی این الگو را می‌سازد

بعد از هر آپدیت، `HSW_Upgrader` یک کار پس‌زمینه شروع می‌کند که CSS المنتور صفحه‌های دارای ویجت HamiShop را بازنویسی می‌کند.

تا ۱.۱۱.۲۳۱ این کار با **کران** جلو می‌رفت. و کرانِ وردپرس با **بازدید فرانت** اجرا می‌شود (`wp-cron.php`). یعنی:

```
بازدیدکننده وارد می‌شود
  → وردپرس یک درخواست wp-cron.php هم می‌فرستد
    → آن درخواست یک صفحهٔ سنگین المنتور را پارس می‌کند و CSS می‌نویسد
      → یک worker PHP برای چند ثانیه اشغال می‌شود
        → بازدیدکنندهٔ بعدی 503 می‌گیرد
```

روی هاست اشتراکی با تعداد کم worker، همین کافی است که سایت «گاهی همه‌جا، گاهی بعضی صفحه‌ها» ۵۰۳ بدهد — و دقیقاً بعد از فعال‌کردن افزونه شروع شود، چون job تازه شروع شده.

## ۳. تغییر

`maybe_start()` دیگر هیچ رویداد کرانی زمان‌بندی نمی‌کند:

```diff
- self::schedule();
```

کار فقط با **بازکردن یک صفحهٔ پیشخوان** جلو می‌رود، با محدودیت یک تیک هر ۳۰ ثانیه. یعنی هیچ‌وقت روی فرانت اجرا نمی‌شود و هیچ بازدیدکننده‌ای برایش صبر نمی‌کند.

اگر می‌خواهی سریع‌تر تمام شود: چند بار پیشخوان را رفرش کن. اگر می‌خواهی هیچ‌وقت اجرا نشود: `define( 'HSW_UPGRADER_OFF', true );`

## ۴. آزمون ۱ دقیقه‌ای که حرف آخر را می‌زند

قبل از نصب ۱.۱۱.۲۳۲، همین حالا می‌توانی مطمئن شوی که مقصر همین job است:

1. در `wp-config.php` این خط را اضافه کن:
   ```php
   define( 'HSW_UPGRADER_OFF', true );
   ```
2. ۱۰ دقیقه سایت را زیر همان ترافیک بگذار.

| نتیجه | معنی |
|---|---|
| ۵۰۳ قطع شد | مقصر همین job بود → ۱.۱۱.۲۳۲ را نصب کن (بدون این خط هم درست می‌شود) |
| ۵۰۳ ادامه داشت | مقصر جای دیگری است و باید بگردیم |

## ۵. چیزهایی که این نسخه نیست

- باگ در سبد خرید نیست. سبد خرید از بیرون ۲۰۰ می‌دهد و ۱.۶ ثانیه طول می‌کشد — همان قدر که بقیهٔ صفحات.
- با آن Notice کاری ندارد؛ آن از افزونهٔ دیگری است و فقط چون `WP_DEBUG_LOG` روشن است دیده می‌شود.
