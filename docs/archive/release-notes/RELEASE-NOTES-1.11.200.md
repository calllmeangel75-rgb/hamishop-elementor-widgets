# HamiShop 1.11.200 — «۹۲٪ تخفیف» روی محصولی که هیچ تخفیفی نداشت

## ۱) علت: بیشترین قیمت اصلی ÷ کمترین قیمت فروش

`HSW_Helpers::discount_percent()` برای محصول متغیر این‌طور حساب می‌کرد:

```php
$regular = $product->get_variation_regular_price( 'max' );  // 798,600
$sale    = $product->get_variation_price( 'min' );          //  66,550
// → ۹۲٪ تخفیف
```

این دو عدد **مال دو variation مختلف** بودند. محصول «محصول متغیر تست» دو variation
دارد — ۷۹۸٬۶۰۰ و ۶۶٬۵۵۰ — و **هیچ‌کدام قیمت تخفیف ندارند**. ولی آرشیو
«۹۲٪ تخفیف» می‌زد.

صفحهٔ خود محصول اما درست بود، چون از مسیر دیگری می‌خواند
(`HSW_Product_Base::display_prices()` که min را با min مقایسه می‌کند) و همان
۰٪ را می‌گرفت. یعنی **آرشیو دروغ می‌گفت، صفحهٔ محصول راست**.

حالا هر دو یک variation را می‌خوانند — ارزان‌ترین، همان که روی کارت چاپ می‌شود —
و اگر محصول اصلاً `is_on_sale()` نباشد، صفر برمی‌گردد.

| محصول | قبل | بعد |
|---|---|---|
| محصول متغیر تست (بدون تخفیف) | **۹۲٪** | ۰ |
| خرید ژل شستشوکننده (۲٬۴۳۶٬۲۶۲ → ۱٬۹۰۳٬۳۳۰) | ۲۲٪ | ۲۲٪ |
| روغن اصل Syrup | ۲۹٪ | ۲۹٪ |
| چهارفصل (۹٬۸۹۹٬۰۰۰ → ۹٬۸۹۰٬۰۰۰) | ۰٪ | ۰٪ |

## ۲) همان ایراد در کارت‌های لوپ و قیمت خط‌خورده

`HSW_Widget_Base::price_html()` هم قیمت اصلی را از `max` و قیمت فروش را از
`min` می‌گرفت، پس روی کارت «محصول متغیر تست» این را می‌کشید:

```
۷۹۸,۶۰۰ (خط‌خورده)
۶۶,۵۵۰ تومان
```

یعنی یک تخفیف ۹۲ درصدی که وجود نداشت. حالا هر دو از min می‌آیند و کارت فقط
«۶۶,۵۵۰ تومان» نشان می‌دهد.

همین اتلاف در دو جای دیگر هم بود و یک‌سان شد:

- `widgets/class-hsw-widget-archive-grid.php` — قیمت خط‌خوردهٔ کارت آرشیو برای
  محصول متغیر اصلاً چاپ نمی‌شد (چون `get_regular_price()` والد خالی است).
- `includes/class-hsw-rest.php` — درصد تخفیف payload جستجو/ویجت‌ها.

## ۳) «٪۲۲» به‌جای «۲۲٪»

سه جا علامت درصد را **قبل** از عدد می‌گذاشتند (`'٪' . $num`) و بقیه بعد از عدد.
در فارسی «۲۲٪» درست است:

- `widgets/class-hsw-widget-product-gallery.php` — نشان روی گالری محصول
- `widgets/class-hsw-widget-product-sticky.php` — نوار چسبان محصول
- `assets/js/hsw-product.js` — همان نوار وقتی variation عوض می‌شود

## دربارهٔ «سود شما از خرید ۴,۹۵۴,۰۰۰ تومان»

این عدد **درست است** و ایراد نبود. جمع دو چیز است:

| جزء | مبلغ |
|---|---|
| تخفیف خود محصول (۹٬۸۹۹٬۰۰۰ → ۹٬۸۹۰٬۰۰۰) | ۹٬۰۰۰ |
| کوپن `offer` (۵۰٪ درصدی، روی کل سبد) | ۴٬۹۴۵٬۰۰۰ |
| **جمع** | **۴٬۹۵۴٬۰۰۰** |

کوپن با کد `offer` در ووکامرس ۵۰٪ درصدی تعریف شده و روی سبد فعال بود؛ ردیف
«سود شما از خرید» تخفیف محصول و کوپن را با هم نشان می‌دهد. اگر بخواهی می‌توانم
این ردیف را به دو خط بشکنم («تخفیف محصول» + «کد تخفیف») تا مشتری گیج نشود.

## آنچه تست شد

| مورد | نتیجه |
|---|---|
| `discount_percent()` روی چهار محصول | ۰ / ۲۲ / ۰ / ۲۹ — مطابق دادهٔ واقعی |
| محصول متغیر با تخفیف واقعی روی یک variation | تست شد (سپس داده به حالت قبل برگشت) |
| آرشیو `/shop/page/2/` | کارت محصول متغیر: بدون نشان، بدون قیمت خط‌خورده |
| صفحهٔ محصول ساده | «۲۲٪ تخفیف» (قبلاً «٪۲۲ تخفیف») + «۵۳۲,۹۳۲ تومان تخفیف» |
| صفحهٔ محصول متغیر | بدون نشان، ردیف تخفیف مخفی |
| کارت لوپ (`price_html`) | متغیر: فقط ۶۶,۵۵۰ · ساده: ۲,۴۳۶,۲۶۲ خط‌خورده + ۱,۹۰۳,۳۳۰ |
| سبد خرید | «سود شما» ۵۳۲,۹۳۲ و جمع ۱,۹۰۳,۳۳۰ برای یک عدد از محصول ساده |

## تست نشده (صادقانه)
- **محصول متغیری که فقط بعضی variationهایش تخفیف دارند:** نشان تخفیف فقط وقتی
  ظاهر می‌شود که ارزان‌ترین variation (همان قیمتی که کارت چاپ می‌کند) تخفیف
  داشته باشد. یعنی «تا ۲۵٪ تخفیف» نمایش داده نمی‌شود. اگر این رفتار را می‌خواهی،
  باید متن نشان به «تا N٪» تغییر کند — بگو تا اضافه کنم.
