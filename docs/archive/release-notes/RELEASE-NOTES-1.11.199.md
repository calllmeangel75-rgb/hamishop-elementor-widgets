# HamiShop 1.11.199 — ویجت‌های هدر: دو ایراد رفتاری + یک کوئری تکراری

هر دو ویجت هدر روی `http://localhost/sks/` با مرورگر واقعی (Chromium، دسکتاپ
۱۴۴۰×۹۰۰ و موبایل ۳۹۰×۸۴۴) و کلیک/هاور/کیبورد واقعی آزمایش شدند. **دو ایراد
رفتاری** و **یک اتلاف واقعی** پیدا شد.

## ۱) در حالت «با هاور»، کلیک روی دکمهٔ دسته‌بندی‌ها منو را می‌بست

وقتی نشانگر روی دکمه می‌رفت منو باز می‌شد (`mouseenter` → `setMegaOpen(true)`)،
و همان لحظه کلیک هم `toggle` می‌زد — یعنی منویی که مشتری جلوی چشمش بود بسته
می‌شد. تست: `hover → open:true`، `click → open:false`.

حالا در حالت هاور، کلیک اشاره‌گر منو را **باز نگه می‌دارد**؛ بستن با خارج‌شدن
نشانگر یا `Escape` انجام می‌شود. فعال‌سازی با کیبورد (`Enter`/`Space`) مثل قبل
toggle است، چون در آن حالت هاوری وجود ندارد.

## ۲) ردیف بازشدهٔ منوی آبشاری هرگز `is-open` نمی‌گرفت

`itemForNode()` فقط `[data-hsw-hd-mega-item]` را می‌شناخت، ولی مارک‌آپ آبشار
`<li class="hsw-hd__cascadeitem">` می‌سازد. نتیجه: کلاس `is-open` هیچ‌وقت اضافه
نمی‌شد، و CSS بر اساس همان کلاس کار می‌کند —

```css
.hsw-hd__cascadeitem.is-open > .hsw-hd__cascadenode { ... }
```

یعنی هایلایت ردیف، چرخش فلش و بستن هم‌نوع‌های باز، هر سه از کار افتاده بودند.
تست بعد از اصلاح: `openItems: 1` و `aria-expanded="true"` روی ردیف کلیک‌شده.

## ۳) دو کوئری تکراری `product_cat` در هر صفحه

سرچ‌باکس ۱۲ دستهٔ ریشه می‌خواست و مگامنو ۵ تا؛ چون `number` در خودِ کوئری بود،
هر کدام یک `JOIN` جدا روی `wp_terms`/`wp_term_taxonomy` می‌زد:

```
SELECT t.term_id FROM wp_terms ... WHERE tt.parent = '0' ORDER BY t.name ASC   (بار ۱)
SELECT t.term_id FROM wp_terms ... WHERE tt.parent = '0' ORDER BY t.name ASC   (بار ۲)
```

حالا دسته‌های ریشه یک‌بار خوانده و در PHP برش داده می‌شوند. فرزندان همان `LIMIT`
را نگه می‌دارند (یک دستهٔ عمیق می‌تواند صدها زیردسته داشته باشد).

نتیجهٔ اندازه‌گیری روی هدر: **۹ کوئری → ۸ کوئری**، رندر ۳۷ms → ۳۱–۳۷ms.
هیچ چیز دیگری تغییر نکرد: سرچ‌باکس هنوز ۱۲ گزینه دارد و مگامنو ۵ ردیف.

## ۴) `hsw-header.min.js` دوباره ساخته شد

فایل مینی‌شده با سورس هم‌زمان بود ولی با تنظیمات قدیمی ساخته شده بود؛ بازسازی
با terser: **۲۶٫۸KB → ۱۸٫۷KB** (−۳۰٪). هر دو فایل با `node --check` و تست
مرورگر تأیید شدند.

## آنچه **مشکل سایت است، نه هدر**

اندازه‌گیری کامل صفحهٔ اصلی: TTFB ۱٬۷۶۷ms، LCP ۲٬۷۷۶ms، ۵۵ درخواست،
۱٬۵۰۶KB. سهم هدر از این‌ها ناچیز است؛ گلوگاه جای دیگری است:

- **gzip روی سرور خاموش است.** `hsw-header.min.css` با ۵۴٬۸۵۷ بایت و بدون
  `Content-Encoding` می‌آید؛ با gzip همان فایل ۹KB است. کل صفحه ۱٬۵۰۶KB است که
  با gzip حدود ۴۰۰KB می‌شود.
- **۲۰ فایل JS = ۸۱۲KB** (jQuery، WooCommerce، Elementor، Swiper) — نه هدر.
- **۲۳ فایل CSS = ۴۲۷KB.**
- TTFB ۱٬۷۶۷ms با ۱۷۸ کوئری و ۱۶۰MB حافظه.
- LiteSpeed نصب و روشن است ولی روی XAMPP (Apache) کش نمی‌کند؛ روی هاست
  LiteSpeed واقعی این عددها کاملاً متفاوت می‌شوند. «Browser Cache» هم خاموش است.

## تست نشده (صادقانه)
- **ویجت هدر مینیمال** روی هیچ صفحه‌ای از این سایت استفاده نشده (همهٔ صفحات
  `hsw-hd--store` هستند)؛ فقط از نظر کد بررسی شد، نه با کلیک.
- **حالت `mega_trigger=click`** روی این سایت فعال نیست (حالت هاور فعال است)؛
  مسیر کلیک/کیبورد در همان حالت هاور تست شد.
