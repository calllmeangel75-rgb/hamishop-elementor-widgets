# انتشار ۱.۱۱.۲۴۶ — مکانیزم دوم خرید در صفحهٔ محصول

تاریخ: ۲۰۲۶-۱۱-۰۵

---

## ۱. خواسته

روی صفحهٔ محصول، علاوه بر رفتار فعلی، یک راه دیگر برای انتخاب تعداد قبل از خرید:

- استپر و دکمهٔ «خرید آنلاین» کنار هم باشند
- کاربر تعداد را انتخاب کند، بعد خرید بزند
- کلیک روی + و − **هیچ درخواستی به سرور نفرستد**

## ۲. دو حالت، نه سه

در درخواست اولیه سه نام آمده بود: «استپر — معمولی — بهینه». در پاسخ روشن شد که «معمولی» و «بهینه» یک رفتار را توصیف می‌کنند: همان چیدمان کنار هم، بدون درخواست. پس دو حالت ساخته شد:

| حالت | رفتار |
|---|---|
| **استپر** (پیش‌فرض) | استپر بعد از افزودن به سبد ظاهر می‌شود؛ هر کلیک سبد را با `hsw_set_qty` به‌روز می‌کند؛ دکمهٔ خرید وقتی محصول در سبد است ۱ عدد اضافه می‌کند |
| **کنار دکمهٔ خرید** | استپر همیشه کنار دکمه دیده می‌شود؛ کلیک‌ها فقط عدد محلی را عوض می‌کنند؛ دکمهٔ خرید همان تعداد را اضافه می‌کند |

پیش‌فرض `stepper` است، پس هیچ سایت موجودی با ارتقا چیزی را از دست نمی‌دهد.

## ۳. تفاوت‌های ریز که باید می‌دانستید

**استپر از ۱ شروع می‌شود، نه از تعداد سبد.** در حالت جدید معنی استپر «چند تا اضافه کنم» است، نه «چند تا در سبد دارم». اگر محصول ۲ عدد در سبد دارد و استپر روی ۳ است، نتیجه ۵ می‌شود.

**آیکون سبد (bin) حذف شد.** در حالت جدید چیزی برای حذف کردن نیست؛ استپر فقط اضافه می‌کند.

**در تعداد ۱، دکمهٔ منفی جای خودش می‌ماند.** در حالت قدیم منفی جای خود را به bin می‌داد. حالا منفی با `opacity: .4` و `pointer-events: none` سر جایش است تا چیدمان نپرد.

**دکمهٔ خرید پنهان نمی‌شود.** در حالت قدیم، وقتی محصول در سبد بود دکمهٔ خرید کنار می‌رفت و استپر تمام عرض را می‌گرفت. در حالت جدید هر دو در یک ردیف می‌مانند.

## ۴. اندازه‌گیری

روی وردپرس لوکال، با رندر واقعی ویجت و مرورگر واقعی:

```
دو کلیک روی +   →  input: ۱ → ۳
                    درخواست به wc-ajax: ۰

کلیک «خرید آنلاین» →  یک درخواست:
                    action=hsw_add_to_cart&product_id=13192&quantity=3
```

با محصولی که از قبل ۲ عدد در سبد است:

```
حالت استپر   : is-not-in-cart=no   qty=۲   bin=دارد
حالت کنار دکمه: buy-inline=yes     qty=۱   bin=ندارد
```

در عرض ۳۶۰ پیکسل:

```
overflow افقی        : ۰
دکمه                 : ۱۳۴×۴۸
استپر                : ۱۰۴×۴۸
ارتفاع ردیف          : ۴۸
متن دکمه             : یک خط (۱۳px)
```

## ۵. چرا CSS با سه کلاس نوشته شد

قواعد موجود حالت «در سبد» با `!important` و specificity سه‌کلاسی نوشته شده‌اند:

```css
.hsw-ppurch:not(.is-not-in-cart) .hsw-ppurch__cart { display: none !important; }
```

برای رد کردنشان، قواعد حالت جدید هم سه کلاس دارند و **بعد** از آن‌ها می‌آیند:

```css
.hsw-ppurch.hsw-ppurch--buy-inline .hsw-ppurch__cart { display: flex !important; }
```

اگر با دو کلاس نوشته می‌شد، `:not()` وزن بیشتری می‌داد و دکمه در حالت «در سبد» ناپدید می‌ماند.

## ۶. کارهایی که انجام نشد

- **نوار چسبان پایین محصول** (`hsw-product-sticky`) استپر خودش را دارد و دست‌نخورده ماند. اگر همان رفتار را آنجا هم می‌خواهید، کنترلش باید جدا اضافه شود.
- **سقف تعداد** همان ۹۹ است که موتور JS دارد؛ کنترل `qty_max` روی `data-hsw-max` چاپ می‌شود ولی JS هنوز آن را نمی‌خواند. این محدودیت از قبل بود و در این نسخه دست نخورد.
