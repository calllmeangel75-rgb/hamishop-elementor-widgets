# انتشار ۱.۱۱.۲۴۶ — مکانیزم دوم خرید در صفحهٔ محصول

تاریخ: ۲۰۲۶-۱۱-۰۵

---

## ۱. خواسته

روی صفحهٔ محصول، علاوه بر رفتار فعلی، یک راه دیگر برای انتخاب تعداد قبل از خرید:

- استپر و دکمهٔ «خرید آنلاین» کنار هم باشند
- کاربر تعداد را انتخاب کند، بعد خرید بزند
- کلیک روی + و − **هیچ درخواستی به سرور نفرستد**

## ۲. دو حالت، نه سه

در درخواست اولیه سه نام آمده بود: «استپر — معمولی — بهینه». در پاسخ روشن شد که «معمولی» و «بهینه» یک رفتار را توصیف می‌کنند: همان چیدمان کنار هم، بدون درخواست. پس دو حالت ساخته شد:

| حالت | رفتار |
|---|---|
| **استپر** (پیش‌فرض) | استپر بعد از افزودن به سبد ظاهر می‌شود؛ هر کلیک سبد را با `hsw_set_qty` به‌روز می‌کند؛ دکمهٔ خرید وقتی محصول در سبد است ۱ عدد اضافه می‌کند |
| **کنار دکمهٔ خرید** | استپر همیشه کنار دکمه دیده می‌شود؛ کلیک‌ها فقط عدد محلی را عوض می‌کنند؛ دکمهٔ خرید همان تعداد را اضافه می‌کند |

پیش‌فرض `stepper` است، پس هیچ سایت موجودی با ارتقا چیزی را از دست نمی‌دهد.

## ۳. تفاوت‌های ریز که باید می‌دانستید

**استپر از ۱ شروع می‌شود، نه از تعداد سبد.** در حالت جدید معنی استپر «چند تا اضافه کنم» است، نه «چند تا در سبد دارم». اگر محصول ۲ عدد در سبد دارد و استپر روی ۳ است، نتیجه ۵ می‌شود.

**آیکون سبد (bin) حذف شد.** در حالت جدید چیزی برای حذف کردن نیست؛ استپر فقط اضافه می‌کند.

**در تعداد ۱، دکمهٔ منفی جای خودش می‌ماند.** در حالت قدیم منفی جای خود را به bin می‌داد. حالا منفی با `opacity: .4` و `pointer-events: none` سر جایش است تا چیدمان نپرد.

**دکمهٔ خرید پنهان نمی‌شود.** در حالت قدیم، وقتی محصول در سبد بود دکمهٔ خرید کنار می‌رفت و استپر تمام عرض را می‌گرفت. در حالت جدید هر دو در یک ردیف می‌مانند.

## ۴. اندازه‌گیری

روی وردپرس لوکال، با رندر واقعی ویجت و مرورگر واقعی:

```
دو کلیک روی +   →  input: ۱ → ۳
                    درخواست به wc-ajax: ۰

کلیک «خرید آنلاین» →  یک درخواست:
                    action=hsw_add_to_cart&product_id=13192&quantity=3
```

با محصولی که از قبل ۲ عدد در سبد است:

```
حالت استپر   : is-not-in-cart=no   qty=۲   bin=دارد
حالت کنار دکمه: buy-inline=yes     qty=۱   bin=ندارد
```

در عرض ۳۶۰ پیکسل:

```
overflow افقی        : ۰
دکمه                 : ۱۳۴×۴۸
استپر                : ۱۰۴×۴۸
ارتفاع ردیف          : ۴۸
متن دکمه             : یک خط (۱۳px)
```

## ۵. چرا اول در پنل دیده نمی‌شد

ویجت «صفحه محصول» یک ویجت **جامع** است: کنترل‌های هر بخش را از ویجت فرزند قرض می‌گیرد، ولی فقط آن‌هایی که در فهرست صریح `part_section()` آمده باشند:

```php
part_section( 'ppu_', '۶. جعبه خرید', '\HSW_Widget_Product_Purchase',
    array( 'vis', 'type', 'cart_text', 'qty_max', 'assure_items' ) );
```

`buy_mode` در آن فهرست نبود، پس فقط در ویجت مستقل «جعبه خرید» دیده می‌شد، نه در صفحهٔ محصول. اضافه شد و مسیر کامل تست شد:

```
part('ppu_', ...) → ۴٬۰۱۸ بایت
hsw-ppurch--buy-inline : دارد
qty                    : ۱
```

## ۶. چرا CSS با سه کلاس نوشته شد

قواعد موجود حالت «در سبد» با `!important` و specificity سه‌کلاسی نوشته شده‌اند:

```css
.hsw-ppurch:not(.is-not-in-cart) .hsw-ppurch__cart { display: none !important; }
```

برای رد کردنشان، قواعد حالت جدید هم سه کلاس دارند و **بعد** از آن‌ها می‌آیند:

```css
.hsw-ppurch.hsw-ppurch--buy-inline .hsw-ppurch__cart { display: flex !important; }
```

اگر با دو کلاس نوشته می‌شد، `:not()` وزن بیشتری می‌داد و دکمه در حالت «در سبد» ناپدید می‌ماند.

## ۷. بازبینی دوم — پنج سناریو

هر پنج مورد روی کد **قبل از رفع** اجرا شد تا «بازتولید شد» واقعاً مشاهده شود، نه استنتاج از کد.

| # | سناریو | قبل | بعد |
|---|---|---|---|
| ۱ | پچ زندهٔ totals برای مقصد بدون نرخ | `free=true` «رایگان» | `free=false` «روش ارسال در دسترس نیست» |
| ۱ | پچ زنده برای سبد دیجیتال | `free=true` «رایگان» | `free=false` «نیازی به ارسال ندارد» |
| ۲ | سفارش دیجیتال در پرداخت مجدد | `["free",0]` | `["none",0]` |
| ۳ | دو تغییر سریع روش ارسال | UI به مقدار تأییدشده برمی‌گشت و با پاسخ اول ناهماهنگ می‌شد | UI روی مقداری می‌ماند که در حال ذخیره است |
| ۳ | کلیک «ادامه» حین درخواست | با نرخ قبلی رد می‌شد | تا پایان درخواست صبر می‌کند، بعد ادامه می‌دهد |
| ۴ | فیلتر `hsw_terms_required` بدون صفحهٔ قوانین | سرور=true، ویجت=false → سفارش غیرممکن | هر دو true |
| ۵ | صفحهٔ بیگانه در option | `unwired` و noindex روی آن صفحه (`'1'`) | `foreign`؛ صفحهٔ تازه ساخته می‌شود، صفحهٔ قبلی دست‌نخورده |
| ۵ | صفحهٔ درست با slug متفاوت | — | **بازتولید نشد**؛ با انتخاب در تنظیمات `wired` است |

### ۷.۱ منبع واحد ارسال

کلاس تازهٔ `HSW_Shipping_State` جای چهار محاسبهٔ جدا را گرفت. عمداً بی‌قید در `includes()` بارگذاری می‌شود، چون پچ REST روی درخواستی اجرا می‌شود که المنتور در آن ویجتی ثبت نمی‌کند.

```
HSW_Shipping_State::for_cart()   → REST patch + cart/checkout summaries
HSW_Shipping_State::for_order()  → pay step / retry
HSW_Shipping_State::label()      → the five labels
```

`for_order()` حالا از اقلام سفارش می‌پرسد: سفارش دیجیتال `none` است، سفارش با نرخ رایگان `free`.

### ۷.۲ مسابقهٔ روش ارسال

```
shipConfirmed   آخرین نرخی که سرور پذیرفت
shipPending     نرخی که همین حالا در حال ذخیره است
shipPromise     خود درخواست
```

تغییر دوم در حین درخواست، UI را روی `shipPending` نگه می‌دارد — نه روی مقدار تأییدشده. کلیک «ادامه» با `shipPromise` معلق می‌شود و بعد از پایان دوباره اجرا می‌شود.

> **باگ دومی که همین تست بیرون کشید:** هندلر `[data-hsw-need-address]` روی همان دکمه، یک میلی‌ثانیه بعد از پیام «در حال ذخیره…» پیام آدرس را می‌نوشت و انتظار را نامرئی می‌کرد. حالا اگر هندلر دیگری `preventDefault` زده باشد، عقب می‌کشد.

اندازه‌گیری:

```
t=4552ms  «در حال ذخیره روش ارسال…»
t=5147ms  «برای ادامه، این موارد را کامل کنید: …»   ← بعد از پایان درخواست
```

### ۷.۳ سیاست قوانین

ویجت اول از `HSW_Complete_Route::terms_required()` می‌پرسد و بعد لینک خودش را اضافه می‌کند. لینک سفارشی می‌تواند الزام اضافه کند (بی‌خطر)، ولی دیگر نمی‌تواند الزام سرور را حذف کند.

### ۷.۴ صفحهٔ نامرتبط

`resolve_page_id()` عمداً به option اعتماد می‌کند — مسیریابی باید از انتخاب مدیر پیروی کند. پس رفع در صفحهٔ راه‌اندازی است: صفحهٔ منتشرشده‌ای که مال ما نیست `foreign` است، دکمه به‌جای دست‌زدن به آن یک صفحهٔ تازه می‌سازد، و صفحهٔ قبلی محتوا و ایندکسش را نگه می‌دارد.

## ۸. کارهایی که انجام نشد

- **نوار چسبان پایین محصول** (`hsw-product-sticky`) استپر خودش را دارد و دست‌نخورده ماند. اگر همان رفتار را آنجا هم می‌خواهید، کنترلش باید جدا اضافه شود.
- **سقف تعداد** همان ۹۹ است که موتور JS دارد؛ کنترل `qty_max` روی `data-hsw-max` چاپ می‌شود ولی JS هنوز آن را نمی‌خواند. این محدودیت از قبل بود و در این نسخه دست نخورد.
