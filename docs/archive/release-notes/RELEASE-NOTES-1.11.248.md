## ۲. پنج رفعی که انجام شد

### ۲.۱ عنوان هدر حساب

`a_text()` از قبل کنترل «رنگ متن» را ثبت می‌کند (`ac_hero_title_c`)، ولی CSS مقدار را با `color:#fff !important` قفل کرده بود. حالا:

```
بدون کنترل        → #fff  (همان پیش‌فرض، بدون تغییر)
با کنترل          → قاعدهٔ المنتور (0,2,0) بر CSS (0,1,0) مقدم می‌شود
```

### ۲.۲ پس‌زمینهٔ هدر حساب

کنترل `background-color` می‌نوشت، عنصر `background: linear-gradient(...)` می‌کشد. رنگ زیر گرادیان دیده نمی‌شود. حالا شورت‌هند `background` نوشته می‌شود: رنگ انتخابی جای گرادیان را می‌گیرد، و کنترل خالی گرادیان را دست‌نخورده می‌گذارد.

### ۲.۳ فونت‌ها

```
قبل : .hsw-font-design, .hsw-font-design *:not(.hsw-ic) { ... !important }
بعد : .hsw-font-design { ... !important }          ← ریشه
      .hsw-font-design *:not(.hsw-ic) { ... }      ← فرزندان، بدون !important
```

فرزندان هنوز بر سلکتورهای عنصری قالب (`p`, `a`) غالب‌اند، ولی Typography صریح المنتور (0,2,0)+ بر آن‌ها مقدم است.

### ۲.۴ کنتراست

```
readable_on('#1d4ed8', '#0b1f3a')
  قبل → #111827   (مشکی روی سرمه‌ای، محو)
  بعد → #6183e4   (آبی روشن‌شده)

readable_on روی پس‌زمینهٔ روشن → بدون تغییر

contrast_text('#888888')
  قبل → #ffffff   (۳٫۵:۱)
  بعد → #111827   (۵٫۹:۱)

کف جدید: ۴٫۵۸:۱ (نقطهٔ تقاطع سفید/مشکی)
```

### ۲.۵ رنگ نامعتبر در پالت

```
قبل : مقدار بی‌معنی → پیش‌فرض، بی‌صدا، با پیام «ذخیره شد»
بعد : مقدار قبلی حفظ می‌شود + خطای تنظیمات با نام همان فیلدها
```

## ۳. مواردی که عمداً تغییر نکردند

**فوتر Woodmart (`hsw-archive.css:1794`).** قاعده با `!important` رنگ `#5f6368` می‌گذارد چون تم `#767676` روی سطح روشن می‌دهد: ۴٫۲۳:۱، زیر حد ۴٫۵. حذفش خوانایی را کم می‌کند. دامنه‌اش هم فقط صفحه‌های آرشیو است. اگر مدیر بخواهد، با یک فیلتر CSS قابل خنثی‌کردن است.

**رنگ‌های ثابت سبد و تسویه.** `ok` / `error` / رنگ برند درگاه‌ها نقش پالت نیستند؛ تغییرشان با پالت یعنی «موفق» و «خطا» رنگ برند بگیرند.

**hover/active دکمه‌ها.** ادعا نادرست بود: CTA محصول همین حالا `--hsw-cart-bg-hover` و `--hsw-cart-bg-active` را با `color-mix` از رنگ کنترل می‌سازد. CTA سبد و تسویه کنترل رنگ اختصاصی ندارند و از پالت پیروی می‌کنند — طراحی، نه باگ.

**بارگذاری ویجت‌ها.** ۶۳ فایل، ۱٫۳۳ مگابایت، پیش از بررسی فعال‌بودن `require_once` می‌شوند. با opcache چند میلی‌ثانیه است؛ بدون آن، پارس ۱٫۳ مگابایت در هر درخواست. چون ویجت جامع به کلاس‌های فرزند ارجاع می‌دهد، شرطی‌کردن بارگذاری بدون پروفایل واقعی ریسک دارد و انجام نشد.

**CSS پالت.** ۱٬۴۶۹ بایت درون `<style>` — ناچیز. شرطی‌کردنش به «صفحه‌ای که ویجت دارد» شکننده است (شورت‌کد، ویجت جامع، پیش‌نمایش المنتور) و سودش زیر ۱KB است.

**پیش‌نمایش زنده.** ناقص است ولی فقط نمایشی؛ اولویت پایین‌تر از بقیه.

## ۴. تست پذیرش

| سناریو | نتیجه |
|---|---|
| ویجت بدون override از پالت پیروی می‌کند | بدون تغییر ✓ |
| رنگ همان عنصر در المنتور اعمال می‌شود | عنوان هدر حساب ✓ |
| تغییر پالت، عنصر override‌دار را ثابت می‌گذارد | قاعدهٔ المنتور مقدم است ✓ |
| پاک‌کردن کنترل، عنصر را به پالت برمی‌گرداند | کنترل خالی → پیش‌فرض ✓ |
| دو ویجت مشابه روی هم اثر نگذارند | سلکتورها به `{{WRAPPER}}` محدودند ✓ |
| فوتر قالب دست‌نخورده بماند | فقط قاعدهٔ عمدی آرشیو، خارج از دامنه ✓ |

> محدودیت: تست مرورگری با کنترل واقعی المنتور در این نسخه انجام نشد؛ اندازه‌گیری‌ها از CSS، PHP و نمونه‌های تابع گرفته شده‌اند.
