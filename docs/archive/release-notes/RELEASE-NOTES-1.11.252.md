# انتشار ۱.۱۱.۲۵۲ — دو اصلاح روی ۲۵۱

## ۱. رفع پاک‌سازی کش در ۲۵۱ کار نمی‌کرد

`purge_on_style_change()` در ۲۵۱ پارامتر سوم گرفت، ولی `add_action()` با تعداد آرگومان پیش‌فرض (۱) ثبت شده بود. یعنی `$option` همیشه `''` بود و شرط `'hsw_security' === $option` هرگز برقرار نمی‌شد — همان رفتار قبلی: هر تغییر امنیتی کل کش را پاک می‌کرد.

**چرا تست ۲۵۱ این را نگرفت:** متد را مستقیم با سه آرگومان صدا زدم. باگ در سیم‌کشی بود، نه در متد.

```
update_option('hsw_security', …) با تغییر فقط block_rest_users
  قبل از این نسخه : ۱ پاک‌سازی
  بعد             : ۰
  تغییر clean_assets : ۱
```

## ۲. دو صفحهٔ تنظیمات از قلم افتاده بودند

`HSW_Security::form_action()` و `HSW_Widget_Manager::options_form_action()` هنوز فقط وجود slug را ملاک می‌گرفتند. حالا هر پنج صفحه از یک تابع استفاده می‌کنند:

```
                    slug + rewrite   slug بدون rewrite   ثابت اضطراری
account             /2226/options    admin_url           admin_url
branding            /2226/admin.php  ''                  ''
palette             /2226/admin.php  ''                  ''
security            /2226/admin.php  ''                  ''
widgets             /2226/options    admin_url           admin_url
```

## ۳. REST — ماتریس کامل با نقش‌ها

```
role        /users   /users/5074   /users/me
anonymous   404      404           404
admin       200      200           200
editor      200      403           200
author      200      403           200
customer    404      404           200
```

`/users/{id}` برای ویرایشگر و نویسنده ۴۰۳ است — این تصمیم هستهٔ وردپرس در `get_item` است، نه این گارد. مسیرهایی که رابط‌های ویرایشگر استفاده می‌کنند فهرست و `/users/me` هستند.

## ۴. برچسب XML-RPC

«فیلتر HamiShop: ورود از مسیر XML-RPC بسته است» — چون کادر فقط وضعیت فیلتر خود افزونه را نشان می‌دهد، نه نتیجهٔ نهایی بعد از افزونه‌های دیگر و گزینهٔ قدیمی `disable_xmlrpc`.

## ۵. تست‌نشده
