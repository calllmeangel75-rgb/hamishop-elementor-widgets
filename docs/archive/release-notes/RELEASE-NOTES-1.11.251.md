## ۲. آنچه تست شد

```
REST (rest_do_request با نقش واقعی)
  anonymous  /users=404  /users/5074=404  /users/me=404
  admin      /users=200  /users/5074=200  /users/me=200
  customer   /users=404  /users/5074=404  /users/me=200

تشخیص بلاک
  برگه با wp:woocommerce/product-gallery → true
  برگهٔ فقط پاراگراف                    → false

فرم تنظیمات
  slug=2226 + rewrite نصب‌شده → http://…/2226/options.php
  slug تنظیم‌شده + rewrite غایب → '' (بازگشت به admin_url)

کش
  تغییر block_rest_users → ۰ پاک‌سازی
  تغییر clean_assets     → ۱ پاک‌سازی

?author=1 (مرورگر)
  status 404 · body class error404 · بدون لینک نویسنده
```

## ۳. آنچه تست نشد

- **درگاه واقعی:** فقط بررسی شد که دامنهٔ allowlist شده «مسدود» حساب نمی‌شود؛ پرداخت آزمایشی انجام نشد.
- **آدرس سفارشی روی Nginx** یا زیرشاخه: فقط Apache محلی.
- **`font_swap`:** هزینهٔ بافر اندازه‌گیری نشد.

## ۴. تصمیم‌های آگاهانه

**تبدیل کوکی.** `logged_in` → `auth` فقط برای همان درخواست، بعد از اعتبارسنجی کوکی. طراحی در کد توضیح داده شده، ولی مرز امنیتی کوکی را جابه‌جا می‌کند؛ تغییرش نیاز به بازبینی جدا و نقشهٔ بازیابی دارد، نه پچ سریع.

**بازنویسی .htaccess.** چرخهٔ خواندن/تغییر/نوشتن با نویسنده‌های دیگر تراکنشی نیست. نسخهٔ تراکنشی (نگه‌داشتن قواعد قبلی، تأیید، بازگشت) یک تغییر طراحی است.

**تست سلامت.** هر 2xx/3xx را موفق می‌داند. سخت‌گیرکردنش وقتی loopback احراز نشود، سایت سالم را خراب اعلام می‌کند. `unknown` همچنان گزارش می‌شود.
