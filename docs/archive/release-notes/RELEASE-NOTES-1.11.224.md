# یادداشت‌های انتشار نگارش 1.11.224 (Release Notes v1.11.224)

> **موضوع:** رفع ۵۰۳ بعد از آپدیت روی سایت زنده — بازسازی CSS المنتور بدون حذف فایل.

## ۱. چه اتفاقی افتاد

بعد از آپدیت به ۱.۱۱.۲۲۳ روی `gilaclick.ir` سایت چند دقیقه با `503 Service Unavailable` بالا نیامد.

**شاهد:** فایل‌های CSS المنتور روی همان سایت مهر زمانی `04:27–04:30 UTC` دارند — دقیقاً همان بازه‌ای که سایت خطا می‌داد.

**زنجیرهٔ رویداد:**

1. job پس‌زمینهٔ آپدیت شروع شد و CSS المنتور صفحه‌هایی که ویجت HamiShop دارند را **حذف** کرد.
2. هر بازدیدکننده‌ای که به آن صفحه‌ها می‌رسید، به‌جای پاسخ آماده، باید CSS را از صفر می‌ساخت.
3. چند ده درخواست هم‌زمان وارد بازسازی شدند، workerهای PHP-FPM پر شدند و nginx برای بقیهٔ درخواست‌ها ۵۰۳ داد.
4. وقتی صف تخلیه شد و فایل‌ها ساخته شدند، سایت خودبه‌خود برگشت.

نسخهٔ ۱.۱۱.۲۲۲ این کار را از `init` بیرون آورده بود، اما «حذف و واگذاری بازسازی به بازدیدکننده» هنوز یک پنجرهٔ سرد می‌ساخت.

## ۲. راه‌حل

CSS دیگر **حذف نمی‌شود**. برای هر صفحه `Post::update()` صدا زده می‌شود: المنتور همان لحظه صفحه را پارس می‌کند و فایل CSS را بازنویسی می‌کند.

| قبل (۱.۱۱.۲۲۳) | بعد (۱.۱۱.۲۲۴) |
|---|---|
| `delete()` → فایل نیست تا اولین بازدید | `update()` → فایل همیشه هست |
| بازسازی روی درخواست بازدیدکننده | بازسازی در تیک پس‌زمینه |
| موج بازسازی هم‌زمان | یک صفحه در هر گام |

### سه تغییر کوچک ولی مهم

- **بودجهٔ زمانی هر پست، نه هر کوئری.** قبلاً یک batch چهل‌تایی می‌توانست ده ثانیه در یک درخواست طول بکشد؛ حالا بعد از هر پست بررسی می‌شود.
- **batch کوچک‌تر:** ۴۰ پست در هر کوئری (قبلاً ۱۵۰) و فاصلهٔ تیک‌ها ۴۵ ثانیه (قبلاً ۳۰).
- **پاک‌سازی کش WP Rocket** برای همان صفحه‌ای که بازسازی شد (قبلاً فقط LiteSpeed).

اگر `update()` خطا بدهد، فایل حذف می‌شود و متای `_elementor_css` پاک می‌شود تا المنتور در بازدید بعدی بسازد — یک پنجرهٔ سرد کوچک بهتر از CSS کهنهٔ همیشگی است.

## ۳. فایل‌های تغییر‌یافته

- `includes/class-hsw-upgrader.php` — `drop_post_css()` → `rebuild_post_css()`، بودجهٔ هر پست، batch و فاصلهٔ تیک
- `hamishop-elementor-widgets.php` (نسخه)
- `readme.txt` · `CHANGELOG.md`
- `docs/PERFORMANCE.md` (توضیح بازسازی درجا)

## ۴. اگر باز هم ۵۰۳ دیدید

این نسخه پنجرهٔ سرد را حذف می‌کند، اما اگر باز هم رخ داد، این‌ها را بفرستید تا ریشه پیدا شود:

1. **لاگ خطای PHP** همان بازه (`error_log` یا `wp-content/debug.log`).
2. **لاگ ۵۰۳ سرور** — معمولاً `nginx error.log` با `upstream timed out` یا `connect() failed`.
3. **`max_children` در PHP-FPM** و مقدار `pm.max_children` نسبت به RAM.
4. خروجی `wp option get hsw_upgrader_log --format=json` (اگر WP-CLI دارید).
5. خروجی `wp option get hsw_upgrader_state --format=json` — اگر هنوز پر است، job تمام نشده.

**راه قطع فوری** اگر سایت پایین آمد: پوشهٔ افزونه را از `wp-content/plugins/` موقتاً تغییر نام دهید؛ سایت بلافاصله بالا می‌آید و ویجت‌ها فقط رندر نمی‌شوند (صفحه‌ها پاک نمی‌شوند).
