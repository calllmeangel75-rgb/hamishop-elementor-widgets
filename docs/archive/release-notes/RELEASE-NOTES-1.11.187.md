# HamiShop 1.11.187 — هندسهٔ اولین ویوپورت از قبل رزرو می‌شود (CLS)

## چه تغییر کرد
یک کامیت، یک رفع کوچک و اندازه‌گیری‌شده: `HSW_Assets::print_layout_guard()`
یک `<style id="hsw-layout-guard">` حدوداً ۷۰۰ بایتی در `wp_head` (اولویت ۲) چاپ
می‌کند که **فقط هندسه** بلوک‌های اولین ویوپورت را تکرار می‌کند:

- `.hsw-hd__maininner` و `.hsw-hd__pill` (از `hsw-header.css`)
- `.hsw-cp__body` / `.hsw-cp__panels` / `.hsw-cp__col` (از `hsw-composite.css`، با همان `--hsw-cp-gap`)
- `.hsw-ag__grid` (از `hsw-archive.css`)

هیچ رنگ، فونت یا بک‌گراندی تکرار نشده؛ و مقادیر کپی‌شده با همان
fallbackهای متغیرهای خودِ سوئیت نوشته شده‌اند، پس وقتی سوئیت لود می‌شود یا
موافق است یا چون دیرتر می‌آید برنده می‌شود. `hsw_layout_guard = false` کامل
خاموشش می‌کند.

## چرا — عدد، نه حدس

با Playwright (Chrome سیستم، ناظر `layout-shift`، Slow 4G، 411×731 DPR 2.625)
روی لایو و لوکال اندازه گرفته شد:

| | لایو ۱.۱۱.۱۸۵ | لوکال قبل از گارد | لوکال بعد از گارد |
|---|---|---|---|
| شیفت سطر هدر (`.hsw-hd__maininner`) | 0.0517 | 0.0517 | **۰ (حذف شد)** |
| CLS کل | 0.5746 | 0.5969 | 0.5969 |
| FCP | 6140ms | 11164ms | 6844ms |

علت شیفت هدر: `hsw-header.min.css` روی موبایل با اتصال کند **بعد از اولین
paint** می‌رسید و سطر هدر عرضش ۳۳px → ۴۱۱px عوض می‌شد (همه‌چیز زیرش جابه‌جا
می‌شد).

روشن‌کردن CSS Combine لایت‌اسپید (با خروجی خودکار فایل‌های ما که از ۱.۱۱.۱۸۶
کار می‌کند) هم تست شد: FCP −2.7s، LCP −2.4s، درخواست CSS از ۱۴ به ۷ — و
استایل افزونه نشکست.

## باقی‌ماندهٔ شناخته‌شده (صادقانه)
رویداد بزرگ CLS (≈۰.۶۰) هنوز جایش است و علتش **وزن HTML** است، نه CSS:
صفحهٔ `/shop/` ۲۰۶KB است (اسپرایت SVG ۳۲.۵KB + ۱۲ بلوک `<style>` ۱۷KB) و
اسنپ‌شات‌ها نشان دادند ارتفاع سند تا `DOMContentLoaded` فقط یک صفحه (731px)
بوده — یعنی محتوای اصلی دیر به DOM می‌رسد. قدم بعدی: کوچک‌کردن همان HTML.
