# یادداشت‌های انتشار نگارش 1.11.237 (Release Notes v1.11.237)

> **موضوع:** دو رفع در مسیر تسویه — پیام «تحویل دیجیتال» روی سبد مختلط، و دکمه‌ای که به خود صفحه برمی‌گشت.

## ۱. پیام «تحویل دیجیتال سفارش» روی سبد فیزیکی

```php
if ( ! WC()->cart->needs_shipping() ) {
    return true;                    // ← حذف شد
}
return self::cart_items_all_digital();
```

`WC()->cart->needs_shipping()` در ووکامرس **قبل از هر فیلتری** `false` برمی‌گرداند اگر فروشگاه روش ارسال نداشته باشد (`wc_shipping_enabled()`). نتیجه: روی چنین فروشگاهی **هر سبدی** دیجیتال حساب می‌شد.

دو اثر داشت:

1. پیام «این سفارش محصول دانلودی است…» روی سبدی که محصول فیزیکی داشت.
2. فرم آدرس به «نام + موبایل» خلاصه می‌شد و بقیهٔ فیلدها حذف می‌شدند.

**رفع:** حالا فقط از روی خودِ آیتم‌ها تصمیم می‌گیرد:

```php
return self::cart_items_all_digital();
```

اگر **همهٔ** اقلام مجازی یا دانلودی باشند → دیجیتال. یک قلم فیزیکی → نه.

## ۲. دکمه‌ای که به خودِ صفحه برمی‌گشت

در ۱.۱۱.۲۳۵ گاردی گذاشتم که «به همان صفحه نرو»، ولی در **مسیر زودهنگام** اجرا نمی‌شد:

```js
if ( has && ! open ) {
    if ( hasPay ) { return; }   // ← لینک خودش را باز می‌کرد
```

یعنی وقتی مشتری آدرس ذخیره‌شده دارد و «لینک مرحله بعد» به همان صفحهٔ تسویه اشاره می‌کند، مرورگر همان صفحه را دوباره بارگذاری می‌کرد.

**رفع:**

```js
if ( hasPay && ! isCurrentPage( payUrl ) ) { return; }
event.preventDefault();
continueToPayment();
```

حالا در هر مسیری، اگر مقصد همان صفحهٔ جاری باشد، به‌جای ناوبری سفارش ثبت می‌شود.

## ۳. تست

`tests/qa/digital-checkout-sim.php` گسترش یافت:

```
[ok] mixed cart is not digital
[ok] download-only cart is digital
[ok] mixed cart with shipping disabled is still not digital   ← جدید
[ok] empty cart is not digital
[ok] no recursion
```

نسخهٔ قبلی روی همین تست **قرمز** می‌شود (`mixed cart with shipping disabled`)، یعنی تست واقعاً باگ را می‌گیرد.

در تست خود تست هم یک ضعف پیدا شد: `HSW_QA_Product` از `WC_Product` ارث نمی‌برد، پس `cart_items_all_digital()` همهٔ آیتم‌ها را رد می‌کرد و تست به دلیل اشتباه پاس می‌شد. اصلاح شد.

دکمهٔ تسویه در Chrome واقعی با دو صفحهٔ آزمایشی (فرم جستجوی هدر + فرم تسویه):

```
حالت عادی     → place_order: 1 | search: 0 | PASS
لینک به خودش  → place_order: 1 | search: 0 | PASS
```

## ۴. یادآوری: صفحهٔ پرداخت

جریان چهارمرحله‌ای (`سبد → تسویه → پرداخت → تشکر`) به دو صفحهٔ جدا نیاز دارد:

- «صفحه کامل پرداخت — حامی» (`hsw-pay-page`)
- «صفحه کامل تکمیل خرید — حامی» (`hsw-complete-page`)

و تنظیمشان در **ووکامرس → تنظیمات → تسویه حساب → «مسیر خرید (حامی)»**.

اگر تنظیم نشده باشد، دکمه سفارش را مستقیم ثبت می‌کند (رفتار درست، بدون صفحهٔ پرداخت).
