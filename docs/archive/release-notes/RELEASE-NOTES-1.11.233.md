# یادداشت‌های انتشار نگارش 1.11.233 (Release Notes v1.11.233)

> **موضوع:** دکمهٔ «ادامه و ورود به مرحله پرداخت» به خود صفحهٔ تسویه لینک می‌داد و سفارش ثبت نمی‌شد.

## ۱. جریان درست

بله، ترتیبی که گفتی درست است:

```
سبد خرید → تسویه حساب → درگاه پرداخت (یا ثبت سفارش) → برگهٔ تکمیل خرید
```

افزونه یک مرحلهٔ **اختیاری** هم دارد: «صفحهٔ پرداخت». اگر بخواهی، بین تسویه و درگاه یک صفحهٔ جدا می‌گذاری که انتخاب درگاه در آن انجام می‌شود:

```
سبد خرید → تسویه → صفحهٔ پرداخت (حامی) → درگاه → تکمیل خرید
```

## ۲. چه چیزی خراب بود

در ویجت «خلاصهٔ تسویه» دکمه این‌طور ساخته می‌شد:

```php
$cta_url = $s['next_url']['url'] ?: $this->pay_step_url();
```

و `pay_step_url()` وقتی «صفحهٔ پرداخت» تنظیم نشده باشد، به **همان صفحهٔ تسویه** برمی‌گردد:

```php
return $this->checkout_url();   // ← خودش
```

نتیجه: `href="https://…/checkout/"` روی صفحهٔ `/checkout/`. کلیک → همان صفحه دوباره بارگذاری می‌شد و **سفارش هرگز ثبت نمی‌شد**.

## ۳. رفع

دکمه حالا می‌داند صفحهٔ پرداخت وجود دارد یا نه:

```html
<a class="hsw-cksum__cta" data-hsw-pay-step="0" data-hsw-pay-url="…/checkout/">…
```

- **`data-hsw-pay-step="1"`** → مثل قبل به صفحهٔ پرداخت می‌رود.
- **`data-hsw-pay-step="0"`** → به‌جای ناوبری، دکمهٔ `#place_order` ووکامرس را می‌زند؛ یعنی همان مسیر استاندارد: ثبت سفارش → درگاه → تکمیل خرید.

این رفتار در هر دو حالت بررسی می‌شود: وقتی مشتری از قبل آدرس دارد (مسیر سریع) و وقتی باید آدرس را در فرم پر کند.

## ۴. اگر صفحهٔ پرداخت جدا می‌خواهی

دو جا می‌توانی تعیین کنی:

1. **ویجت «خلاصهٔ تسویه» → کنترل «لینک مرحله بعد»** — همان URL را بده.
2. یا **حامی‌شاپ → تنظیمات → «صفحهٔ پرداخت»** — صفحه‌ای که ویجت «صفحه کامل پرداخت — حامی» در آن است.

اگر هر دو خالی باشند، با این نسخه دکمه مستقیم سفارش را ثبت می‌کند.

> نکته: صفحه‌ای که به‌عنوان «صفحهٔ پرداخت» انتخاب می‌کنی نباید خودِ صفحهٔ سبد یا تسویه باشد؛ افزونه این دو را رد می‌کند و به fallback برمی‌گردد.
