# انتشار ۱.۱۱.۲۴۷ — بازبینی سوم

تاریخ: ۲۰۲۶-۱۱-۰۵

---

## ۱. چهار سناریو، هر چهار بازتولید شد

هر «قبل» با اجرای همان تست روی ۱.۱۱.۲۴۶ گرفته شد، نه از خواندن کد.

| # | سناریو | قبل | بعد |
|---|---|---|---|
| ۱ | «ادامه» حین ذخیرهٔ ناموفق ارسال | کلیک دوباره اجرا می‌شد و با نرخ قبلی ادامه می‌داد | روی صفحه می‌ماند، پیام خطا می‌ماند |
| ۲ | لینک سفارشی قوانین | سرور=false، ویجت=true | هر دو=false |
| ۳ | صفحهٔ بیگانه در option | `current_route()='payment'` و `noindex` از `wp_robots` | `current_route()=''` و `index:true` |
| ۴ | مارکر قدیمی بدون محتوا | `unwired` و وصل می‌شد | `missing`، وصل نمی‌شود |
| ۴ب | صفحهٔ درست با slug متفاوت | `missing` (پیدا نمی‌شد) | `unwired` (خودکار پیدا می‌شود) |

## ۲. چرا «ادامه» بعد از خطا رد می‌شد

زنجیرهٔ `shipPromise` به `.then( clear, clear )` ختم می‌شد، پس **هم در موفقیت و هم در خطا resolve می‌شد**. `.catch()` روی آن هیچ‌وقت اجرا نمی‌شد و `cta.click()` بعد از خطا هم اجرا می‌شد.

```
shipFailed = true  →  انتظار تمام می‌شود، پیام «در حال ذخیره…» جایش را
                      به متن خطا می‌دهد، و کلیک دوباره اجرا نمی‌شود
```

اندازه‌گیری در مرورگر:

```
ذخیرهٔ ناموفق : addrNote="خطا در بروزرسانی روش ارسال"
                radio=flat_rate:1 · URL بدون تغییر · بدون اجرای دوبارهٔ کلیک
ذخیرهٔ موفق   : addrNote="برای ادامه، این موارد را کامل کنید: …"   ← کلیک ادامه یافت
```

## ۳. یک سیاست برای قوانین

قبلاً `terms_required()` ویجت، لینک سفارشی را هم الزام می‌کرد؛ سرور فقط تنظیمات سایت را می‌دید. حالا:

```
terms_required()  →  HSW_Complete_Route::terms_required()   ← تنها منبع الزام
terms_shown()     →  الزام || لینک سفارشی                   ← فقط نمایش
data-hsw-terms    →  terms_required() ? 1 : 0
```

یعنی لینک سفارشی می‌تواند تیک را **نشان** دهد، ولی نمی‌تواند الزامی بسازد که سرور آن را نمی‌داند. توضیح کنترل هم همین را می‌گوید.

## ۴. صفحهٔ بیگانه و noindex پنهان

`current_route()` هر صفحه‌ای را که id آن با option یکی بود مال مسیر می‌دانست، و `robots()` روی آن `noindex` می‌گذاشت. متای یواست دست‌نخورده می‌ماند، پس در پنل سئو هیچ اثری دیده نمی‌شد.

```
قبل  : current_route()='payment'  robots={"noindex":true,"nofollow":true}  yoast=''
بعد  : current_route()=''         robots={"index":true,"follow":true}      yoast=''
```

## ۵. مارکر بدون محتوا

`page_is_ours()` یک fast path داشت که فقط مارکر را چک می‌کرد — همان باگ را دوباره می‌ساخت. حالا مارکر باید **همراه با شورت‌کد در محتوا** باشد:

```
صفحهٔ مارک‌دار با محتوای خالی → ours=false، status=missing
```

`_hsw_route_page` هم به یک ثابت مشترک تبدیل شد (`HSW_Complete_Route::META`) تا مسیریاب و صفحهٔ راه‌اندازی یک رشته را بخوانند.

## ۶. صفحهٔ درست با slug متفاوت

اگر option، slug متعارف و مارکر همه شکست بخورند، صفحهٔ راه‌اندازی یک جست‌وجوی محتوایی برای شورت‌کد انجام می‌دهد (یک-دو کوئری، فقط در پنل مدیر). صفحهٔ `[hamishop_payment]` روی `/pay-now/` حالا خودکار `unwired` می‌شود و دکمه وصلش می‌کند، نه اینکه صفحهٔ تکراری بسازد.

## ۷. کارهایی که انجام نشد

- صفحه‌ای که فقط با **المنتور** ساخته شده و شورت‌کد ندارد، هنوز با جست‌وجوی محتوایی پیدا نمی‌شود؛ باید در تنظیمات ووکامرس انتخاب شود. جست‌وجو در `_elementor_data` با `LIKE` روی همهٔ برگه‌ها سنگین است و در پنل هم قابل توجیه نیست.
