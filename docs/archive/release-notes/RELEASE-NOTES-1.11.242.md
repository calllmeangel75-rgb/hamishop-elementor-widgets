# یادداشت‌های انتشار نگارش 1.11.242 (Release Notes v1.11.242)

> **موضوع:** شش رفع در ویجت «صفحهٔ نوشته». یکی امنیتی است و با تست واقعی تأیید شد.

## ۱. نوشتهٔ پیش‌نویس و رمزدار روی صفحهٔ عمومی نمایش داده می‌شد ⚠️

`widgets/class-hsw-widget-post-page.php` — `current_post()` و `render()`

فیلد «شناسه نوشته» یک `NUMBER` آزاد است و `current_post()` فقط `post_type` را بررسی می‌کرد:

```php
$p = $id ? get_post( $id ) : null;
if ( $p && 'post' === $p->post_type ) {
    return $p;          // ← بدون بررسی وضعیت انتشار
}
```

یعنی اگر ویجت با شناسهٔ یک **پیش‌نویس** روی یک صفحهٔ عمومی تنظیم می‌شد، متنش نمایش داده می‌شد.

جدا از آن، بدنه از `$post->post_content` مستقیم به `the_content` می‌رفت، نه از `get_the_content()`. پس **فرم رمز وردپرس هیچ‌وقت جایگزین نمی‌شد** و نوشتهٔ رمزدار کامل رندر می‌شد — حتی در مسیر عادی تک‌نوشته.

**رفع:**

```php
if ( 'publish' !== $p->post_status && ! current_user_can( 'edit_post', $p->ID ) ) {
    return null;
}
```

```php
if ( post_password_required( $post ) ) {
    echo '<div class="hsw-pp hsw-pp--locked">' . get_the_password_form( $post ) . '</div>';
    return;
}
```

**اثبات — با کد قدیم و جدید، کاربر مهمان:**

```
                                     کد قدیم   کد جدید
صفحه‌ای با شناسهٔ پیش‌نویس              لو رفت     0
نوشتهٔ رمزدار                          لو رفت     0   (فرم رمز نمایش داده شد)
```

## ۲. لینک «مجله» و دسته به خود مقاله برمی‌گشت

`includes/class-hsw-blog-base.php` — `blog_base_url()` و `post_category()`

`blog_base_url()` آدرس پایه را از `$_SERVER['REQUEST_URI']` می‌ساخت. در صفحهٔ تک‌نوشته، آن مسیر **خود مقاله** است، پس «مجله»، «بازگشت به مجله»، «مشاهده همه» و لینک دسته همه به مقاله برمی‌گشتند.

**رفع:** در تک‌نوشته، پایه از `page_for_posts` گرفته می‌شود (و اگر تنظیم نشده باشد، صفحهٔ اصلی)، و لینک دسته از `get_category_link()`.

**اثبات روی لوکال، همان مقاله:**

```
کد قدیم:  مجله -> /طول-عمر-مفید-یک-کامپیوتر-جدید-چقدر-باید/   ← خود مقاله
          وبلاگ -> /طول-عمر-مفید-یک-کامپیوتر-جدید-چقدر-باید/

کد جدید:  مجله -> /
          وبلاگ -> /category/blog/                              ← آرشیو واقعی دسته
```

## ۳. خاموش‌کردن «فهرست مطالب»، فهرست سایدبار را خاموش نمی‌کرد

`render_sidebar()` فهرست را از `$content['toc']` می‌ساخت و به `show_toc` کاری نداشت. حالا همان گزینه هر دو فهرست را کنترل می‌کند.

## ۴. دکمهٔ «نظر» در نوار پایین به مقصد ناموجود می‌رفت

بخش دیدگاه‌ها فقط وقتی چاپ می‌شود که روشن باشد **و** دیدگاهی باشد/دیدگاه‌ها باز باشند. نوار پایین همیشه به `#hsw-comments` لینک می‌داد. حالا فقط وقتی لینک است که آن شناسه در صفحه وجود دارد.

## ۵. عنوان «پربازدیدترین مقالات» با داده نمی‌خواند

`popular_posts()` با `orderby => comment_count` مرتب می‌کند، یعنی تعداد **دیدگاه**، نه بازدید. عنوان به «پربحث‌ترین مقالات» تغییر کرد تا با داده یکی باشد. (مرتب‌سازی واقعی بر اساس بازدید، کوئری سنگین‌تری می‌خواهد — اگر بخواهید جداگانه انجام می‌شود.)

## ۶. قالب فرم رمز

`.hsw-pp--locked` به CSS اضافه شد تا فرم رمز وردپرس داخل همان قاب مقاله بنشیند.

## آنچه عمداً انجام نشد

| مورد | دلیل |
|---|---|
| عدد کنار دکمهٔ قلب | عدد از تعداد دیدگاه می‌آید و JS با `localStorage` یکی کم/زیاد می‌کند؛ یعنی عدد «پسند» نیست. جابه‌جا کردنش تغییر ظاهری نوار موبایل است — نیاز به تصمیم شما |
| قبلی/بعدی در حالت «شناسهٔ دستی» | `get_previous_post()` به `$post` سراسری وابسته است. این حالت برای پیش‌نمایش ادیتور است؛ رفعش نیاز به جابه‌جایی موقت گلوبال دارد که ریسکش از فایده‌اش بیشتر است |
| شناسه‌های تکراری فهرست مطالب | فقط وقتی چند ویجت نوشته در یک صفحه باشند؛ نادر |
| بردکرامب سلسله‌مراتبی (عنوان مقاله، دستهٔ والد، `aria-current`) | افزودنی است، نه رفع باگ؛ ظاهر بردکرامب عوض می‌شود |
| نوار پایین و فوتر چسبان، wrap بردکرامب، جدول عریض، نقطهٔ شکست ۱۰۲۴، فاصلهٔ پایین | همه نیاز به تست چشمی روی صفحهٔ واقعی با قالب و فوتر فعال دارند؛ بدون آن، تغییر CSS حدس است |
