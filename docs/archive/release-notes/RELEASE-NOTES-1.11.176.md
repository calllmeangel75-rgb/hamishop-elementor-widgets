# HamiShop 1.11.176 — امنیت، اتمیک‌بودن و بهینه‌سازی

این نسخه یافته‌های بازبینی مستقل امنیتی و مالی را می‌بندد و اولین بهینه‌سازی
بارگیری را اعمال می‌کند. هر اصلاح با اجرای آزمون (هارنس موازی روی دیتابیس
جدا) تأیید شده و CI روی PHP 7.4–8.3 و MySQL 8 سبز است.

## ۱) بستن باگ بحرانی «شارژ موجودی توسط مشترک»
- فیلد موجودی کیف پول در پروفایل با `edit_user` گارد می‌شد؛ هستهٔ وردپرس
  ویرایش «خودِ کاربر» را بدون هیچ دسترسی‌ای می‌پذیرد، پس هر مشترک از
  `wp-admin/profile.php` می‌توانست موجودی خودش را هر عددی بگذارد.
- حالا `manage_woocommerce` هم لازم است (هم در رندر فرم، هم در ذخیره).

## ۲) یک‌بارمصرف واقعی برای کد یکبارمصرف (OTP/2FA)
- کد ورود با دو درخواست موازی دو بار قابل قبول بود (۴ از ۴ اجرا بازتولید شد).
- claim و شمارندهٔ تلاش‌ها به جدول اتمیک `hsw_throttle` منتقل شد: از دو
  پروسهٔ موازی فقط اولی می‌برد و ۶ کد اشتباهِ همزمان دیگر از سقف
  `max_attempts` عبور نمی‌کند. همین الگو برای تأیید ورود دوعاملی هم اعمال شد.

## ۳) جلوگیری از سفارش تکراری با دابل‌کلیک
- `POST /hsw/v1/checkout/complete` حالا `create_order()` را پشت یک قفل
  یک‌بارمصرف اتمیک اجرا می‌کند؛ دابل‌کلیک دیگر دو سفارش pending نمی‌سازد.

## ۴) مقاوم‌سازی کیف پول
- `DEFAULT '0000-00-00 00:00:00'` از هر سه جدول حذف شد (سرورهای
  `NO_ZERO_DATE` نصب را با خطا رد می‌کردند) و نسخهٔ شِما فقط بعد از ساخت
  موفق هر سه جدول ثبت می‌شود، پس نصب شکسته دوباره تلاش می‌کند.
- `set_balance` همان سقف ۱e16 را دارد که credit/debit داشتند.
- `repair_gaps` فقط گپ مثبت را می‌بندد؛ گپ منفی (اعتباری که هرگز واریز
  نشده) فقط گزارش می‌شود تا بررسی انسانی — دیگر پنهان نمی‌شود.
- رفرنس ترمیم زمان‌دار شد تا گپ تکراریِ هم‌مقدار برای همیشه قابل ترمیم بماند.
- ریفاند وقتی سفارش `mark_paid` نشده، مستقیم از ردیف `spend:` دفتر
  مبلغ واقعاً کسرشده را می‌خواند.

## ۵) Rate limit و پراکسی‌ها
- تطبیق پراکسی مورد اعتماد حالا IPv6 را هم می‌فهمد (رنج‌های Cloudflare v6
  اضافه شد) — بازدیدکنندگان پشت یک edge IPv6 دیگر با هم یک سطل اشتراکی
  ندارند. رنج‌های سایر CDNها (مثل آروان‌کلود) با فیلتر `hsw_trusted_proxies`
  قابل افزودن است.

## ۶) بهینه‌سازی بارگیری
- هر ۹ اسکریپت فرانت با استراتژی بومی وردپرس `defer` بارگیری می‌شوند؛
  رندر اول دیگر منتظر آن‌ها نمی‌ماند و ترتیب اجرا حفظ می‌شود.
- بارگذاری دارایی‌ها از قبل شرطی بود (هر صفحه فقط دارایی ویجت‌های خودش) —
  اندازه‌گیری پایه ثبت شد: HSW در هر صفحه ۳-۵ CSS و ۱-۳ JS.

## تست‌ها
- هارنس مستقل موازی (پروسه‌های PHP همزمان روی MariaDB): claim تک‌برد،
  سقف تلاش، throttle اتمیک، XFF spoof رد شد.
- CI: lint و تست واحد روی PHP 7.4/8.2/8.3، harness، سازگاری SQL با MySQL 8
  و «generated files in sync» — همه سبز.
