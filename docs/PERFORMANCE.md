# عملکرد

این سند می‌گوید افزونه چه کاری برای سرعت انجام می‌دهد، چه چیزی اندازه‌گیری شده و چه چیزی به محیط شما بستگی دارد. اعداد اینجا **اندازه‌گیری‌شده‌اند**، نه هدف تبلیغاتی.

## چه چیزی در کنترل افزونه است

| مکانیزم | اثر |
|---|---|
| **بارگذاری شرطی** | CSS/JS هر خانواده فقط در صفحه‌ای لود می‌شود که ویجتی از آن خانواده داشته باشد. صفحه‌ای بدون ویجت HamiShop هیچ بایتی از آن نمی‌گیرد. |
| **بدون فریم‌ورک** | بدون jQuery، بدون Tailwind، بدون CDN. صفر درخواست خارجی، صفر DNS lookup سوم‌شخص. |
| **اسپرایت SVG درون‌صفحه** | فقط نمادهای همان صفحه چاپ می‌شوند؛ نه فونت آیکون، نه درخواست جدا. |
| **فونت لوکال با `font-display: optional`** | فونت از همان دامنه می‌آید و در بار اول رندر، تعویض فونت رخ نمی‌دهد (CLS صفر). |
| **کش فهرست محصول** | فهرست ID با transient + نسخهٔ کاتالوگ کش می‌شود و با `_prime_post_caches()` یک‌جا پر می‌شود؛ ویجت لوپ گرم ۲ تا ۳ کوئری می‌زند. |
| **تصاویر** | `srcset/sizes` داینامیک، `loading="lazy"`، `decoding="async"`، `fetchpriority` برای تصویر اول، `preload` یک تصویر. |
| **گارد چیدمان** | چند قاعدهٔ هندسی در `wp_head` تکرار می‌شود تا بلوک‌ها قبل از رسیدن CSS اصلی سر جایشان بنشینند (کاهش CLS). |
| **بدون نوشتن فایل در مسیرهای حساس** | فاکتور، پرداخت و ورکر تلگرام هیچ فایلی روی دیسک نمی‌نویسند. |

## اعداد اندازه‌گیری‌شده

| سنجه | مقدار | زمینه |
|---|---|---|
| CLS صفحهٔ لوپ | ۰٫۰۰۰ | بعد از `font-display: optional` (قبلاً ۰٫۱۶۷–۰٫۱۸۴) |
| CLS آرشیو موبایل | ۰٫۱۵۸۱ | از ۰٫۵۹۶۷ — با گارد چیدمان ستون سایدبار |
| CSS لوپ | ۲۱ KB → حدود ۴٫۳ KB با gzip | فقط در صفحه‌ای که ویجت لوپ دارد |
| JS لوپ | ۸٫۹ KB → حدود ۳٫۲ KB با gzip | همان |
| کوئری ویجت لوپ (کش گرم) | ۲ تا ۳ | کش فهرست ID + `_prime_post_caches` |
| صفحهٔ `/shop/` | ۱۹۷ کوئری، با و بدون ورکر تلگرام | تفاوت صفر |
| فاکتور | همیشه ۱ برگهٔ A4 | سفارش‌های ۱، ۲۲ و ۲۵ قلمی |
| ورکر تلگرام خاموش | ۱ `isset($_GET)` | بدون کوئری و بدون درخواست |

**حجم دارایی‌ها (کمینه):** ۱۹ فایل CSS ≈ ۴۸۸ KB و ۹ فایل JS ≈ ۱۷۵ KB — اما هر صفحه فقط یک یا دو خانواده از این مجموعه را می‌گیرد.

## چه چیزی به محیط شما بستگی دارد

امتیاز Lighthouse یک عدد ثابت نیست. این‌ها بیرون از کنترل افزونه‌اند:

- **قالب و صفحه‌ساز** — CSS و JS قالب معمولاً بزرگ‌ترین سهم را دارند.
- **تصاویر محصول** — اندازه و فرمت (WebP/AVIF) و ابعاد واقعی.
- **میزبانی** — TTFB، PHP worker، دیسک.
- **افزونه‌های دیگر** — هر افزونه‌ای که اسکریپت سراسری اضافه کند.
- **تنظیمات کش** — اگر کش صفحه و CSS درست تنظیم نشود، هیچ بهینه‌سازی افزونه جبرانش نمی‌کند.

## تنظیم پیشنهادی سرور

یک‌بار تنظیم می‌شود، برای همهٔ صفحات:

```nginx
# gzip
gzip on;
gzip_types text/css application/javascript image/svg+xml application/json;
gzip_min_length 1024;

# cache دارایی‌های نسخه‌دار
location ~* \.(css|js|woff2|svg)$ {
    expires 1y;
    add_header Cache-Control "public, immutable";
}
```

```apache
# .htaccess
<IfModule mod_deflate.c>
  AddOutputFilterByType DEFLATE text/css application/javascript image/svg+xml
</IfModule>
<IfModule mod_expires.c>
  ExpiresByType text/css "access plus 1 year"
  ExpiresByType application/javascript "access plus 1 year"
  ExpiresByType font/woff2 "access plus 1 year"
</IfModule>
```

نسخهٔ دارایی‌ها با `HSW_VERSION` در query string می‌آید، پس cache طولانی امن است.

## LiteSpeed

افزونه دارایی‌های خودش را با `data-no-optimize` از ادغام، حذف UCSS و defer خودکار خارج می‌کند تا چیدمان و فونت به‌هم نریزد. تنظیمات پیشنهادی:

- **CSS Excludes:** `elementor/css/post-` و `elementor/assets/css` را هم اضافه کنید؛ CSS المنتور با هر ذخیره عوض می‌شود و ادغام آن باعث تولید مداوم فایل ترکیبی می‌شود.
- **Font Display:** روی `swap` بگذارید. `optional` یا `block` باعث می‌شود فونت گاهی روی Tahoma بماند.

اعلان مربوطه در صفحهٔ HamiShop نمایش داده می‌شود و با هر نسخه یک‌بار.

## پاک‌سازی کش هنگام آپدیت

از نسخهٔ ۱.۱۱.۲۲۴، CSS المنتور **حذف نمی‌شود**: برای هر صفحهٔ دارای ویجت HamiShop، `Post::update()` صدا زده می‌شود و فایل همان لحظه بازنویسی می‌شود. این کار در **پس‌زمینه و مرحله‌ای** انجام می‌شود (کلاس `HSW_Upgrader`): یک صفحه در هر گام، بودجهٔ ۲ ثانیه در هر تیک که بعد از هر پست بررسی می‌شود، قفل، و ادامه از همان‌جا. کش هر URL جداگانه پاک می‌شود (LiteSpeed و WP Rocket) — نه کل سایت.

اگر می‌خواهید در پایان کار یک پاک‌سازی سراسری هم انجام شود:

```php
add_filter( 'hsw_upgrader_full_purge', '__return_true' );
```

## اندازه‌گیری خودتان

```bash
# Lighthouse روی صفحهٔ واقعی (موبایل، throttling پیش‌فرض)
npx lighthouse https://example.com/shop/ --preset=desktop --view

# CLS و LCP در DevTools: Performance → Experience
```

برای مقایسهٔ منصفانه، همیشه همان صفحه، همان دستگاه و همان شرایط شبکه را بگیرید.
